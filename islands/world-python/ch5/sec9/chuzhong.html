9.1 坐标系与 pos

The Coordinate System and "pos"

9.1.1 地图的坐标系（The Map's Coordinate System）

9.1.1.1 用两个数字定位地图上任意一点 Locate any point with two numbers

之前你一直用 moveXY(x, y) 移动到固定地点，但那些数字是从哪来的？本单元揭开谜底——整张地图其实是一个坐标系。地图上每一个点，都可以用一对数字 (x, y) 精确描述：x 表示水平方向（左右）的位置，y 表示垂直方向（上下）的位置。

这套坐标系有个关键规则，"十字路口"关卡说得很清楚：x 坐标越往左越小、越往右越大；y 坐标越往下越小、越往上越大。地图左下角是原点 (0, 0)，越往右上走，两个坐标值都越大。

9.1.2 pos.x 与 pos.y（Reading pos.x and pos.y）

9.1.2.1 pos 里装着当前的 x 和 y pos holds the current x and y

"强壮的沙牦牛"关卡介绍了读取位置的方法："hero.pos 属性表示英雄的当前位置。pos 对象又有两个属性：x 和 y。" 也就是说，hero.pos.x 是英雄此刻的横坐标，hero.pos.y 是纵坐标——它们是随英雄移动而实时变化的数字。

# 读取英雄当前位置的 x 和 y,存进变量
x = hero.pos.x
y = hero.pos.y
属性套属性:hero.pos.x 读起来是"英雄的 pos 的 x"——pos 是英雄的一个属性,它本身又是个对象,里面还装着 x 和 y 两个属性。这种"点号一层套一层"的写法,是访问嵌套对象数据的常见方式。

9.1.3 万物皆有 pos（Everything Has a pos）

9.1.3.1 敌人、朋友、物品都能读位置 Enemies, friends, items all have a pos

"Sarven间隙"关卡提示了一个重要事实："英雄、敌人、朋友、甚至物品，都可以访问 pos 属性。" 这意味着你不仅能知道自己在哪，还能知道敌人在哪（enemy.pos.x）、朋友在哪（friend.pos.y）、物品在哪（item.pos.x）。掌握了所有对象的坐标，你就能做出各种基于位置的智能决策。

9.2 相对移动

Relative Movement

9.2.1 加减改变坐标（Add/Subtract to Move）

9.2.1.1 在当前坐标上加减,得到目标坐标 Offset the current coordinate

这是本单元的核心思想——相对移动（Relative Movement）。以前 moveXY(30, 20) 是移动到固定的绝对位置；现在我们改为相对于当前位置移动：先读出 hero.pos.x，在它基础上加或减一个数，再 moveXY 过去。

"强壮的沙牦牛"给了最经典的例子——向右移动 10 米，就是让新的 x 等于当前 x 加 10，而 y 不变：

# 相对当前位置向右移动 10 米(y 保持不变)
hero.moveXY(hero.pos.x + 10, hero.pos.y)
为什么相对移动很重要:"绿洲"关卡点出了它的价值——"使用像这样的小范围移动技术可以让您在途中改变位置,这对于应对不断变化的威胁和新信息是非常有帮助的。" 每次只走一小步,走完再重新观察、重新决策,英雄就能灵活应对随时出现的牦牛和敌人,而不是傻乎乎地一头冲到底。

9.2.2 四个方向的口诀（Four-Direction Rules）

9.2.2.1 加右减左,加上减下 +x right, -x left, +y up, -y down

根据坐标系的规则，对 x 和 y 做加减，就对应四个基本方向。"Sarven间隙"关卡的提醒可以浓缩成一句口诀："对 y 做减法是往下走，对 x 做减法是往左走。" 反过来加法就是往上、往右。整理成表：

想去的方向怎么改坐标代码示例
向右 →x 加hero.pos.x + 10
向左 ←x 减hero.pos.x - 10
向上 ↑y 加hero.pos.y + 10
向下 ↓y 减hero.pos.y - 10

值得一提的是复合赋值运算符 += 和 -=。x += 10 是 x = x + 10 的简写，意思是"把 x 增加 10"；x -= 10 则是"把 x 减少 10"。用它们改坐标更简洁：

x = hero.pos.x
x += 10          # 等同于 x = x + 10,向右
hero.moveXY(x, y)

9.2.3 斜线移动（Diagonal Movement）

9.2.3.1 同时改 x 和 y 就走斜线 Change both x and y for a diagonal

如果只改 x 或只改 y，走的是横线或竖线；如果同时改动 x 和 y，英雄就会走斜线。"Sarven路"要求朝右上斜行——x 和 y 都增加；"干燥灌溉"要求朝左上斜行——x 减、y 加：

# 向右上斜线移动(x 加 5, y 加 5)
hero.moveXY(hero.pos.x + 5, hero.pos.y + 5)

# 向左上斜线移动(x 减 6, y 加 4)
hero.moveXY(hero.pos.x - 6, hero.pos.y + 4)

9.3 位置比较与计算

Comparing and Computing Positions

9.3.1 用 < > 判断方向（Direction via < >）

9.3.1.1 比较坐标就能知道谁在谁的哪边 Compare coordinates to find relative direction

"十字路口"关卡教了一个强大技巧：用 < 和 > 比较两个对象的坐标，就能判断出它们的相对方向。关卡原话："如果英雄的位置坐标 x 大于敌人的位置坐标 x，因为 x 坐标越往左越小，所以英雄在食人魔的右边。"

比较含义
enemy.pos.x < hero.pos.x敌人的 x 更小 → 敌人在英雄左边
enemy.pos.x > hero.pos.x敌人的 x 更大 → 敌人在英雄右边
enemy.pos.y < hero.pos.y敌人的 y 更小 → 敌人在英雄下方
enemy.pos.y > hero.pos.y敌人的 y 更大 → 敌人在英雄上方
大声读出来:"十字路口"建议——"有时大声读出来会很有用。" 把 enemy.pos.y > hero.pos.y 念成"敌人的 y 比我的 y 大,所以敌人在我上面",逻辑就清楚了。当你分不清方向时,回到"坐标大小 ↔ 上下左右"的基本规则,一读便知。

9.3.2 基于他人坐标定位（Positioning Off Others）

9.3.2.1 在敌人坐标上加减,算出建造/站位点 Offset an enemy's position to place things

既然敌人也有 pos，我们就能相对于敌人来计算一个位置。"Sarven间隙"要在敌人左侧 20 米建围栏——用敌人的 x 减 20；"雷蹄"要在牦牛下方 10 米建围栏——用牦牛的 y 减 10：

# 在敌人左侧 20 米处建围栏
x = enemy.pos.x - 20
y = enemy.pos.y
hero.buildXY("fence", x, y)

9.3.3 求中点坐标（Finding the Midpoint）

9.3.3.1 两点坐标相加除以2 Add two coordinates and divide by 2

"截断"关卡引入了一个漂亮的数学公式——求两点之间的中点。要站在塔和农民正中间保护农民，就得算出他俩连线的中点坐标。公式很简单：把两个点的 x 相加除以 2，得到中点的 x；y 同理。

📐 中点公式的由来

一维例子最直观:塔在 x=0,农民在 x=10,正中间显然是 (0 + 10) / 2 = 5。就算塔挪到 x=6,公式照样管用:(6 + 10) / 2 = 8。把这个思路分别用在 x 和 y 上,就得到了二维平面的中点。

# 求 friend 和 enemy 连线的中点
x = (friend.pos.x + enemy.pos.x) / 2
y = (friend.pos.y + enemy.pos.y) / 2
hero.moveXY(x, y)
括号不能省:一定要写成 (a + b) / 2,先加后除。如果漏掉括号写成 a + b / 2,按运算优先级会先算 b / 2 再加 a,结果就错了。这和上一单元逻辑运算里"用括号保证顺序"是同一个道理。

9.4 实战关卡精讲

Level Strategy & Analysis

这一节聚焦每一关的策略、思路与算法设计，看懂"坐标怎么加减、方向怎么判断"，你就能自己写出完整解法。

9.4.1 强壮的沙牦牛（Sand Yak Strong）

9.4.1.1 策略：牦牛靠近就 x 加 10 向右闪避 Strategy: dodge right by adding 10 to x

图2：强壮的沙牦牛——牦牛靠近10米内时,x 加10向右闪身躲避

这是相对移动的入门关。任务是躲开 4 头沙牦牛：当有牦牛靠近到 10 米以内时，向右闪 10 米避开。算法思路是主循环里先用 hero.pos.x、hero.pos.y 记下当前位置，找到最近的牦牛，if hero.distanceTo(yak) < 10 判断它是否够近；够近就把 x 加 10（x += 10），再 moveXY(x, y) 向右闪避。核心是第一次体会"读当前坐标 → 加减 → moveXY"这套相对移动的骨架。

9.4.2 绿洲（The Oasis）

9.4.2.1 策略：近牦牛就向左,否则向右奔绿洲 Strategy: left to dodge, else right to the oasis

图3：绿洲——用 if/else 双向抉择,躲牦牛向左、奔绿洲向右

这一关在"沙牦牛"基础上加了 if/else 双向抉择。目标是往右到达绿洲，但路上有牦牛。算法思路是：if enemy and hero.distanceTo(enemy) < 10——有牦牛且靠近时，x -= 10 向左躲避；else——没有威胁时，x += 10 继续向右奔向绿洲。这一关让你把"向左（减）"和"向右（加）"两个方向配合 if/else 灵活切换，边躲边进。

关键洞察:注意条件里用了 enemy and ... 的短路写法(上一单元的知识)——先确认牦牛存在,再算距离,避免没敌人时报错。相对移动 + 存在性判断 + if/else 分流三者结合,是应对动态环境的经典组合拳。

9.4.3 Sarven路 & 干燥灌溉（Diagonal Levels）

9.4.3.1 策略：无敌人就走斜线,有敌人就攻击 Strategy: move diagonally, attack if enemy appears

图4：Sarven路——同时增大 x 和 y 走右上斜线,遇敌则先攻击

这两关引入了斜线移动。"Sarven路"要朝右上前进——x、y 同时加 5；"干燥灌溉"要朝左上前进——x 减 6、y 加 4。算法思路一致：主循环里先 findNearestEnemy，if enemy 就 attack，else（没敌人）才走斜线 moveXY(pos.x±a, pos.y±b)。把"同时改动两个坐标"和"边走边战"结合起来，是这两关的训练重点。

斜线的方向:斜线方向完全由"x 加还是减、y 加还是减"这两个选择决定——右上(+x+y)、左上(-x+y)、右下(+x-y)、左下(-x-y)。想清楚要去哪个角,再决定两个坐标各自加还是减,斜线移动就不会出错。

9.4.4 Sarven间隙（Sarven Gaps）

9.4.4.1 策略：在敌人左侧建围栏,无敌人则向下移动 Strategy: build a fence left of the enemy, else move down

图5：Sarven间隙——相对敌人坐标定位,在其左侧20米建围栏拦截

这一关首次让你相对于敌人的坐标来定位。任务是一边向下移动接近绿洲，一边在食人魔左侧 20 米处建围栏挡路。算法思路是：if enemy 存在，就取 x = enemy.pos.x - 20、y = enemy.pos.y，用 buildXY("fence", x, y) 在敌人左侧建栏；else 没敌人时，用 hero.pos.y - 10 向下移动。关键突破是意识到——加减的基准不一定是自己的坐标，也可以是敌人的坐标。

9.4.5 十字路口（Crossroads）

9.4.5.1 策略：比较坐标判断来袭方向,对应建陷阱 Strategy: compare coords to find attack direction

图6：十字路口——用 < > 比较敌我坐标,判断敌人从哪个方向来,在对应X处建火焰陷阱

这一关是"位置比较"的核心演练。食人魔从上下左右四个方向进攻，你要判断每个敌人来自哪一方，在对应方向的 X 标记处建造火焰陷阱。算法思路是用 if/elif 链依次比较：enemy.pos.x < hero.pos.x（敌人在左）→ 在左侧 X 建陷阱；enemy.pos.x > hero.pos.x（在右）→ 右侧；再比 pos.y 判断上下。每种方向对应一组固定的建造坐标。核心是把"坐标大小比较"翻译成"方向判断"。

关键洞察:这一关用 if/elif/elif/elif 而不是四个独立的 if,因为敌人只可能主要来自一个方向,用 elif 链能在命中第一个匹配后就跳过其余判断,既高效又符合逻辑。判断方向的顺序(先左右后上下)可以根据关卡布局灵活安排。

9.4.6 截断（Interception）

9.4.6.1 策略：站到敌我中点,拦在农民与塔之间 Strategy: stand at the midpoint to shield

图7：截断——用中点公式算出敌人与农民连线的中点,站在中间保护农民

这一关是坐标计算的高光时刻——用中点公式动态定位。要保护农民，就得站在敌人（塔）和农民之间。算法思路是：每一轮找到 enemy 和 friend，用 x = (friend.pos.x + enemy.pos.x) / 2 和 y = (friend.pos.y + enemy.pos.y) / 2 算出他俩的中点，再 moveXY(x, y) 站过去。由于放在 while True 里，敌人一移动，中点就重新计算，英雄会持续调整站位，始终挡在中间。

动态计算的威力:这一关最精彩之处在于——中点不是固定的,而是每一帧根据敌我实时位置算出来的。这展示了坐标计算的真正价值:把数学公式放进循环,英雄就能像有智能一样,自动追踪并响应场上的变化。

9.4.7 雷蹄 & 友好的雷区（Direction-Compare Levels）

9.4.7.1 策略：比较 y 坐标决定上方还是下方行动 Strategy: compare y to act above or below

图8：雷蹄——比较牦牛与英雄的 y 坐标,在牦牛的另一侧建围栏拦截

这两关都靠比较 y 坐标来决策。"雷蹄"中牦牛随机从上方或下方出现，你要在牦牛靠英雄的那一侧建围栏拦截：if yak.pos.y > hero.pos.y（牦牛在上方）→ 在牦牛下方 10 米（yak.pos.y - 10）建栏；else（牦牛在下方）→ 在牦牛上方建栏；没牦牛就向右移动。

"友好的雷区"（概念挑战）思路类似：比较敌我 y 坐标，敌人在上就向上走 4 米、在下就向下走 4 米躲避，同时每轮固定向右走 12 米穿过雷区。这两关让你熟练运用"比较坐标 → 决定往哪个方向加减"这一完整链条。

思路辨析:"雷蹄"是"敌人在哪边,就在它另一边建栏拦住去路";"友好的雷区"是"敌人在哪边,就朝反方向躲开"。两者都基于同一个 y 坐标比较,但后续动作的方向相反——关键在于想清楚"我到底想拦截还是躲避",再决定加减的方向。

9.5 常见错误

Common Mistakes

9.5.1 新手最容易踩的坑（Pitfalls for Beginners）

9.5.1.1 坐标与方向环节的典型问题 Typical issues with coordinates and directions

图9：方向加减弄反、中点漏括号、忘更新坐标,是本单元最常见的失误
易错点清单：
  • 方向加减弄反——想向左却写成 x + 10(实际向右)，想向下却写成 y + 10(实际向上)，务必牢记"加右减左、加上减下"。
  • 改错了坐标轴——想上下移动却改了 x，想左右移动却改了 y。左右动 x、上下动 y，别搞混。
  • 中点公式漏括号——写成 a + b / 2 会先算除法，必须写 (a + b) / 2 先加后除。
  • 忘记先读取或更新坐标——用了 x 变量却没先写 x = hero.pos.x，或改了 x 却忘了 y 也要传给 moveXY。
  • 比较方向时读反坐标规则——记住 x 越大越靠右、y 越大越靠上，别把"y 大"当成"在下面"。
  • 把 pos 当数字用——pos 是对象，不能直接 hero.pos + 10，要写 hero.pos.x + 10。
  • 忘记对象可能不存在——相对敌人坐标建造前，若没先 if enemy: 确认存在，没敌人时读 enemy.pos 会报错。

1.1 字符串连接入门

Getting Started with String Concatenation

1.1.1 什么是字符串连接（What Is Concatenation）

1.1.1.1 把两段文字"粘"成一段 Gluing two pieces of text together

欢迎来到流金沙漠！本单元的主角是字符串（String）——也就是用引号括起来的文字。"友和敌"关卡开门见山地介绍："你可以使用 + 运算符连接两个字符串。这就叫做'字符串连接'。"

关卡用一个直观的例子点破了原理：如果你有两个字符串 "foo" 和 "bar"，"foo" + "bar" 的结果就是 "foobar"。 + 不过是把两段文字首尾相接、"粘"成一段更长的文字而已。这个动作的英文叫 concatenate（连接）。

1.1.2 + 号的双重身份（The Two Roles of +）

1.1.2.1 既能加数字，也能连文字 It adds numbers, and it joins text

关卡有个精妙的类比："就像两个数可以用 + 加起来一样，字符串也可以使用 + 运算符。" 同一个 + 号，遇到数字就做加法运算，遇到字符串就做连接拼合。这就是 + 的双重身份。

表达式+ 的作用结果
3 + 5数字相加8
"foo" + "bar"字符串连接"foobar"
"去战斗, " + "Sally"字符串连接"去战斗, Sally"

1.1.3 连接变量里的字符串（Concatenating Variables）

1.1.3.1 把"固定文字"接上"动态信息" Joining fixed text with dynamic info

连接的真正威力，在于把固定不变的文字和存在变量里的动态信息拼起来。"友和敌"关卡要求英雄喊出每个单位的名字命令它们行动，而每个单位的名字（id）是变化的，必须用变量获取再拼接：

friend = hero.findNearestFriend()
if friend:
    hero.say("去战斗, " + friend.id + "!")

关卡特别提醒："仅仅叫名字是不行的，你得加上(连接)一些东西让他们行动。" 也就是说，光说 friend.id 不够，要把命令词("去战斗, ")拼在前面，才能让农民真正行动起来。

1.2 多段拼接与混合

Multiple Joins & Mixing Types

1.2.1 一行连接多个字符串（Many Strings in One Line）

1.2.1.1 + 可以接龙 + can chain

"罪与罚"关卡指出："字符串连接可以在同一行中连接多个字符串。" 你可以用多个 + 把好几段文字接成一长串，像接龙一样。例如：

"Hello" + " " + "World" + "!"   # 结果："Hello World!"
空格小窍门：连接时不会自动加空格。"Hello"+"World" 会得到 "HelloWorld" 粘在一起。想要词与词之间有空格，必须自己拼一个 " "（含空格的字符串）进去。

1.2.2 字符串 + 数字（String + Number）

1.2.2.1 数字会被"拉进"文字里 Numbers join the text

"似曾相识的味道"关卡介绍了混合连接："你可以将字符串和其他字符串或数字连接起来。" 当 + 一边是字符串、另一边是数字时，数字会被当作文字拼进去。这一关用经典的"墙上的药水"歌曲来练习，把变量 potionsOnTheWall（数字）拼进歌词：

potionsOnTheWall = 10
hero.say(potionsOnTheWall + " potions of health on the wall!")
hero.say("Take " + numToTakeDown + " down, pass it around!")
算法亮点：这首歌每唱一轮，药水数量就 potionsOnTheWall -= numToTakeDown 减少一次。所以同一段拼接代码，每轮唱出的数字都不同——变量在变，拼出的歌词也跟着变。这正是"固定文字 + 动态变量"的魅力。

1.2.3 拼接坐标与位置（Joining Coordinates）

1.2.3.1 把 x、y 拼成一句报点 Turn x, y into a readable report

"罪与罚"关卡要把敌人和宝石的位置连接成容易理解的字符串，好让火炮听懂目标在哪。思路是把 pos.x 和 pos.y 两个坐标数字、再加一个空格拼成一句报点：

enemyPos = enemy.pos.x + " " + enemy.pos.y
hero.say("敌人的位置在： " + enemyPos)

1.3.2 用变量做运算（Doing Math with Variables）

1.3.2.1 变量能存任何东西 Variables can store anything

"巫师之门"关卡点明了一个重要观念："之前你学过用变量来存储敌人，其实变量可以存储任何东西！" 变量当然也能存数字，而且存了数字的变量可以像数字本身一样参与运算。这正是和巫师斗智的核心：每个魔法数字都是随机的，没法心算，必须用变量接住、再用代码计算。

las = hero.findNearestFriend().getSecret()  # 拿到巫师的秘密数字
erz = las + 7                            # 用变量做运算，结果再存进新变量
hero.say(erz)
核心思想：每一步都"接住一个数 → 算出新数 → 存进新变量 → 说出来"。用变量记录中间结果，是巫师系列关卡的通用算法骨架。只有正确记录每个数字，才能一环扣一环算到最后。

1.3.3 运算顺序与括号（Order of Operations）

1.3.3.1 乘除优先，括号最大 Multiply/divide first, parentheses win

"巫师天际层"关卡把难度推到顶点："使用括号来确保公式顺序正确！记住，乘除优先于加减。" 和数学课一样，代码也遵循运算优先级——先算乘除、后算加减；而括号能强制改变顺序，让里面的运算先做。

例如 (tam + zso) * (zso - ist)，括号保证了"两个和差先各自算好，再相乘"。如果不加括号，乘除会抢先执行，结果就全错了。

1.4.2 似曾相识的味道（A Familiar Tune）

1.4.2.1 策略：字符串 + 数字唱循环歌 Strategy: sing a counting song

图3：似曾相识的味道——把递减的数字拼进歌词,唱出"墙上的药水"

这一关练的是字符串与数字混合连接。算法思路是:在 while 循环里,每轮把当前的 potionsOnTheWall 数字拼进四句歌词唱出,然后用 -= 把数量减少,下一轮自然唱出更小的数。妙处在于同一段拼接代码,因变量递减而唱出不断变化的歌词——这就是变量驱动文本的典型应用。

1.4.3 罪与罚（Salt and Pepper）

1.4.3.1 策略：把坐标拼成火炮能懂的报点 Strategy: format coordinates for the cannons

图4：罪与罚——把敌人和宝石的 x、y 坐标拼成报点,引导火炮攻击

这一关让连接派上实际用场。算法思路是:找到敌人和宝石后,分别取出它们的 pos.x 和 pos.y,用 + " " + 把两个坐标连成"x y"格式的字符串,再拼上说明文字喊出来。火炮听到这串坐标就能锁定目标。一举两得——既报敌人位置,又报宝石位置。

思路要点:中间那个 " " 空格至关重要——它把两个数字隔开,否则 x 和 y 会粘成一个看不懂的大数字。连接时"分隔符"的设计,直接决定输出是否清晰可读。

1.4.4 空中救援行动（概念挑战 · Aerial Rescue）

1.4.4.1 策略：用前缀区分敌我 Strategy: prefix to tell friend from foe

这是概念挑战。算法思路很清晰:循环中分别找敌人和朋友,对朋友喊 "Friend " + friend.id,对敌人喊 "Enemy " + enemy.id。飞行救援队听到 "Friend" 前缀就疏散、听到 "Enemy" 前缀就消灭。这关再次强化:用一个固定前缀 + 动态 id,就能给不同对象贴上不同"标签"。

1.4.5 巫师之门（Wizard's Door）

1.4.5.1 策略：逐个巫师、链式计算魔法数字 Strategy: compute magic numbers step by step

图5：巫师之门——从第一个巫师取数,逐步加减乘除算出后续每个魔法数字

这一关切换到数学运算主题。算法骨架是一条"计算链":先到第一个巫师处 getSecret() 拿到起始数字存入变量,然后按每个巫师的指示(加 7、除以 4、乘以前一个数……)一步步用变量计算出下一个数字,走到对应巫师处说出来。因为数字随机,必须靠代码计算而非心算。

通关节奏:关卡建议一次只处理一个巫师——编辑代码、运行、拿到下一条指示,再继续写。这种"小步快跑、逐步推进"的调试节奏,是应对未知信息时的实用策略。

1.4.6 巫师出没 & 巫师天际层（Wizard Levels）

1.4.6.1 策略：从单步运算到带括号的复合运算 Strategy: from single ops to parenthesized formulas

图6：巫师天际层——用括号组合多个运算,完成复杂的魔法数字计算

这两关是"巫师之门"的进阶。"巫师出没"延续链式计算,重点练习除法及不整除的情况;"巫师天际层"则要求把多种运算组合起来,如 (esz * 3) - 2、(tam + zso) / 2 乃至 (tam + zso) * (zso - ist)。算法思路不变(取数→算→存→说),难点升级为正确使用括号控制运算顺序。

括号的价值:面对"先把两数相加,再除以 2"这类指示,必须写成 (tam + zso) / 2。若漏掉括号写成 tam + zso / 2,会变成"只把 zso 除以 2 再加 tam",结果完全不同。把口语指示翻译成带括号的公式,是这关的核心技能。

1.4.7 真炼金术（概念挑战 · True Alchemy）

1.4.7.1 策略：分步炼金,层层接力 Strategy: chain results step by step

这是概念挑战,综合运用基本运算符。任务是把金、银、铜币按四个步骤炼化:相加 → 减铜币 → 除以 3 → 乘以 2。算法思路是每一步都把上一步的结果存进新变量,并说出来:sum → sub → div → mult 层层接力。这种"用变量保存中间结果、逐步推进"的模式,正是处理多步计算的标准做法。

sum = goldCoins + silverCoins   # 步骤①
sub = sum - bronzeCoins        # 步骤②：用上一步结果
div = sub / 3                  # 步骤③：再用上一步结果
mult = div * 2                 # 步骤④：层层接力

1.5 常见错误

Common Mistakes

1.5.1 新手最容易踩的坑（Pitfalls for Beginners）

1.5.1.1 字符串与运算环节的典型问题 Typical issues with strings and math

图7：忘记空格、漏写括号、运算顺序错,是本单元最常见的失误
易错点清单：
  • 连接时忘了加空格——"Take"+num 会粘成 "Take3"，需自己拼一个 " "。
  • 字符串忘了引号——文字必须用引号括起来，否则会被当成变量名。
  • 乘法误用 x 或 ×、除法误用 ÷——代码里只认 * 和 /。
  • 该加括号却没加——把"先加后除"写成无括号形式，运算顺序就乱了。
  • 忘记用变量保存中间结果——多步计算时没存变量，下一步就无从接力。
  • 把魔法数字写死成具体数——巫师的数字是随机的，必须用 getSecret() 取并计算。

Unit 4: Function Return Values

4.1 认识返回值

Meet the Return Value

4.1.1 函数能返回一个值（Functions Can Return a Value）

4.1.1.1 函数不只做事，还能"交回结果" Functions can hand back a result

之前你写的函数都是"做一件事"——移动、攻击、说话。本单元让函数学会一项新本领：算出一个结果并交回来。"树精树林"关卡一句话点题："函数可以返回（return）一个值！"

这意味着函数不再只是"指令的打包"，它还可以像一台机器：你给它输入，它经过内部计算，吐出一个结果。这个被吐出的结果，就叫返回值（Return Value）。

4.1.2 调用等于返回值（A Call Equals Its Return）

4.1.2.1 函数调用本身"变成"那个值 The call itself becomes the value

这是理解返回值的关键。关卡解释："当一个函数被调用时，它将等于它所返回的值。" 也就是说，shouldAttack(enemy) 这个调用，整体就等于函数内部 return 出来的那个值。所以你可以把调用结果存进变量，供后面使用：

# heroShouldAttack 将被赋值为 shouldAttack() 返回的值
heroShouldAttack = shouldAttack(enemy)
if heroShouldAttack:      # 用返回值来做判断
    hero.attack(enemy)

4.1.3 你早就用过返回值（You've Used Them Already）

4.1.3.1 findNearestEnemy 就有返回值 findNearestEnemy already returns one

"盲距"关卡点破真相："其实之前你用 hero.findNearestEnemy() 的时候就见过了。" 想想看——enemy = hero.findNearestEnemy()，等号右边的调用返回了一个敌人对象，被存进了 enemy。同理 hero.distanceTo(enemy) 返回一个距离数字。本单元的新本领是：给自己写的函数也加上返回值。

4.2 return 关键字

The "return" Keyword

4.2.1 return 的语法（Syntax of return）

4.2.1.1 return 后面跟要交回的值 Put the value after return

"盲距"关卡介绍语法："要从函数返回一个值，需要使用 return 关键字。在它的后面加上要返回的值（或者变量）。" 写法很简单——return 后面跟上你想交回去的那个值或变量：

4.2.2 return 立即终止函数（return Ends the Function）

4.2.2.1 执行到 return，函数当场结束 The function stops at return

这是 return 一个极重要的特性。"树精树林"关卡警告："函数在执行 return 语句后就会立刻终止！" 一旦遇到 return，函数当场交回结果并退出，它后面的代码都不会再执行。

💡 return 像"交卷离场"

想象函数在做一份试卷。写到 return 这一行，就等于"交卷、立刻走人"。后面还没写的题目（代码）一律作废。所以 return 不仅交回答案，还终结了整个函数的运行。

4.2.3 多个 return 分支（Multiple Returns）

4.2.3.1 多个 return，只有一个会生效 Many returns, only one runs

"固定打击"关卡指出："你可以在一个函数中使用多个 return 语句，但是只有一个会被使用，因为 return 会导致函数停止执行，并且返回到函数被调用的地方。" 配合 if/else，函数可以根据不同情况走向不同的 return：

def shouldAttack(target):
    if not target:
        return False          # 分支一：没目标，交回 False 并退出
    if target.type == "burl":
        return False          # 分支二：是树精，交回 False 并退出
    return True              # 都不是，才走到这里交回 True

哪个 return 先被执行到，函数就交回哪个值并立刻结束，后面的 return 再也没机会运行。这种"层层筛查、命中即返回"的写法非常实用。

4.3 用好返回值

Making the Most of Return Values

4.3.1 返回布尔值做判断（Return a Boolean）

4.3.1.1 把"该不该"封进函数 Wrap a yes/no decision in a function

返回值最常见的用法，是返回上单元学的布尔值，把一段复杂的判断逻辑封装起来。"返回 Agrippa"关卡总结得好："通过将距离检查放入独立的函数，这段代码可以变得简洁很多。函数会返回一个布尔值，我们可以基于这个值来决定是否攻击。"

于是主循环里只需一行 if enemyInRange(enemy): 就能读懂"敌人是否在范围内"，而具体怎么算距离、怎么比较，全藏在函数里。函数返回 True/False，主代码据此分流——这是组织复杂判断的黄金模式。

4.3.2 返回数字与坐标（Return Numbers and Coordinates）

4.3.2.1 返回算好的距离或位置 Return a computed distance or position

返回值不限于布尔值。"盲距"和"金属探测器"让函数返回一个数字（到敌人/硬币的距离），"食人魔入侵者"让函数返回一个坐标（敌人的 x 位置）。函数把"算出有用信息"的活儿包办了，主代码拿到现成结果直接用：

def nearestEnemyDistance():
    enemy = hero.findNearestEnemy()
    result = 0
    if enemy:
        result = hero.distanceTo(enemy)
    return result        # 交回算好的距离

4.3.3 返回特殊"哨兵值"（Return a Sentinel）

4.3.3.1 用 0 或 -1 表示"没有" Use 0 or -1 to mean "none"

有时函数没有有效结果可返回——比如附近没有敌人。这时常约定返回一个特殊的"哨兵值"来表示"空"。"盲距""金属探测器"约定没敌人/硬币时返回 0，"食人魔入侵者"约定没敌人时返回 -1。主代码再用 if distance > 0: 之类的判断把这种"无结果"情况排除掉。

设计智慧：为什么用 0 或 -1？因为真实的距离/坐标不会是这些值，用它们当"没有"的标记不会和正常结果混淆。这种"用一个不可能出现的正常值来表示异常"的约定，是编程中常见的技巧。

Level Strategy & Analysis

4.4.1 树精树林（Sleepwalkers / Burl Boss）

4.4.1.1 策略：返回 True/False 决定是否攻击 Strategy: return a boolean to decide attacking

图2：树精树林——shouldAttack 函数返回布尔值,决定英雄是否出手

这是返回值的入门关。任务是只打有效目标、放过树精。算法思路是写 shouldAttack(target) 函数:用"层层筛查、命中即返回"的写法——没目标返回 False、是 "burl" 返回 False、其余返回 True。主循环把找到的敌人传进去,用返回的布尔值决定要不要 attack。核心在体会"调用等于返回值"——把判断结果存进变量再用。

关键洞察:注意几个 return 的顺序——先排除"不该打"的情况(没目标、是树精),都通过了才返回 True。由于 return 会立即终止函数,只要命中前面任一条件,就不会走到最后的 return True。这种"先否决、后肯定"的结构很常见。

4.4.2 盲距 & 金属探测器（Distance Levels）

4.4.2.1 策略：返回距离数字,无目标返回 0 Strategy: return a distance, or 0 if none

图3：盲距——函数返回到敌人的距离,英雄当观测手报给盲眼巫师

这两关让函数返回一个数字。"盲距"中英雄当观测手,写 nearestEnemyDistance() 返回到最近敌人的距离;"金属探测器"中英雄当炮兵测距仪,写 coinDistance() 返回到硬币的距离。算法思路一致:函数内先找目标,有就 distanceTo 算距离并返回,没有就返回 0。主循环拿到返回值,只在 > 0 时才 say 出来。

哨兵值的妙用:返回 0 表示"没有目标"是关键设计。主代码用 if distance > 0: 过滤掉"无目标"的情况,既避免了报假数据,也节省了巫师/大炮的有限能量。函数返回值 + 主代码判断,配合得天衣无缝。

4.4.3 固定打击 & 金币猎手（Range Check Levels）

4.4.3.1 策略：返回布尔判断"够近了吗" Strategy: return whether it's close enough

图4：金币猎手——isCoinClose 返回布尔值,只移向 20 米内的硬币

这两关把"距离检查"封成返回布尔值的函数。"固定打击"中英雄被困,只能等敌人进入攻击范围(≤3 米),写 inAttackRange(enemy) 返回"是否够近";"金币猎手"中身中毒,乱动会受伤,写 isCoinClose(coin) 返回"硬币是否在 20 米内"。算法思路是:函数内算距离、与阈值比较、返回 True/False;主循环据此决定攻击或移动。

为何要"够近才动":这两关都有"贸然行动会受伤"的设定,所以必须先用返回值确认"安全/有效"再行动。把"够不够近"的判断封进函数返回,让主逻辑读起来就像一句话:"如果够近,就行动",清晰又安全。

4.4.4 返回 Agrippa（Agrippa Returns）

4.4.4.1 策略：用返回值进一步重构 Strategy: refactor further with return values

图5：返回 Agrippa——把距离检查抽成返回布尔值的函数,代码更流畅

这是对此前"Agrippa 重构"的再升级。上次只是把动作抽成函数,这次更进一步——用函数计算并返回一个值。算法思路是写 enemyInRange(enemy) 返回"距离是否小于 5"的布尔值,再配合 cleaveOrAttack(enemy) 函数。主循环里 if enemyInRange(enemy): cleaveOrAttack(enemy) 读起来像自然语言。返回值让代码"胜似流水"。

两类函数:这一关同时用到两种函数——enemyInRange 是"计算并返回值"型(返回布尔),cleaveOrAttack 是"执行动作"型(不返回)。理解这两类函数的分工,是组织清晰代码的关键。

4.4.5 食人魔入侵者（概念挑战 · Ogre Intruders）

4.4.5.1 策略：返回 x 坐标,无敌人返回 -1 Strategy: return enemy x, or -1 if none

这是概念挑战。古老机器人靠英雄报出的敌人 x 坐标来打击食人魔。算法思路是完成 getEnemyX():找到敌人就 return enemy.pos.x,没有敌人就返回 -1。主循环拿到返回值,据此报点给机器人。这关再次强化"函数返回有用信息、主代码消费信息"的协作模式,并练习用 -1 作哨兵值。

def getEnemyX():
    enemy = hero.findNearestEnemy()
    if enemy:
        return enemy.pos.x   # 有敌人 → 返回它的 x 坐标
    return -1               # 没敌人 → 返回 -1 表示"无"

4.4.6 森林风暴（组合挑战 · Storm the Forest）

4.4.6.1 策略：把三重检查封进一个返回函数 Strategy: pack three checks into one function

这是组合挑战,要求融会 ==、type 属性和 return。英雄受传送风暴困扰,不能离护盾光线超过 15 米。任务是只收集 15 米内的 "coin"、只攻击 15 米内的 "munchkin"。关卡的巧思在于:收集和攻击都要检查三件事——存在、够近、类型对,逻辑高度相似。算法思路是把这三重检查封进一个返回布尔值的通用函数 isCloseType(target, type),只写一次逻辑,两处复用。

def isCloseType(target, type):
    if target:                              # ① 存在吗
        if hero.distanceTo(target) < 15:   # ② 够近吗
            if target.type == type:           # ③ 类型对吗
                return True
    return False
集大成之作:这一关把前几单元的本领全用上了——嵌套 if 检查多个条件、type == 核验身份、distanceTo 算距离、return 交回布尔值、多参数函数复用逻辑。因为对硬币是"移动"、对敌人是"攻击"(动作不同),所以动作不放进函数,而是让函数只返回判断结果,由主代码选择正确动作。这正是"返回值"相比"直接做事"更灵活之处。

4.5 常见错误

Common Mistakes

4.5.1 新手最容易踩的坑（Pitfalls for Beginners）

4.5.1.1 返回值环节的典型问题 Typical issues with return values

图6：忘写 return、漏掉无目标情况、未接住返回值,是本单元最常见的失误
易错点清单：
  • 忘记写 return——函数算了半天却没交回结果，调用处拿到的会是空值。
  • 漏掉"无目标"的返回——没敌人时没 return 0/-1，导致后续判断出错。
  • 没接住返回值——直接调用却不存进变量也不在 if 里用，结果白白丢失。
  • 误以为 return 后的代码还会运行——return 会立即终止函数，后面代码作废。
  • 把 return 写成 say——说出来不等于返回，主代码并不能"接住"说出的话。
  • 哨兵值与正常值混淆——选的"表示无"的值（如 0）若可能是正常结果，就会判断错误。

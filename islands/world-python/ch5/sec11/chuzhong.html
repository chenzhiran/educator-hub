11.1 循环控制概览

Overview of Loop Control

11.1.1 什么是循环控制（What Is Loop Control）

11.1.1.1 在循环里"改道"的两个开关 Two switches that reroute a loop

你已经熟悉了 while 循环（while loop）——它会一遍又一遍地执行循环体。但真实世界里，循环并不总是"从头到尾老老实实跑一整轮"。有时你想跳过某一轮的剩余部分，有时你想干脆彻底离开循环。这就是循环控制（Loop Control）要解决的问题。

本单元介绍两个关键的循环控制语句：continue 和 break。它们就像装在循环里的两个开关——continue 是"跳过本轮、重来下一轮"，break 是"立刻离开整个循环"。掌握了它们，你就能让循环真正听从你的指挥。

11.1.2 continue 与 break 对比（continue vs break）

11.1.2.1 一张表看清区别 The difference at a glance

这两个语句名字都短，作用却截然不同。最容易混淆的地方在于：continue 不会结束循环，break 才会。下表帮你一眼分清：

语句作用跳到哪里循环是否继续
continue跳过本轮剩余代码回到循环开头，进入下一轮继续
break终止整个循环跳到循环外，执行循环后面的代码结束
一句话记忆：continue = "这一轮我不干了，下一轮见"；break = "整个循环我都不干了，散伙"。 前者是"跳过"，后者是"退出"。

11.1.3 一轮循环的生命周期（The Life of One Iteration）

11.1.3.1 循环体里发生了什么 What happens inside the loop body

要真正理解 continue 和 break，先要看清一轮循环（英文叫 iteration，迭代）是怎么走的。一个 while True 循环，每一轮都会从循环体第一行开始，逐行往下执行，跑到最后一行后，再自动回到第一行开始下一轮。continue 和 break 就是在这个流程中"插一脚"：

可以看到：continue 把控制权抛回循环开头（虚线箭头），本轮后面的代码全部被跳过；而 break 直接冲出循环（红色出口），连"回开头"都不做了，程序继续执行循环后面的语句。

11.2 continue 跳过本轮

continue — Skip the Current Iteration

11.2.1 continue 的执行逻辑（How continue Works）

11.2.1.1 "这一轮的剩下部分，不看了" Skip the rest of this round

"炼金术传承"关卡这样介绍："使用 continue 语句停止循环的当前迭代过程，并在下一轮循环的开始处重新开始。" 换句话说，程序一旦执行到 continue，就会立即放弃本轮循环体里 continue 之后的所有代码，直接跳回循环开头，开始新的一轮。

11.2.2 continue + 条件判断（continue with if）

11.2.2.1 只在特定情况下跳过 Skip only when a condition is met

单独一个 continue 会让循环体后半部分永远执行不到，几乎没有意义。它真正的威力来自和 if 搭档。关卡明确指出："continue 可以和条件判别搭配起来，跳过部分代码。" 也就是"当满足某个条件时，才跳过本轮"。

while True:
    enemy = hero.findNearestEnemy()
    if not enemy:
        continue   # 没有敌人 → 跳过本轮，重新去找
    hero.attack(enemy)   # 只有"有敌人"时才会执行到这里

这段代码的意思是：如果没找到敌人（not enemy 为真），就 continue 跳回开头重新找；只有当敌人确实存在时，程序才会跳过那个 if，继续往下执行攻击代码。continue 就像一道"守门",不满足前提就把你请回起点。

11.2.3 用 continue 过滤对象（Filtering with continue）

11.2.3.1 遇到"不该处理"的对象就跳过 Skip objects you should not handle

continue 最实用的场景之一，是过滤掉不符合要求的对象。"炼金术传承"关卡要求避开毒药，只取水。思路是：找到物品后先检查它的 type，如果是毒药就 continue 跳过，绝不去碰它：

item = hero.findNearestItem()
if item.type is "poison":
    continue   # 是毒药 → 跳过，不去拿
# 走到这里，物品一定不是毒药，可以安全处理
过滤思维：把 continue 想象成一个"筛子"——每一轮先用 if 检查对象是否合格，不合格的直接 continue 筛掉，让后面的代码只处理"通过筛选"的对象。这是处理混杂数据时极其常见的模式。

11.3 break 跳出循环

break — Exit the Loop Entirely

11.3.1 break 的执行逻辑（How break Works）

11.3.1.1 "整个循环，到此为止" End the whole loop here

如果说 continue 是"跳过本轮",那 break 就是"彻底收工"。程序执行到 break 时，会立刻终止整个循环，不再有下一轮，控制权转交给循环后面的第一条语句。对于 while True 这种本来永不停止的死循环来说，break 是让它优雅退出的关键出口。

11.3.2 break 与终止条件（break as a Stop Condition）

11.3.2.1 用 break 给死循环装上"刹车" A brake for infinite loops

while True 会无限循环下去，如果不加控制，英雄就永远卡在里面。break 配合 if 就成了这个死循环的"刹车"——一旦达成目标或满足退出条件，就 break 出去。"逃到春天"关卡用了两处经典的 break：一处按时间退出，一处按金币数量退出。

while True:
    if hero.time > 30:
        break   # 时间超过 30 秒 → 退出这个循环
    # ... 战斗代码 ...
while True:
    # ... 捡金币代码 ...
    if hero.gold > 20:
        break   # 金币够 20 → 收工，去下一个目标
设计要点：用 break 时，一定要保证退出条件迟早会成立。上面两例中，时间会不断流逝、金币会不断增加，所以条件必然在某刻满足，循环一定能退出。如果条件永远不成立，循环就成了真正的死循环。

11.3.3 break 之后的代码（Code After break）

11.3.3.1 循环退出后，程序继续往下走 The program continues after the loop

很多初学者误以为 break 会结束整个程序——其实不然。break 只结束它所在的那一个循环，程序会接着执行循环后面的语句。这正是"逃到春天"能分成"先战斗、再捡金、最后离开"三段的原因：每段用一个 while True 加 break，break 完就自然进入下一段。

🏃 逃到春天的三段式结构
第一个 while：战斗直到时间超 30 秒 → break
↓ 循环外：hero.moveXY(46, 34) 走到草坪
第二个 while：捡金币直到金币超 20 → break
↓ 循环外：hero.moveXY(78, 34) 从右边离开
每个 break 都是一段任务的"完成信号"，交接给下一段。

11.4 实战关卡精讲

Level Strategy & Analysis

这一节聚焦每一关的策略、思路与算法设计，看懂"为什么在这里跳过、在那里退出"，你就能自己写出完整解法。

11.4.1 炼金术传承（Alchemic Power）

11.4.1.1 策略：用 continue 层层设卡，只取水 Strategy: guard clauses that skip until only water remains

图2：炼金术传承——用连续的 continue 过滤掉"没敌人""没物品""毒药"三种情况

这是 continue 的首秀。任务是不让脱水的食人矮人抢到水源。算法核心是一串"守卫式判断"（guard clauses）：在 while True 里连续放三个 if ... continue，像三道关卡逐层筛选——

第一道，若没找到敌人（not enemy）就 continue，因为没敌人就没必要行动；第二道，若地上没有物品（not item）就喊一句"给我点喝的"再 continue，等系统刷新出物品；第三道，若物品是毒药（item.type is "poison"）就 continue 跳过，绝不碰它。三关都通过后，剩下的一定是一瓶水，此时才用 moveXY 去取水并送回起点。

思路要点：守卫式 continue 的妙处在于——把"不该处理的情况"一个个提前排除，让最后的核心代码运行时，前提条件已经全部满足，逻辑异常清晰。这比层层嵌套的 if-else 更易读、更不易出错。

11.4.2 伪装大师（Master of Disguise）

11.4.2.1 策略：用 continue 实现"敌人在场就静止不动" Strategy: use continue to freeze when watched

图3：伪装大师——英雄伪装成仙人掌，卫兵在看时用 continue 保持不动

这是一个概念挑战关卡，展示了 continue 一个非常巧妙的用法："有时要用 continue 什么都不做。" 英雄伪装成仙人掌去敌营偷 7 颗宝石，但只要卫兵在看（即附近有敌人），行走的仙人掌就会露馅，所以必须原地不动。

算法思路是：在循环开头先 findNearestEnemy()，如果有敌人就立刻 continue——注意这里 continue 之后没有任何移动代码会执行，英雄自然就"定住"了。只有当没有敌人时，程序才会跳过 continue，往下执行 findNearestItem() 和 moveXY 去捡宝石。

反向思维：前一关用 continue 是为了"跳过去做别的"，这一关用 continue 却是为了"什么都不做地等待"。continue 的本质是"跳过本轮剩余的动作"——而当剩余动作正好是"移动"时，跳过它就等于"静止"。 同一个语句，用途可以完全相反。

11.4.3 逃到春天（Escape 'Em）

11.4.3.1 策略：break、continue、time、gold 四合一 Strategy: combine break, continue, time and gold

图4：逃到春天——限时战斗、精准过滤、收够金币，三段任务用 break 依次交接

这是组合挑战关卡，把本单元所有概念熔于一炉：用 break 在完成目标后离开循环，用 continue 避免攻击错误的敌人，用 gold 属性判断金币是否够了。任务分三段：30 秒内击败 7 个食人魔（忽略 "burl" 和 "sand-yak" 类型）、去草坪收集 20 金、最后从右边离开。

第一段的算法最精彩，同时用到了 break 和 continue：先判时间，if hero.time > 30: break 保证不超时；再判类型，找到敌人后如果它是 "burl" 或 "sand-yak"，就 continue 跳过（不攻击这些无关目标），否则才 attack。两个控制语句各司其职——break 管"何时结束"，continue 管"跳过谁"。

while True:
    if hero.time > 30:
        break                        # 时间到 → 退出战斗段
    enemy = hero.findNearestEnemy()
    if enemy:
        if enemy.type == "burl" or enemy.type == "sand-yak":
            continue                 # 无关目标 → 跳过，不攻击
        hero.attack(enemy)
分段思维：整关由三个独立的 while 段落串成，每段用 break 退出后，就靠一句 moveXY 走到下一段的位置。把复杂任务拆成"若干个带 break 的循环段"，是处理多阶段目标的通用架构——每一段专注一件事，做完就 break 交棒。

11.5 进阶技巧

Advanced Techniques

11.5.1 二者的配合使用（Using Both Together）

11.5.1.1 一个循环里同时放 continue 和 break continue and break in one loop

一个循环里完全可以同时出现 continue 和 break，它们互不冲突、各管一摊。常见的搭配模式是：break 负责"终点条件"（何时整体结束），continue 负责"过滤条件"（跳过哪些不处理）。执行顺序通常是先检查 break 条件，再检查 continue 条件，最后才是核心动作。

11.5.2 continue 与死循环风险（continue & Infinite Loops）

11.5.2.1 用错 continue 会让循环卡死 Misusing continue can trap the loop

continue 虽好，但用不当会引发隐蔽的问题：如果一个 continue 前面漏掉了任何"能改变状态"的代码，循环可能永远在同一个分支里空转。比如在计数循环里，如果 continue 跳过了"计数器加一"那一行，计数器就永远不变，循环条件也就永远不满足，程序卡死。

警惕：在计次循环（如 while i < 10）里使用 continue 时要格外小心——务必确保负责推进循环的那行代码（比如 i += 1）不会被 continue 跳过。否则一旦进入 continue 分支，计数器停滞，就成了永远出不来的死循环。本单元关卡多用 while True，靠 break 退出，相对不易踩这个坑，但迁移到计次循环时必须提高警惕。

11.6 常见错误

Common Mistakes

11.6.1 新手最容易踩的坑（Pitfalls for Beginners）

11.6.1.1 循环控制的典型问题 Typical issues with loop control

图5：混淆 continue 与 break、忘记退出条件、continue 前漏改状态，是本单元最常见的失误
易错点清单：
  • 把 continue 和 break 用反——想跳过一轮却写了 break，结果整个循环提前结束；想退出却写了 continue，结果循环停不下来。
  • 以为 break 会结束整个程序——其实它只结束当前所在的那一个循环，后面的代码照常执行。
  • continue 或 break 忘了配 if 条件——裸放一个 continue，会让它后面的代码永远执行不到。
  • continue 前漏掉推进状态的代码——在计次循环里，若跳过了 i += 1 之类，会导致死循环。
  • 退出条件永远不成立——用 break 时，如果依赖的条件（时间、金币等）实际上永远达不到，循环无法退出。
  • 忘记检查 item.type 就行动——像"炼金术传承"里没过滤毒药，英雄就会去碰不该碰的东西。
  • 缩进错误——continue/break 必须在循环体内、且在正确的 if 分支下，缩进错了逻辑就全乱了。

2.1 对象与属性

Objects and Properties

2.1.1 物品也是对象（Items Are Objects）

2.1.1.1 一种能装更多数据的数据类型 A data type that holds more data

本单元要让英雄学会"读懂"战场上的事物。"币屑"关卡揭示了一个重要真相："每个物品都是一个对象（object），对象是一种数据类型，就像字符串或者数字。"

前面学的字符串和数字都是简单的数据，而对象（Object）更高级——它能在自己身上打包携带许多份数据。地图上的硬币、宝石、药水、敌人、英雄，全都是对象。它们不只是一个值，而是一个装着多种信息的"百宝箱"。

2.1.2 属性是对象的数据（Properties Hold the Data）

2.1.2.1 对象身上挂着的一个个标签 Labeled data attached to an object

关卡定义道："对象还包含其他的数据，我们称之为属性（property）。" 属性（Property）就是对象身上挂着的一个个带标签的数据。比如一个敌人对象，有 type（类型）属性，有 pos（位置）属性，还有 health（生命）属性等。

"伪装者"关卡用了一个生动的类比："如果你想知道朋友的头发长度和颜色，可以这样……"——头发长度、头发颜色，都是"朋友"这个对象身上的属性。读取属性，就是从对象这个百宝箱里取出某一份具体数据。

2.1.3 点号访问属性（Dot Notation）

2.1.3.1 用 . 取出对象的某个属性 Use a dot to reach into an object

访问对象的属性，要用点号（.）。写法是"对象名 + 点 + 属性名"。你其实早就在用了——enemy.type 就是读敌人的类型，item.pos 就是读物品的位置。

2.2 pos 位置属性

The "pos" Property

2.2.1 pos 代表位置（pos Means Position）

2.2.1.1 每个单位都有 pos Every unit has a pos

本单元的核心属性是 pos。关卡明确："每个物品（及单位）对象都有一个 pos 属性，代表它的位置。" 无论是硬币、宝石，还是敌人、英雄自己——"边地投弹"关卡强调连英雄都有——只要在地图上，就有一个 pos 告诉你它在哪儿。

2.2.2 pos 里的 x 与 y（x and y Inside pos）

2.2.2.1 pos 本身又是一个对象 pos is itself an object

这里有个精妙的层次："而每个 pos 本身也是一个对象，拥有 x 和 y 属性。" 也就是说，pos 不是一个简单的数字，它又是一个小对象，里面装着两个数：

属性含义类型
pos.x水平位置（左右）浮点（十进制）数字
pos.y竖直位置（上下）浮点（十进制）数字

"边地投弹"关卡补充："x 和 y 是浮点（十进制）数字。X 代表敌人的水平位置，Y 代表敌人的竖直位置。" 这两个数字正好可以喂给 moveXY 和 buildXY 使用。

2.2.3 嵌套属性的访问链（The Access Chain）

2.2.3.1 一层套一层，点号往里钻 Drill down with chained dots

既然 item 是对象、pos 也是对象，要拿到最里层的 x，就得用点号一层层往里钻：先从 item 取 pos，再从 pos 取 x，连起来就是 item.pos.x。

💡 像查户口本一样层层翻

把 item.pos.x 想成"先翻开 item 这本册子，找到 pos 那一页，再读出 x 这一行"。每个点号都是"翻进下一层"的动作。理解这条访问链，你就能从任何对象里精确取出深藏的数据。

2.3 用坐标行动与计算

Acting and Calculating with Coordinates

2.3.1 移动到对象位置（Move to an Object's Position）

2.3.1.1 让坐标驱动移动 Let coordinates drive movement

读出坐标最直接的用途，就是移动过去。"币屑"关卡的完整思路是：找到物品 → 取出它的 pos → 拆出 x 和 y → 用 moveXY 走过去：

item = hero.findNearestItem()
if item:
    itemX = item.pos.x      # 拆出水平坐标
    itemY = item.pos.y      # 拆出竖直坐标
    hero.moveXY(itemX, itemY)   # 移动过去
为何不用写死坐标："币屑"提交时迷宫会变化，所以不能写固定的数字坐标。关卡要求"使用物品的位置来代替绝对的坐标数字"——读取 pos 是动态的，无论物品出现在哪，代码都能正确跟上。这是位置属性最大的价值。

2.3.2 直接引用还是存变量（Inline or Store First）

2.3.2.1 两种写法，效果相同 Two styles, same result

"白兔"关卡指出："你也可以直接引用 x 和 y，而不使用变量。" 所以有两种等价写法——一种是先把坐标存进变量再用，另一种是直接把 item.pos.x 写进 moveXY 的括号里：

# 写法一：先存变量（清晰、便于复用）
pos = item.pos
hero.moveXY(pos.x, pos.y)

# 写法二：直接引用（简洁）
hero.moveXY(item.pos.x, item.pos.y)
如何取舍：如果一个坐标只用一次，直接引用更简洁；如果要反复使用、或想让代码更易读，先存进变量更清晰。两者没有对错，按场景选择即可。

2.3.3 对坐标做运算（Doing Math on Coordinates）

2.3.3.1 把上一单元的运算用在 pos 上 Apply arithmetic to pos values

既然 pos.x、pos.y 就是数字，自然可以对它们做加减乘除。"风向校正"关卡要求用 y 坐标减去 4 来修正火炮落点：

y = enemy.pos.y - 4              # 对坐标做运算来校正
hero.say(enemy.pos.x + "," + y)  # 再拼成"x,y"格式报点

这一步把上一单元的坐标拼接与数学运算结合了起来：读属性 → 算坐标 → 拼字符串，三项技能环环相扣。

2.4.1 币屑（Coin Crumbs）

2.4.1.1 策略：跟着硬币轨迹动态走位 Strategy: follow the coin trail dynamically

图2：币屑——读取最近硬币的 pos 坐标,跟着轨迹躲开守卫逃出藏宝室

这是 pos 属性的首秀。藏宝室会随提交变化,且有迅捷守卫,所以绝不能写死坐标。算法思路是:循环中 findNearestItem() 找到最近硬币,读出 item.pos.x 和 item.pos.y,moveXY 走过去。硬币像面包屑一样指引路线,英雄读着坐标一路跟到出口。核心在于理解"读 pos 是动态的,地图怎么变都能应对"。

2.4.2 白兔（White Rabbit）

2.4.2.1 策略：追逐会移动的发光石 Strategy: chase the moving glowstone

图3：白兔——发光石跑得很快,但持续读它的 pos 就能穿过陷阱

这一关与"币屑"思路一致,但发光石会快速移动。算法关键在于把读坐标、移动放进 while 循环里不停重复——每一轮都重新 findNearestItem() 拿到发光石最新的 pos,再追过去。这样即使目标在跑,英雄也能持续锁定它的实时位置。这一关还示范了"直接引用 pos.x/pos.y"的简洁写法。

2.4.3 伪装者（The Mighty Sand Yak）

2.4.3.1 策略：边收集边防身 Strategy: collect while staying alert

图4：伪装者——食人魔伪装成硬币宝石,靠近时要能及时攻击自保

这一关把读 pos 和战斗结合。食人魔会伪装成物品,必须靠近才能识破。算法思路是:循环中先 findNearestEnemy(),看到敌人就 attack 自保;再 findNearestItem(),读出 pos.x、pos.y 移动去收集。"先防身、后收集"的判断顺序,保证英雄在贴近伪装者时不会吃亏。

顺序的讲究:把攻击判断放在移动之前,是一种防御性设计——确保每靠近一个可疑物品前,都先检查它是不是伪装的敌人。读 pos 让英雄能精准走位,而判断顺序让走位变得安全。

2.4.4 富有且安全（概念挑战 · Rich and Safe）

2.4.4.1 策略：用收集宝石当"护身符" Strategy: collecting gems keeps you safe

这是概念挑战,要在火焰攻击下存活 60 秒。诀窍很巧妙:食人魔不舍得砸坏宝石,所以只要英雄一直待在宝石旁收集,就是安全的。算法思路极简:循环中 findNearestItem() 找宝石,直接 moveXY(item.pos.x, item.pos.y) 移过去。不断收集 = 不断移动到安全点,生存问题就转化成了"持续读 pos 并移动"的问题。

2.4.5 边地投弹（Backwoods Bombardier）

2.4.5.1 策略：读敌人 pos 报点给火炮 Strategy: report enemy pos to the cannon

图5：边地投弹——读出敌人 pos 的 x、y,拼成"x,y"格式喊给火炮

这一关让英雄当"炮兵观察员"。算法思路是:循环找敌人,读出 enemy.pos.x 和 enemy.pos.y,用 + "," + 拼成"x,y"格式喊出来,火炮就按这个坐标开火;没有敌人时则喊"停止开火"。这里把读位置属性和字符串连接自然地结合在一起。

格式要点:火炮要求坐标用逗号分隔("x,y")。所以中间拼的是 "," 而非空格。报点的格式必须严格匹配火炮能识别的样式,差一个符号都可能瞄不准。

2.4.6 风向校正（组合挑战 · Wind Correction）

2.4.6.1 策略：读 pos + 算坐标 + 拼字符串 Strategy: read pos, adjust, concatenate

这是组合挑战,要把读属性、字符串连接、算术运算三项本领一次用全。任务是为大炮精确报点,但有风的干扰,需要把 y 坐标减去 4 来校正落点。算法思路是:读出敌人 pos.x 和 pos.y,把 pos.y - 4 算出新 y,再用逗号拼成"x,y"喊出。关卡提醒:只报 x 会漏掉一部分敌人,必须 x、y 都报才够精确。

enemy = hero.findNearestEnemy()
if enemy:
    y = enemy.pos.y - 4          # ① 读属性 + ② 算坐标
    hero.say(enemy.pos.x + "," + y)  # ③ 拼字符串报点
三技合一:这一关是第一、二单元的集大成——读位置属性(pos.x/pos.y)、对坐标做运算(-4)、把结果拼成字符串报点。三步一气呵成,正是处理"读取数据→加工数据→输出数据"这一通用流程的缩影。

2.5 常见错误

Common Mistakes

2.5.1 新手最容易踩的坑（Pitfalls for Beginners）

2.5.1.1 属性与坐标环节的典型问题 Typical issues with properties and coordinates

图6：漏写一层属性、写死坐标、未判断存在,是本单元最常见的失误
易错点清单：
  • 漏写一层属性——想要坐标却写成 item.x，正确应是 item.pos.x（先 pos 再 x）。
  • 把 pos 直接喂给 moveXY——moveXY(item.pos) 不行，要拆成 moveXY(item.pos.x, item.pos.y)。
  • 写死绝对坐标——地图会变化时仍用固定数字，应改用动态的 pos。
  • 没先判断对象是否存在——没找到物品时 item 为空，直接读 item.pos 会出错，要先 if item:。
  • 报点格式用错分隔符——火炮要逗号 ","，误用空格会瞄不准。
  • 校正时忘了运算——"风向校正"需 pos.y - 4，漏掉减法落点就偏了。

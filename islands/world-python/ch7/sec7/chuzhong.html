7.1 数组与迭代基础

Arrays and Iteration

在之前的冒险里，你一直依靠 hero.findNearest() 这样的"智能"方法自动帮你找到目标。但流金沙漠的峡谷会干扰你的眼镜，让自动寻路技能失灵！从本单元起，你要学会亲手遍历数组、亲手做判断——通过循环、索引和比较，从一堆物品或敌人里精准地挑出"最近""最远"或"特定"的那一个。这正是编程与人工智能中最核心的搜索思想。

本单元主线：贯穿全单元的是一个在计算机科学里反复出现的经典模式——遍历 + 比较 + 记录。它是排序、搜索、推荐算法乃至 AI 决策的雏形。AI 做决策时，本质上就是在候选集合里按某个评分函数挑出最优项，与本单元思想一脉相承。

7.1.1 什么是数组（What Is an Array）

7.1.1.1 数组是"一串按顺序排好的数据" An ordered list of values

数组（array）是一串按顺序排列的数据，比如一堆金币、一群敌人、一列名字。而迭代（iteration）就是"一个接一个地走过"数组里的每个元素，对它们逐一处理。像 hero.findItems()、hero.findEnemies() 返回的都是数组——只不过以前系统帮你处理了，现在要你自己动手走一遍。

7.1.2 手动遍历三件套（The Iteration Pattern）

7.1.2.1 索引变量、循环条件、索引自增 Index, condition, increment

手动遍历数组，需要三样东西配合：一个索引变量记录"现在看到第几个"，一个循环条件判断"是否还没走完"，以及一句索引自增让指针前进。这三件套和第一单元的计数器三部曲一脉相承，只是这次计数器用来"点名"数组里的元素。

🔢 数组遍历三件套
①初始化索引：循环前设 index = 0，从第一个元素开始
②判断没走完：while index < len(items)
③索引前进：循环体内 index += 1，指针挪向下一个
三者缺一不可——尤其是③，漏了它就会卡在第一个元素上死循环。 
# 遍历数组的标准结构
items = hero.findItems()      # ① 拿到数组
index = 0                    # ② 索引从 0 开始
while index < len(items):    # ③ 只要没走完就继续
    item = items[index]         # ④ 取出当前元素
    # ... 在这里处理 item ...
    index += 1                # ⑤ 指针前进一格（千万别忘！）

7.1.3 len 与循环终点（Where the Loop Stops）

7.1.3.1 len() 返回"元素个数" len() gives the count

len(items) 返回数组里元素的个数。如果数组里有 5 个金币，len(items) 就是 5。循环条件写成 index < len(items)，意味着当 index 从 0 数到 4 时循环执行，等 index 变成 5（已越界）时循环停止——恰好把每个元素都处理一遍，不多不少。

最容易犯的错：忘记写 index += 1。没有这句，index 永远是 0，循环条件永远成立，程序会卡在第一个元素上死循环，英雄站在原地一动不动。

7.2 索引访问与步长控制

Index Access & Step Control

7.2.1 方括号取值 arr[i]（Bracket Access）

7.2.1.1 方括号是访问单个元素的钥匙 Brackets pick one element

方括号 arr[i] 是从数组里取出单个元素的钥匙。把想要的位置编号写进方括号，就能拿到那个位置上的值。

everybody = ['Yetu', 'Tabitha', 'Rasha', 'Max']
# everybody[0] → 'Yetu'    （第 1 个）
# everybody[1] → 'Tabitha' （第 2 个）
# everybody[2] → 'Rasha'   （第 3 个）
name = everybody[2]   # name 现在是 'Rasha'

7.2.2 索引从 0 开始（Zero-based Indexing）

7.2.2.1 "索引比第几个小 1" Index is one less than position

计算机从 0 开始计数，所以数组的第一个元素索引是 [0]，第三个元素索引是 [2]。这条规则贯穿本单元每一关，也是最容易绊倒新手的地方。

记忆口诀：索引比"第几个"小 1。第 1 个元素的索引是 [0]，第 3 个元素的索引是 [2]，最后一个元素的索引是 len(arr) - 1。所以循环条件永远用 index < len(arr) 而不是 <=，否则就会索引越界报错。

7.2.3 步长跳跃访问（Stepping Through）

7.2.3.1 索引自增的数字叫"步长" The step decides which elements you visit

循环里索引自增的数字叫步长（step）。index += 1 是逐个访问；index += 2 则是隔一个访问一个——当需要跳过某些元素时非常有用。当数据是交替排列时（比如"敌-友-敌-友"），从索引 0 出发、步长为 2，就能只挑出所有偶数位、自动跳过奇数位。这正是"奇数沙尘暴"关卡的核心技巧。

步长的威力：只要数据的排列有规律，改变步长就能优雅地筛选，比"每个都取出来再判断敌友"更简洁高效。前提是你确信规律成立（例如偶数位一定是敌人）。

7.3 极值搜索算法

Finding the Extreme

7.3.1 打擂台的思想（The Champion Pattern）

7.3.1.1 "找最"的东西，本质是同一个问题 Finding max or min is one idea

"找最近的金币""找最远的敌人""找血最少的目标"——这些需求本质上都是同一个问题：在数组中找出某个属性的极值（最大或最小）对应的元素。解决它的经典方法叫打擂台算法。

想象一场擂台赛：先让一个选手站上擂台当"当前擂主"，然后每来一个挑战者就和擂主比一比，谁更强谁留下。全部比完后，站在台上的就是冠军。数组搜索极值就是这个思路：

🏆 打擂台五步走
①准备擂主变量：用 best 记录当前最优元素，用 bestValue 记录它的属性值
②设定初始擂主：找最小值时把 bestValue 设成超大数（如 9999），找最大值时设成 0
③逐个挑战：遍历数组，把每个元素的属性和 bestValue 比较
④更新擂主：挑战者更优，就把 best 和 bestValue 都换成它
⑤决出冠军：循环结束后，best 就是全数组的极值元素

7.3.2 找最小 vs 找最大（Min versus Max）

7.3.2.1 骨架相同，只有两处对调 Same skeleton, two swaps

找最小和找最大，算法骨架完全一样，只有两处需要对调：初始值和比较符号。理解了这张表，你就能在两个方向之间自由切换。

对比项找最小值（最近金币）找最大值（最远敌人）
擂主初始值设成很大：9999设成很小：0
比较符号if distance < bestValueif distance > bestValue
比较含义"更小就更新""更大就更新"

7.3.3 初始擂主值的选择（Choosing the Seed）

7.3.3.1 初始值决定打擂台能否正确工作 The seed value must lose to any real value

核心法则：找最小时，初始值必须大于任何真实距离，否则第一个元素永远打不过初始擂主；找最大时同理，初始值必须小于任何真实距离。简单说——初始擂主必须"弱到一定会被第一个真实元素打败"，这样擂台上最终留下的才是真正的极值。

7.4 打擂台法逐行拆解

Reading the Template Line by Line

7.4.1 模板逐行讲解（Walk Through the Code）

7.4.1.1 通用的"找最近元素"骨架 A reusable nearest-element skeleton

下面用一段通用的"找最近元素"代码骨架，逐行讲解每句话在做什么。请注意，这是通用模板，而非任何关卡的完整答案。

nearest = None          # 擂主：还没有人，先空着
nearestDistance = 9999  # 擂主成绩：先设一个大到离谱的数
index = 0               # 从第 0 个开始检查
while index < len(items):
    item = items[index]                  # 取出当前挑战者
    index += 1                      # 指针立刻前进，防止死循环
    distance = hero.distanceTo(item)   # 计算它的成绩
    if distance < nearestDistance:      # 它比擂主更好吗？
        nearest = item                   # 是 → 它当新擂主
        nearestDistance = distance       # 记下新的最好成绩
为什么先 index += 1 再计算？把 index += 1 放在取出元素之后、比较之前，是一个稳妥的习惯：它保证无论后面的逻辑多复杂、有没有提前跳转，指针都已经安全地前进了，从根源上杜绝死循环。

7.4.2 空数组的守护判断（Guard Against Empty）

7.4.2.1 行动前先确认"确实找到了目标" Check before you act

如果数组是空的（一个金币都没有），循环体一次都不执行，nearest 会保持 None。此时若直接 hero.moveXY(nearest.pos.x, ...) 就会因为 None 没有 pos 属性而报错。所以行动前先加一句 if nearest: 确认。

if nearest:                       # 确实找到了才行动
    hero.moveXY(nearest.pos.x, nearest.pos.y)
算法复杂度小知识：打擂台法只需要从头到尾扫描数组一遍，就能找出极值。如果数组有 n 个元素，就比较 n 次，我们说它的时间复杂度是 O(n)——这是搜索极值最高效的方式，不可能比"看一遍"更快。

关卡 · 沙蛇

🐍 沙蛇 —— 找最近的金币

图2：沙蛇——跟着最近的金币，踩着安全点穿越火焰陷阱峡谷

策略：打擂台找最小距离

峡谷会干扰眼镜，findNearest 技能失灵；地上的火焰陷阱之间，侦察员留下了硬币作为安全路标。只要总是走向最近的硬币，就能踩着安全点前进。既然自动寻路失灵，就用打擂台法手动找出最近的金币（距离最小），再用 moveXY 精确移动过去；到了新位置重新扫描、再找最近，如此循环推进。

思路拆解

算法思路是标准的"遍历 + 打擂台"：先用 hero.findItems() 拿到金币数组，初始化擂主 nearest = None、nearestDistance = 9999；遍历数组，用 hero.distanceTo(coin) 算距离并比谁更小；找到最近金币后用 moveXY 走过去。关键片段如下：

# 关键片段：打擂台找最小距离
if distance < nearestDistance:
    nearest = coin
    nearestDistance = distance
切记用 moveXY：必须用 hero.moveXY(nearest.pos.x, nearest.pos.y) 一步步移动到硬币坐标，而不是用会自动寻路抄近道的方式。硬币标记的就是安全落脚点，偏离就可能踩雷。
关卡 · 奇数沙尘暴

🌪️ 奇数沙尘暴 —— 步长跳跃筛选

图3：奇数沙尘暴——交替名单中，步长 +2 精准锁定所有敌人

策略：利用交替规律，步长设 2

一个名字数组 everybody 里朋友和敌人交替排列：偶数位（[0][2][4]…）是兽人敌人，奇数位（[1][3][5]…）是朋友。你要攻击所有敌人、绝不误伤朋友。这一关不需要打擂台，也不需要逐个判断敌友——利用交替规律，从索引 0 出发、每次索引 +2，就能只命中所有偶数位的敌人，天然跳过朋友。

思路拆解

算法思路是：索引 enemyIndex 从 0 开始，循环条件 enemyIndex < len(everybody) 遍历整个名单；用 everybody[enemyIndex] 取出敌人名字并攻击；关键一步是 enemyIndex += 2 跳过夹在中间的朋友；全部清理完后 moveXY 前往绿洲。

# 关键片段：步长为 2 跳过朋友
enemy = everybody[enemyIndex]   # 取偶数位的敌人名字
hero.attack(enemy)
enemyIndex += 2              # 每次 +2，跳过奇数位的朋友
前提要成立：这一关展示了"步长"的威力——只要排列有规律，改变步长就能优雅筛选，比"每个都取出来判断"更简洁。但前提是你确信规律成立（偶数位一定是敌人）；一旦排列被打乱，这个技巧就不再安全。

💨 疯狂的 Maxer —— 找最远的敌人

图4：疯狂的 Maxer——无视身边的诱饵，锁定最远处的真正敌人

策略：打擂台找最大距离

成群的诱饵（decoy）紧紧围在你身边扰乱视线，而真正攻击你的敌人躲在最远处。诱饵近、真敌远——只要锁定距离最大的目标，就能找到真正的威胁。用打擂台法，但这次找的是最大值：擂主成绩初始设为 0，比较时用 >。找到最远敌人后，持续攻击直到它血量归零。

思路拆解

算法思路是：初始化 farthest = None、maxDistance = 0；遍历 hero.findEnemies() 得到的敌人数组，对每个敌人算 distanceTo，若比 maxDistance 大就更新擂主；循环结束后 farthest 就是最远（真正）的敌人；再用一个内层 while farthest.health > 0 循环攻击到它倒下。

# 关键片段：打擂台找最大距离
if distance > maxDistance:     # 注意是 >（找最大）
    maxDistance = distance
    farthest = target
# ... 找到后，血量大于 0 就持续攻击 ...
while farthest.health > 0:
    hero.attack(farthest)
两段式结构：这一关是嵌套结构的绝佳示例：外层循环用打擂台找出目标，内层循环专注把这个目标打倒。"先决策、后执行"的两段式结构，正是 AI 行为逻辑的常见范式。
初始值别设错：初始 maxDistance 必须设为 0 而不是 9999。如果误设成 9999，任何真实距离都 > 不过它，擂主永远不会更新，farthest 会一直是 None。

7.6 常见错误

Common Mistakes

7.6.1 新手最容易踩的坑（Pitfalls for Beginners）

7.6.1.1 数组迭代的典型问题 Typical issues with array iteration

图5：忘记索引自增、初始值设反、比较符号写错，是本单元最常见的失误
易错点清单：
  • 忘记索引自增——写了 while index < len(items) 却漏掉 index += 1，卡在第一个元素上死循环，英雄站在原地不动。
  • 找最大值却总是 None——初始擂主值设成了 9999（太大），任何真实值都比不过它。找最大时初始值应设 0。
  • 找最小值却总选到远的——比较符号用反了。找最小用 <，找最大用 >。
  • 误伤了朋友——步长没设成 2，或起始索引错误。交替名单里要从 0 开始、每次 +2 只取偶数位。
  • 移动时报 pos 错误——数组为空，nearest 仍是 None。移动前加 if nearest: 判断。
  • 索引越界报错——循环条件误写成 <= len(arr)。要用 <，因为最大合法索引是 len - 1。
  • 混淆 = 与 ==——条件里比较用 ==（或 < >），赋值才用 =。

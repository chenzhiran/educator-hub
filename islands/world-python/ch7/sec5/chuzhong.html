5.1 嵌套循环基础

The Basics of Nested Loops

5.1.1 什么是嵌套循环（What Is a Nested Loop）

5.1.1.1 循环里面再放一个循环 A loop inside another loop

欢迎来到流金沙漠最烧脑、也最强大的一课！你已经学会了用 while 循环遍历数组、逐个处理元素。但真实的战场往往更复杂——一个敌人不是攻击一次就能倒下，一件物品也不是移动一次就能拿到。这时我们需要嵌套循环（nested loop）：把一个循环整个放进另一个循环的循环体里。

"游魂"关卡一语道破："对于强悍的敌人，只攻击一次是不够的，所以你应该使用 while 条件循环，当他们的 health 大于 0 时攻击。你可以把这个循环放入另一个 while 中，逐个击败敌人。" 换句话说——外层循环负责"轮到哪个敌人"，内层循环负责"把这个敌人彻底打死"。

图1：嵌套循环就像"套娃"——外层每转一圈，内层就要完整地跑完一整轮

5.1.2 内外层的分工（Inner vs. Outer）

5.1.2.1 外层"逐个"，内层"搞定一个" Outer picks one; inner finishes it

理解嵌套循环的钥匙，是想清楚两层各自的职责。用本单元最典型的"攻击"场景来说：外层遍历循环决定"现在轮到打哪个敌人"，内层条件循环负责"对着这个敌人一直砍，直到它血量归零"。

外层循环内层循环
条件enemyIndex < len(enemies)enemy.health > 0
职责遍历数组，逐个选出敌人对当前敌人反复攻击直到死亡
转一圈意味着处理完一个敌人成功命中一次攻击
推进方式enemyIndex += 1敌人被攻击后 health 自动下降

5.1.3 执行顺序（The Order of Execution）

5.1.3.1 内层不跑完，外层不前进 The outer waits for the inner to finish

嵌套循环最重要的执行规律是：外层每前进一步之前，内层必须先彻底跑完。 在"游魂"里，英雄不会打一下第一个骷髅就跳去打第二个——他会一直砍第一个直到它血量归零（内层循环结束），才执行 enemyIndex += 1 转向下一个（外层前进一步）。

一个直观的比喻：外层像"翻书"，一页一页翻；内层像"读完这一页的每个字"。你必须把当前这一页的字全部读完（内层跑完），才会翻到下一页（外层 +1）。理解了这个顺序，嵌套循环就不再神秘了。

5.2 边打边循环：内层条件循环

Inner Condition Loops

5.2.1 击败强敌的内循环（Attack Until Dead）

5.2.1.1 while enemy.health > 0 Keep attacking while health remains

本单元四个关卡都反复出现同一个内层循环模式——只要敌人还有血，就一直攻击。这是因为强敌一次砍不死，必须持续输出。

while enemy.health > 0:   # 只要还有血
    hero.attack(enemy)       # 就继续攻击
这个内循环为什么不会死循环？因为每次 hero.attack(enemy) 都会让 enemy.health 减少。血量是随攻击自动下降的——这正是让条件"迟早变假"的推进力。当血量降到 0，条件 enemy.health > 0 为假，内层循环自然结束。这里不需要手动 += 1，攻击本身就是"递减器"。

5.2.2 靠近目标的内循环（Move Until Close）

5.2.2.1 while hero.distanceTo(item) > 2 Keep moving while still far away

"游魂"关卡还展示了内层循环的另一种妙用——它不仅能用于敌人，也能用于物品。有些发光石会到处游荡，移动一次抓不到，就需要持续追赶直到足够近：

while hero.distanceTo(item) > 2:   # 距离大于 2 就还没拿到
    hero.moveXY(item.pos.x, item.pos.y)  # 就继续朝它移动

关卡概览说得很形象："那些游荡的灵魂很难收集。你需要一直向一个球移动，直到能抓住它们为止！" 这里推进条件的是"距离"——每次 moveXY 都让英雄离物品更近，距离终会小于 2，循环随之结束。

5.2.3 三层嵌套（Three Levels Deep）

5.2.3.1 遍历循环里，套着条件循环 A condition loop inside an iteration loop inside a main loop

"游魂"是本单元结构最复杂的一关，出现了三层嵌套！最外层 while True 反复守卫，中间层遍历敌人/物品数组，最内层则是"打到死"或"追到手"的条件循环。三层各司其职、层层包裹：

层数越多越要小心缩进：三层嵌套里，每一层的缩进都必须精确对齐。哪句属于第几层，全靠缩进决定。比如 enemyIndex += 1 必须和第 3 层的 while 对齐（属于第 2 层循环体），既不能缩进到第 3 层里面（那样永远加不到），也不能退到第 1 层（那样只会处理第一个敌人）。

5.3 按类型筛选敌人

Filtering Enemies by Type

5.3.1 用 type 判断身份（Using enemy.type）

5.3.1.1 遍历时挑出特定类型 Pick out specific types while iterating

光会遍历还不够——很多时候战场上混着各种单位，你只想攻击其中某一类。每个单位都有一个 type 属性，记录着它的身份，比如 "shaman"（萨满）、"thrower"（投掷者）、"sand-yak"（沙牦牛）。在遍历循环里加一个 if 判断 type，就能实现"精准打击"。

"潜伏"关卡的任务正是——牦牛群里混着兽人萨满，只打萨满、别误伤牦牛：

while enemyIndex < len(enemies):
    enemy = enemies[enemyIndex]
    if enemy.type == 'shaman':   # 只有是萨满才打
        while enemy.health > 0:
            hero.attack(enemy)
    enemyIndex += 1              # 不管是不是萨满，都要 +1

5.3.2 == 与 !=（Equal and Not Equal）

5.3.2.1 "是这类"与"不是这类" Match a type, or exclude a type

筛选有两种思路，对应两个比较运算符。想只打某一类，用 ==（等于）正向匹配；想排除某一类、打其余所有，用 !=（不等于）反向筛选。"Sarven 牧羊人"关卡就用了后者——牦牛不能打，那就打"所有不是牦牛的"：

if enemy.type != "sand-yak":   # "!=" 意思是"不等于"
    while enemy.health > 0:
        hero.attack(enemy)
运算符含义典型用法对应关卡
==等于（正向匹配）if enemy.type == "shaman"潜伏
!=不等于（反向排除）if enemy.type != "sand-yak"Sarven 牧羊人
别把 = 和 == 弄混：比较用双等号 ==（判断相等）或 !=（判断不等），赋值才用单等号 =。在 if 条件里写错成单个 = 会直接报语法错误。

5.3.3 筛选中仍要递增（Always Increment）

5.3.3.1 即使跳过，索引也要 +1 Increment even when you skip

这是筛选遍历里最致命的陷阱。"潜伏"关卡用醒目的口吻强调："重点：确保每次循环运行时都增加 enemyIndex，即使敌人不是巫师！"

为什么这么重要？因为 enemyIndex += 1 必须放在 if 判断的外面（与 if 同级）。如果误把它放进 if 里面，那么一旦遇到不是萨满的牦牛，判断为假、跳过整个 if 块，索引就不会增加——外层循环卡在这只牦牛上，条件永真，直接死循环。

📍 enemyIndex += 1 该放哪？
✅ 正确：放在 if 外面（与 if 同级缩进）——无论当前敌人是否被攻击，索引都前进一格。
❌ 错误：放在 if 里面——遇到不符合类型的敌人时索引原地不动，造成死循环。

5.4 两遍遍历策略

The Two-Pass Strategy

5.4.1 优先级作战（Attack by Priority）

5.4.1.1 先清高威胁，再扫全场 Clear the threats first, then the rest

"优待"关卡带来了一个精彩的算法思想——两遍遍历（two-pass）。战场上投掷者攻击力高但血薄，是最危险的目标。聪明的做法不是从头打到尾，而是把同一个数组遍历两次：第一遍只挑投掷者干掉，第二遍再清扫剩下的所有敌人。

⚔️ 两遍遍历 · 算法思路
第一遍：遍历 enemies，if enemy.type == "thrower" 才攻击 —— 优先铲除高威胁。
第二遍：重新 findEnemies() 拿到新数组、索引归零，再遍历一次，攻击所有还活着的敌人。 
# 第一遍：只打投掷者
enemies = hero.findEnemies()
enemyIndex = 0
while enemyIndex < len(enemies):
    enemy = enemies[enemyIndex]
    if enemy and enemy.type == "thrower":
        hero.attack(enemy)
    enemyIndex += 1

# 第二遍：重新获取数组，清扫剩余
enemies = hero.findEnemies()   # 关键：重新 find，索引重新归零
enemyIndex = 0
while enemyIndex < len(enemies):
    enemy = enemies[enemyIndex]
    if enemy:
        hero.attack(enemy)
    enemyIndex += 1
为什么第二遍要重新 findEnemies()？因为第一遍打死了投掷者，原来的 enemies 数组里已经混着"尸体"（失效引用）。重新调用 findEnemies() 拿到一份最新的存活名单，才能干净利落地清扫剩余敌人。这也是"数组会过时、要及时刷新"思想的又一次运用。注意代码里还用了 if enemy 先判断对象是否有效，多一层保险。

Level Strategy & Analysis

这一节聚焦每一关的策略、思路与算法设计，看懂"几层嵌套、内层循环的条件是什么、如何筛选、索引放哪"，你就能自己写出完整解法。

5.5.1 游魂（Wandering Souls）

5.5.1.1 策略：三层嵌套，先歼敌再收石 Strategy: three levels, fight then collect

图2：游魂——三层嵌套，内层"打到死/追到手"，让迷失的灵魂安息

这是本单元的开篇大关，一上来就是三层嵌套的完整演示。算法思路分两大块：先歼灭骷髅，再收集发光石。外层 while True 反复守卫；先遍历 enemies，对每个骷髅用内层 while enemy.health > 0 反复攻击直到消灭；再遍历 items，对每个游荡的发光石用内层 while hero.distanceTo(item) > 2 持续追赶直到抓住。

三个关键领悟：其一，内层循环的两种形态——一种以"血量归零"为终点（打敌人），一种以"距离够近"为终点（追物品），但本质都是"条件循环"；其二，两个遍历各用独立索引（enemyIndex 和 itemIndex），进循环前各自归零；其三，索引递增放在正确层级，必须在内层条件循环之后、外层遍历之内。

5.5.2 潜伏（Lurkers）

5.5.2.1 策略：遍历中用 == 精准锁定萨满 Strategy: match "shaman" with ==

图3：潜伏——牦牛群里混着萨满，用 type=="shaman" 只打萨满不伤牦牛

这一关引入按类型筛选。牦牛群里潜伏着兽人萨满，你只能打萨满、绝不能误伤无辜的牦牛。算法思路是：遍历 enemies，对每个敌人用 if enemy.type == 'shaman' 判断身份，只有是萨满时才进入内层 while enemy.health > 0 循环把它打死；不是萨满就跳过。

本关的灵魂在于索引递增的位置：enemyIndex += 1 必须放在 if 判断的外面。关卡特别用醒目提示强调这一点——"即使敌人不是巫师"也要递增。因为如果把 += 1 误放进 if 里，遇到牦牛时索引就不动了，外层循环会永远卡在那只牦牛身上，直接死循环。这是筛选遍历最经典的坑。

5.5.3 优待（Preferential Treatment）

5.5.3.1 策略：两遍遍历，先投掷者后其余 Strategy: two passes, throwers first

图4：优待——投掷者攻高血薄，第一遍专杀投掷者，第二遍清扫全场

这一关教的是作战优先级与两遍遍历。投掷者攻击力高但血量低，是最该优先解决的威胁。算法思路是两段并列的遍历：第一段遍历 enemies，用 if enemy.type == "thrower" 只攻击投掷者；第二段重新 findEnemies() 获取最新数组、索引归零，再遍历一次，用 if enemy 攻击所有还活着的敌人。

两个关键领悟：其一，用两遍遍历实现优先级——第一遍专挑高威胁目标，比无差别攻击的存活率高得多，这是一种典型的算法策略；其二，第二遍必须重新获取数组，因为第一遍已经改变了战场，旧数组里的投掷者引用已失效，重新 find 才能拿到准确的存活名单。这一关的两段遍历是先后串联而非嵌套，注意与"游魂"的区别。

5.5.4 Sarven 牧羊人（Sarven Shepherd）

5.5.4.1 策略：用 != 排除牦牛，守卫绿洲 Strategy: exclude yaks with !=

图5：Sarven 牧羊人——打"所有不是牦牛的"敌人，每波清完回中心待命

这是本单元的收官关卡，把嵌套、筛选、外层守卫融为一体。任务是从数波兽人袭击中保护绿洲，同时不能伤害穿行其间的沙牦牛。算法思路是：外层 while True 反复守卫；每圈先 findEnemies() 刷新数组、索引归零，遍历 enemies，用 if enemy.type != "sand-yak"（反向排除）筛出所有非牦牛的敌人，对每个用内层 while enemy.health > 0 打死；一波清完后，在 遍历循环外、但在 while True 内 执行 moveXY(40, 32) 回到中心待命。

三个关键领悟：其一，!= 反向筛选的妙用——与其枚举所有该打的类型，不如直接排除唯一不该打的牦牛；其二，仍然要注意 enemyIndex += 1 放在 if 外；其三，善后代码的层级——关卡特别提示，moveXY 要放在遍历循环后面（外面）、但仍在 while True 里面，这样才是"每清完一波才回中心"，而不是"打完一个敌人就回一次"。

5.6 常见错误

Common Mistakes

5.6.1 嵌套循环最容易踩的坑（Pitfalls）

5.6.1.1 嵌套 + 筛选的典型问题 Typical issues with nesting and filtering

图6：递增放错层级、缩进混乱、==/!= 用反，是本单元最常见的失误
易错点清单：
  • 把索引递增放进 if 里——遇到不符合类型的敌人时索引不前进，外层卡死，造成死循环。这是本单元第一大坑。
  • 把索引递增放进内层循环里——只要内层一结束就想 +1，位置太深，导致外层无法正确遍历。递增应在内层之后、外层之内。
  • 缩进层级错乱——三层嵌套里哪句属于哪层全靠缩进，错一格逻辑就全乱。
  • == 与 != 用反——想只打某类却用了 !=，或想排除某类却用了 ==，攻击对象完全相反。
  • 把善后代码放错层级——如"牧羊人"的 moveXY 应在遍历外、while True 内，放错就变成"每打一个就回一次"。
  • 两遍遍历时第二遍忘记重新 find 或忘记索引归零——沿用旧数组或旧索引，导致漏打或越界。
  • 内层循环条件写错——攻击敌人应是 enemy.health > 0，追物品应是 distanceTo > 2，条件写反会立刻死循环或根本不执行。
  • 误用单等号 = 做比较——条件里应用 == 或 !=，用 = 会报语法错误。

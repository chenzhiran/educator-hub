6.1.1 嵌套循环速记（Nested Loops in a Nutshell）

6.1.1.1 内层不跑完，外层不前进 The outer waits for the inner

欢迎回到流金沙漠！上一单元你正式认识了嵌套循环——循环里再套一个循环。本单元不引入全新语法，而是通过两个精心设计的关卡，让你把嵌套循环练熟、练透。先快速回忆一下核心要义：外层循环负责"逐个选出目标"，内层循环负责"把当前这个目标彻底搞定"；而且外层每前进一步之前，内层必须先完整跑完。

内层：条件循环，把"这一个"处理到底（打到死、追到手、收干净）
顺序：内层跑完，外层才 +1；缩进决定归属，一格都不能错

6.2 用属性筛选物品

Filtering Items by Property

6.2.1 value 属性辨类型（The value Property）

6.2.1.1 硬币的"面值"藏在 value 里 Each coin's worth is in its value

上一单元你学会了用敌人的 type 属性筛选目标。这一单元换个对象——物品也有可以用来筛选的属性。"捡闪亮东西的人"关卡告诉我们："每个硬币的 value 属性可以判断硬币的类型。金币的 value 为 3。"

沙漠里散落着铜币、银币、金币，价值各不相同。时间有限，聪明的做法是只捡最值钱的金币。判断的依据就是 coin.value 这个属性：

硬币类型value 值要不要捡
铜币（bronze）1价值低，跳过
银币（silver）2价值中，跳过
金币（gold）3✅ 只捡这个
属性筛选的通用思想：不管是敌人的 type、还是硬币的 value，本质都是读取对象的某个属性、用它作判断依据。学会这一招，你就能在一堆混杂的目标里精准挑出想要的那些。这是数据处理中极其常用的"过滤"操作。

6.2.2 筛选式遍历模板（The Filter-While-Iterating Pattern）

6.2.2.1 遍历 + if 判断 + 处理 Iterate, test, act

"筛选式遍历"是一个固定套路：用遍历循环走过数组里每个元素，用 if 判断它是否符合条件，符合才处理、不符合就跳过——但无论符不符合，索引都要递增（这条铁律上一单元已经反复强调）。

coins = hero.findItems()
coinIndex = 0
while coinIndex < len(coins):
    coin = coins[coinIndex]
    if coin.value == 3:          # 只有金币（value 为 3）才捡
        hero.moveXY(coin.pos.x, coin.pos.y)
    coinIndex += 1                # 不管捡没捡，都要 +1

6.3 两种内层循环写法

Two Ways to Write the Inner Loop

6.3.1 索引遍历法（Index Iteration）

6.3.1.1 用索引一个个走过整个数组 Walk the whole array with an index

这是你已经很熟悉的写法——先 findItems() 拿到整个数组，再用 index 从 0 走到 len()，逐个访问。它的特点是面向"整个快照"：一次性拿到当前所有物品，然后按顺序处理。"捡闪亮东西的人"用的就是这种写法。

6.3.2 存在性循环法（While-Object-Exists）

6.3.2.1 只要还找得到，就一直处理 Keep going while something still exists

"掠夺者"关卡展示了内层循环的另一种优雅写法——用"对象是否存在"作条件。关卡概览解释："while 表达式可以在某些东西存在时执行一些操作……也可以检查一些东西是否存在。" 思路是：找到最近的一个金币存进变量，只要它存在就去捡，捡完再重新找下一个最近的；直到再也找不到（变量为空），循环结束。

coin = hero.findNearestItem()
while coin:                          # 只要还有金币存在
    hero.moveXY(coin.pos.x, coin.pos.y)
    coin = hero.findNearest(hero.findItems())  # 关键：重新找、更新变量

这种写法面向"实时状态"：不预先记住所有金币，而是每次只盯着"当前最近的那一个"，处理完再问"还有吗？"。它不需要索引变量，天然避免了越界问题；但必须记得在循环末尾重新赋值，否则变量永远指向那个已被收集的旧金币，条件永真、死循环。

存在性循环的命门：这正是第一单元"峡谷风暴"里学过的"变量做条件必须在循环里更新"。while coin: 靠的是 coin 变量会变空——只有在循环末尾重新 coin = hero.findNearest(...)，当金币收完时它才会变成 None，循环才能停下来。漏掉这句，就是最典型的死循环。

6.3.3 两种写法对比（Comparing the Two）

6.3.3.1 该用哪一种？ Which one should you use?

两种内层写法都能"把一类东西收干净"，但适用场景略有不同。理解它们的差异，能让你在不同关卡里选对工具：

索引遍历法 · while index < len()
拿到整个快照后逐个处理
✅ 需要按顺序访问、或要筛选特定元素时更清晰
✅ 天然能配合 if 做筛选（如只捡 value==3）
⚠️ 数组是拍下的"旧快照"，处理途中若目标变动可能失准
⚠️ 要维护索引、记得递增，小心越界
存在性循环 · while object
每次只盯最近的一个，实时刷新
✅ 目标会移动/不断刷新时更稳（每轮都重新找最近的）
✅ 不用索引、不会越界，写法简洁
⚠️ 必须在循环末尾重新赋值，否则死循环
⚠️ 不方便"按顺序"或"按索引"精确控制
殊途同归：无论哪种写法，内核都是同一个"条件循环"——设一个迟早会变假的条件，在循环体内推动它变假。索引法靠 index += 1 逼近 len()；存在性法靠"收集/消灭目标"让对象最终消失。看透这一层，两种写法在你眼里就是一回事了。

6.4 分阶段作战

Fighting in Phases

6.4.1 先收集后战斗（Collect First, Then Fight）

6.4.1.1 一轮里安排多个阶段 Multiple phases in one round

"掠夺者"关卡还示范了一个重要的算法编排思想：在外层循环的一圈里，安排先后两个阶段——先把地上现有的金币收干净（一个内层循环），再去攻击机械把它打破（另一个内层循环）。机械被打破后又会掉出新金币，外层转到下一圈时再重新收集。

顺序即策略："先收金币再打机械"的顺序不是随意的——先把安全能拿的钱收进口袋，再去冒险攻击，能让收益最大化、风险最小化。同时注意"掠夺者"在攻击前用了 if enemy: 先确认敌人存在，避免对着空气发起攻击而报错。把动作按合理的先后顺序编排，本身就是算法设计的一部分。

6.5.1 捡闪亮东西的人（Shine Getter）

6.5.1.1 策略：遍历硬币，只捡 value 为 3 的金币 Strategy: iterate coins, take only value 3

图1：捡闪亮东西的人——限时内只捡最值钱的金币（value=3），跳过铜银币

这一关练的是用属性筛选物品。地上散落着各种面值的硬币，时间紧迫，必须只捡最值钱的金币来最大化收益。算法思路是标准的"筛选式遍历嵌套"：外层 while True 反复刷新战场；内层先 findItems() 拿到硬币数组、coinIndex = 0，遍历每一枚硬币，用 if coin.value == 3 判断是不是金币，是才 moveXY 去捡，不是就跳过；无论捡没捡，coinIndex += 1 都要执行。

两个关键领悟：其一，value 属性是筛选的钥匙——通过读取每个硬币的价值来决定取舍，这与上一单元用 type 筛敌人是同一思想；其二，索引递增必须在 if 外面，否则遇到铜银币时索引不动，直接死循环。外层的 while True 则保证金币刷新后能继续开采。

6.5.2 掠夺者（Raiders）

6.5.2.1 策略：先用存在性循环收金币，再打破机械 Strategy: collect with a while-object loop, then smash

图2：掠夺者——先把散落金币收干净，再攻击装满钱的机械，循环劫掠

这一关练的是存在性循环与分阶段作战。前行的机械里装满了钱，要打破它们才能拿到。算法思路是外层 while True 里编排两个阶段：阶段一用存在性循环 while coin: 把地上现有的金币收干净——找到最近的金币就去捡，捡完在循环末尾 coin = hero.findNearest(hero.findItems()) 重新找下一个，直到 coin 为空；阶段二找到最近的机械，先 if enemy: 确认存在，再用 while enemy.health > 0 反复攻击直到打破它。机械破碎掉出新金币，外层转下一圈时又回到阶段一收集。

三个关键领悟：其一，存在性循环靠"重新赋值"驱动——while coin: 能停下来，全靠循环末尾那句重新 findNearest，让 coin 在金币收完后变空；其二，攻击前先判断存在，if enemy: 避免对着不存在的目标出手；其三，阶段顺序即策略，先收安全的钱、再冒险破坏，收益与安全兼顾。这一关把两种内层写法（存在性循环 + 血量循环）在同一段代码里都用上了，是很好的综合练习。

6.6 常见错误

Common Mistakes

6.6.1 练习嵌套循环最容易踩的坑（Pitfalls）

6.6.1.1 筛选与存在性循环的典型问题 Typical issues with filtering and existence loops

图3：忘记重新赋值、递增放错位置、value 判断写错，是本单元最常见的失误
易错点清单：
  • 存在性循环忘记重新赋值——写了 while coin: 却没在循环末尾重新 findNearest，coin 永不为空，直接死循环。这是"掠夺者"的第一大坑。
  • 把索引递增放进 if 里——遇到非金币时索引不前进，外层卡死造成死循环。递增必须在 if 外。
  • value 判断写错——想捡金币应是 value == 3，写成别的值或用了 != 会捡错硬币。
  • 攻击前不判断存在——机械还没出现时直接 attack 会报错，应先 if enemy:。
  • 阶段顺序搞反——先打机械再收金币，可能在战斗中损失，或漏收先掉的金币。
  • 混用两种写法的要素——用了索引遍历却又忘了 len() 条件，或用了存在性循环却还去维护索引，逻辑打架。
  • 缩进层级错乱——阶段一、阶段二、外层的缩进要分清，错一格就会变成"收一个金币就打一下机械"。
  • 误用单等号 = 做比较——条件里应用 ==，用 = 会报语法错误。

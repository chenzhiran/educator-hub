Unit 1: Understanding the while Loop

1.1 while 循环基础

The Basics of while Loops

1.1.1 什么是 while 循环（What Is a while Loop）

1.1.1.1 "只要条件成立，就一直重复" Repeat while a condition holds

欢迎回到流金沙漠！在之前的冒险里，你可能用过 while True 这种"永远循环"的写法。本单元要揭开 while 循环（while loop）更强大的一面——它的条件不必永远是真。"尘埃"关卡一语道破："while 循环可以使用任何布尔条件，而不仅仅是 true……当条件为假时，循环将结束。"

换句话说，while 循环的含义正如它的英文本意："当（While）条件成立时，一直循环。" 一旦条件不再成立，循环就停下来，程序继续往下走。这让循环变得可控——你可以精确地告诉它"重复到什么时候为止"。

图1：while 循环像一道"闸门"——条件为真就放行再跑一圈，条件为假就关闸停下

1.1.2 循环的执行流程（How the Loop Runs）

1.1.2.1 每一圈开头都先"查条件" Check the condition at the top of each pass

关卡把执行机制讲得很清楚："就像 if 语句一样，while 循环需要指定一个条件。每次循环回到开头时，while 会检查条件是否为真。如果是，循环会继续执行；如果不是，循环停止。" 关键在于——检查发生在每一圈的开头，而不是随时打断。

1.1.3 死循环的危险（The Danger of Infinite Loops）

1.1.3.1 条件永远为真 = 永远出不来 A condition that never turns false

几乎每一关都反复警告同一件事："如果你的条件一直为真，有可能创建一个死循环（infinite loop）！" 死循环意味着程序卡在循环里永远出不来——目标没法完成，后面的代码也永远执行不到。

避免死循环的黄金法则："双颊"关卡说得直接——"确保你在 while 循环里做点什么，否则你可能会遇上死循环。" 更准确地说：循环体内必须有代码能让条件逐渐趋向"变假"。比如计数器要递增、变量要更新、金币要增加。只要条件迟早会变假，循环就一定能停下来。

1.2 计数型循环

Counting Loops

1.2.1 计数器三部曲（The Counter Pattern）

1.2.1.1 初始化 → 判断 → 递增 Initialize, test, increment

"尘埃"关卡要求"攻击 10 次然后撤退"，这是最经典的计数型循环。它有一个雷打不动的三段式套路，理解了它，你就掌握了"重复固定次数"的通用模板：

🔢 计数器三部曲
①初始化：循环前把计数器设为起点，如 attacks = 0
②判断：用计数器作条件，如 while attacks < 10
③递增：循环体内让计数器加 1，如 attacks += 1
三者缺一不可——少了①无从比较，少了②不会循环，少了③就成死循环。 
attacks = 0                    # ① 初始化计数器
while attacks < 10:            # ② 用计数器做条件
    enemy = hero.findNearestEnemy()
    if enemy:
        hero.attack(enemy)
    attacks += 1              # ③ 每轮递增，逼近终止

1.2.2 += 自增运算（The += Operator）

1.2.2.1 "增量意味着增加 1" Increment means add one

关卡里出现的 attacks += 1 是自增运算（increment）的简写。attacks += 1 完全等价于 attacks = attacks + 1——把变量当前的值取出、加 1、再存回原变量。它是推动计数器前进的"引擎"。

1.2.3 循环外的收尾代码（Code After the Loop）

1.2.3.1 循环结束后，程序继续往下 Execution continues below the loop

循环停止后，程序会执行紧跟在循环后面（缩进退回去）的代码。"尘埃"关卡正是如此：攻击满 10 次、条件变假、循环结束，接着才执行循环外的 hero.moveXY(79, 33) 撤退到 X 标记。缩进决定了哪些代码在循环内、哪些在循环外——这是极其关键的区别。

缩进即归属：Python 靠缩进划分代码块。写在 while 下方、缩进对齐的代码属于"循环体"，会反复执行；而缩进退回到与 while 同级的代码属于"循环外"，只在循环结束后执行一次。撤退、离开、领奖这类"善后动作"通常都放在循环外。

1.3 各种循环条件

Different Kinds of Conditions

1.3.1 用属性做条件（Using a Property）

1.3.1.1 直接拿英雄的状态当条件 Use the hero's live status

循环条件不一定要是自己维护的计数器，也可以是英雄的实时属性。"双颊"关卡的第二段就用 hero.gold：只要金币不够就继续捡，够了就停——这类循环叫做"直到达标为止"的循环。"先有付出才有回报"则用 hero.health：只在生命值大于 200 时才锻炼，血量掉到 200 就停下休息。

while hero.gold < 30:       # 金币不足 30 就继续捡
    item = hero.findNearestItem()
    if item:
        hero.moveXY(item.pos.x, item.pos.y)
妙在自动更新：用属性做条件的好处是——你不用手动维护计数器，因为 hero.gold、hero.health 这些值会随着游戏进程自动变化。捡到金币 gold 自然增加，被晒到 health 自然减少，条件也就自然地趋向变假。

1.3.2 用变量做条件（Using a Variable）

1.3.2.1 用"存住的对象"判断存在与否 Test whether an object still exists

"峡谷风暴"关卡展示了一个巧妙用法：用变量本身作条件。它把找到的沙牦牛存进变量 yak，然后 while yak——只要 yak 存在（不是 None），循环就继续；等牦牛全部撤退、找不到了，yak 变成空，条件为假，循环结束。这和用 if enemy 判断敌人是否存在是同一个道理。

yak = hero.findNearestEnemy()   # 先存一只牦牛
while yak:                     # 只要还有牦牛就循环
    # ... 趁机捡金币 ...
    yak = hero.findNearestEnemy() # 关键：每轮重新找、更新变量

1.3.3 条件的更新（Updating the Condition）

1.3.3.1 变量做条件，就必须在循环里更新它 A variable condition must be refreshed

"峡谷风暴"关卡反复强调："你可以使用一个变量作为 while 循环的条件，只要确保它在循环中会更新！" 这是用变量做条件时最容易忽略的一点——如果在循环里不重新给 yak 赋值，它就永远是最初那只牦牛，条件永远为真，直接死循环。

核心对照：用属性（hero.gold）做条件时，系统会自动更新它；用自定义变量（yak、attacks）做条件时，更新的责任在你自己——要么递增计数器，要么在循环末尾重新赋值。忘了更新，就是死循环最常见的成因。

1.4 循环与函数结合

Loops Inside Functions

1.4.1 把循环装进函数（Wrapping a Loop in a Function）

1.4.1.1 一次定义，多次复用 Define once, reuse many times

"诱饵和开关"关卡把 while 循环和函数结合起来，威力大增。它定义了一个 collectUntil(enoughGold) 函数，函数内部是一个"直到金币达标为止"的 while 循环；而目标金额通过参数传入，于是同一个函数可以被反复调用、每次设定不同的目标：

def collectUntil(enoughGold):
    while hero.gold < enoughGold:   # 条件里用参数
        coin = hero.findNearestItem()
        if coin:
            hero.moveXY(coin.pos.x, coin.pos.y)

collectUntil(25)   # 先攒够 25
# ... 建诱饵 ...
collectUntil(50)   # 再攒够 50
抽象的力量：把"重复攒钱"的逻辑封装进函数后，主程序就变得像一份清单——"攒25、建诱饵、躲藏、攒50、再建两个诱饵"，一目了然。用参数控制循环的终止条件，是把循环变成可复用工具的关键一步。

1.5.1 尘埃（Dust）

1.5.1.1 策略：计数器控制攻击次数 Strategy: count the attacks

图2：尘埃——用计数器精确控制攻击 10 次，随后撤退到伏击点

这是计数型循环的首秀。算法思路是标准的计数器三部曲：循环前 attacks = 0，以 attacks < 10 为条件，循环体内找到敌人就攻击、并 attacks += 1。要点在于把 attacks += 1 放对位置——它必须每轮都执行，才能让计数稳步逼近 10。满 10 次后循环自然结束，循环外的 moveXY 才带英雄撤退。

1.5.2 双颊（Cheeks）

1.5.2.1 策略：两个不同条件的循环串联 Strategy: chain two loops with different conditions

图3：双颊——先用计数循环打 6 兽人，再用属性循环攒够 30 金

这一关展示了两种条件循环的组合。第一段用计数器 defeatedOgres < 6，但有个细节很关键：只有真正攻击到敌人时才递增计数（defeatedOgres += 1 放在 if enemy 内），没敌人时喊一声而不加数，避免虚增。第二段改用属性条件 hero.gold < 30 收集金币。两段循环各有各的终止条件，依次完成不同目标。

1.5.3 峡谷风暴（Canyon Storm）

1.5.3.1 策略：以牦牛存在与否作为倒计时 Strategy: use the yak as a countdown

图4：峡谷风暴——趁沙牦牛还在时抢收金币，牦牛撤离即刻逃向红X

这一关的巧思在于借用环境线索当循环条件。沙牦牛能预知沙暴，所以"还有牦牛在"就等于"还安全"。算法思路是：先存 yak，while yak 期间不断捡金币，并在循环末尾重新 findNearestEnemy() 更新 yak。一旦牦牛全撤（yak 为空），循环结束，立刻 moveXY 逃到红 X。成败全系于那句"更新 yak"——漏了它就会一直捡金币到被沙暴吞没。

1.5.4 先有付出才有回报（No Pain No Gain）

1.5.4.1 策略：把 while True 改成血量条件 Strategy: replace True with a health condition

这一关的任务很聚焦：把死循环改造成有条件的安全循环。原本 while True 会让英雄在烈日下跑到死，解法是把条件换成 hero.health > 200——只在生命值足够时才跑步锻炼，血量一旦掉到 200 就停下，然后走向 Okar。核心领悟是：条件就是循环的"安全阀"，一个好的退出条件能防止英雄陷入危险。

1.5.5 沙漠战役（Desert Combat）

1.5.5.1 策略：先循环下令，再进入战斗 Strategy: give orders, then fight

图5：沙漠战役——先用计数循环下达 5 次命令激励士兵，再投入战斗

这一关把计数循环用于"重复下令"。算法思路是：用 ordersGiven < 5 的计数循环，每轮向下移动、喊 "Attack!"、并 ordersGiven += 1，激励盟友五次；循环结束后再用一个 while True 投入战斗。关卡反复强调别忘了给 ordersGiven 加 1——这是计数循环最容易漏掉、也最致命的一步，漏了就永远下不完命令。

1.5.6 诱饵和开关（Bait and Switch）

1.5.6.1 策略：用带参函数封装攒钱循环 Strategy: wrap the loop in a parameterized function

图6：诱饵和开关——封装 collectUntil 函数，分阶段攒钱建诱饵诱敌入陷阱

这是本单元的综合关卡，把循环、条件、函数、参数熔于一炉。算法思路是：定义 collectUntil(enoughGold)，内部用 while hero.gold < enoughGold 攒钱到指定数额；主程序则像剧本一样按阶段推进——collectUntil(25) 后在红标记建诱饵、躲藏，再 collectUntil(50) 后在骨头和木质标记各建一个诱饵。关键领悟是"参数化终止条件"：同一段攒钱逻辑，靠传入不同的目标值，就能服务于不同阶段的需求。

1.6 常见错误

Common Mistakes

1.6.1 新手最容易踩的坑（Pitfalls for Beginners）

1.6.1.1 while 循环的典型问题 Typical issues with while loops

图7：忘记更新条件、漏写递增、缩进错误，是本单元最常见的失误
易错点清单：
  • 忘记递增计数器——写了 while attacks < 10 却漏掉 attacks += 1，条件永真，直接死循环。
  • 用变量做条件却不更新它——如"峡谷风暴"里漏掉循环末尾重新 findNearestEnemy()，yak 永不为空。
  • 把递增放错位置——该放在循环体内却放到了循环外，或放进了错误的 if 分支，导致计数不准。
  • 缩进错误——把本应在循环内的代码写到了循环外，或反之，逻辑完全乱套。
  • 条件方向写反——想"攒够就停"却写成 while hero.gold > 30，一开始就不进循环。
  • 误把善后代码写进循环——撤退、离开的 moveXY 应放在循环外，放进去会反复触发。
  • 混淆 = 与 ==——条件里比较用 ==（或 < >），赋值才用 =。

13.1 for 循环再登场

The For Loop Returns

上一单元你第一次认识了 for 循环，学会了用 for friend in findFriends() 遍历盟友、用 range() 计数和配对两个数组。本单元的主题是"练习"——把 for 循环真正用到一场需要边行军、边搜索、边战斗的猎杀行动里。你将带领一支队伍搜遍山峰去寻找兽人营地，而指挥这支队伍的每一个动作，都在一个 for 循环里完成。

本单元主线：这一单元你要练熟三件事——用 for 遍历盟友并逐个下令、让每个士兵调用自己的 findNearestEnemy() 独立判断威胁、以及读取 friend.pos 用相对坐标让士兵"向右挪一小步"从而控制行军速度、保持阵型。for 循环 + 对象属性 + 相对移动，就是本单元的三样组合拳。

13.1.1 从"配对"到"自主"（From Pairing to Autonomy）

13.1.1.1 这次没有预设坐标数组 No preset points this time

上一单元的"动物园管理员""壮烈牺牲"里，你手写了一个 points 坐标数组，让士兵和固定点位一一配对。本单元不一样：没有事先规划的点位，士兵要一边前进一边自己找敌人。因此这次的 for 循环里，每个士兵的行动取决于它自己当下的处境——看到敌人就打，没看到就往前走。这就是从"被安排"到"自主决策"的升级。

上单元：配对固定点位
for j in range(len(friends)):
    friend = friends[j]
    point = points[j]
    hero.command(friend, "move", point)
本单元：各自随机应变
for friend in friends:
    enemy = friend.findNearestEnemy()
    if enemy:
        # 打
    else:
        # 走

13.1.2 循环内重新感知（Re-sense Inside the Loop）

13.1.2.1 每轮重新 findFriends Refresh the army every tick

本关的整体结构是一个 while True 主循环，里面套着一个 for 循环。要注意：friends = hero.findFriends() 写在 while True 内部的每一轮开头，这样部队名单每帧都会刷新——阵亡的士兵会被移除，若有新增援也会被纳入。感知放进循环、每轮更新，是游戏 AI"感知→决策→行动"节拍的又一次体现。

while True:
    friends = hero.findFriends()   # 每轮重新获取最新部队名单
    for friend in friends:
        # ...对每个士兵下令...
        pass
为什么不能在循环外只取一次？如果把 findFriends() 写在 while True 外面只取一次，之后阵亡的士兵仍留在数组里（对着"已消失的对象"下令可能出错），新召唤的士兵也进不来。把它放进循环里每轮刷新，才能始终指挥"当前还活着的这批人"。

13.2 让士兵各自决策

Let Each Soldier Decide

13.2.1 friend.findNearestEnemy（Each Unit's Own Nearest Enemy）

13.2.1.1 谁的视角，谁来找敌人 The enemy is found from the soldier's viewpoint

本单元最关键的一个新意识是：敌人要从士兵自己的角度去找。之前你常用 hero.findNearestEnemy()——那是离"英雄"最近的敌人。但在猎杀行动中，士兵们分散在山道各处，英雄躲在后方，用英雄视角找敌人毫无意义。正确做法是 enemy = friend.findNearestEnemy()，让每个士兵找离它自己最近的敌人。

# 让每个士兵找离"它自己"最近的敌人
for friend in friends:
    enemy = friend.findNearestEnemy()   # 注意：friend. 而不是 hero.
friend. 和 hero. 的一字之差：写成 hero.findNearestEnemy()，所有士兵都会去追同一个"离英雄最近"的敌人，队伍容易挤成一团、顾此失彼。写成 friend.findNearestEnemy()，每个士兵独立应对身边威胁，队伍才能沿整条战线均匀推进。这一字之差，就是"群体智能"的精髓。

13.2.2 攻击或移动的分支（Attack or Advance）

13.2.2.1 一个 if/else 决定进退 One if/else drives the whole tactic

每个士兵在循环体里只做一次简单判断：if enemy: 就 command(friend, "attack", enemy)；else: 就命令它向前移动一小步。"看到敌人就打，没敌人就往前搜索"——整支狩猎队的行为，全靠这一个 if/else 驱动。这也呼应了本关目标：一边推进搜山、一边清剿沿途兽人，直到找到并端掉营地。

13.3 相对坐标移动

Relative Movement

13.3.1 读取 friend.pos（Reading a Unit's Position）

13.3.1.1 每个单位都带着自己的坐标 Every unit carries its own position

要让士兵"从当前位置往前挪一点"，先得知道它当前在哪儿。游戏里每个单位都有一个 pos 属性，记录它此刻的位置；pos 本身又是个带 x 和 y 的对象，用点号一层层取：friend.pos.x 是横坐标，friend.pos.y 是纵坐标。这和字典 {"x":.., "y":..} 表达的信息一样，只不过这里是从对象上"读出来"的。

13.3.2 pos.x + 0.35 一小步（A Tiny Step Right）

13.3.2.1 在当前坐标上加一个小增量 Add a small delta to the current x

知道了当前位置，"向右挪一小步"就是：新目标的 x 用当前 x 加一个小数，y 保持不变。于是目标坐标写成 {"x": friend.pos.x + 0.35, "y": friend.pos.y}，再 command(friend, "move", moveTo)。因为 x 增大对应地图上向右，这就让士兵朝右侧（营地方向）稳步搜索前进。

# 以当前位置为基准，向右挪一小步
moveTo = {"x": friend.pos.x + 0.35, "y": friend.pos.y}
hero.command(friend, "move", moveTo)
相对坐标 vs 绝对坐标：上一单元用的 {"x": 50, "y": 40} 是绝对坐标——不管士兵在哪，都去那个固定点。本单元的 {"x": friend.pos.x + 0.35, ...} 是相对坐标——以士兵"当前所在"为起点算出目标，所以每个士兵各自往前走，而不是都挤向同一点。这是本单元最重要的新技巧。

13.3.3 用步长控速保阵型（Step Size Controls Speed）

13.3.3.1 为什么偏偏加 0.35 这么小 Why such a small increment

关卡有一条关键提示："给单位的 x 坐标增加一个较小的值，可限制他们的行进速度。这样会帮你把速度快的人和速度慢的人协调起来，进而影响战斗结果。"因为每一帧都只把目标设在"前方一丁点"，士兵实际就走得很慢、很克制。走得慢，快的单位就不会脱队冲进敌阵送死，全队能保持紧凑阵型一起推进——阵型不散，才能集中火力打赢遭遇战。

🐢 步长即油门
步长大（如 +5）：士兵一次冲很远，快的单位远远甩开队友，容易被敌人各个击破。
步长小（如 +0.35）：每帧只往前挪一丁点，全队慢而齐，阵型不散、火力集中。
结论：这个"加多少"就像油门，数值越小，队伍推进越慢越稳。
调参思路：如果你的士兵冲太快、阵型散了，就把 0.35 改得更小；如果推进太慢、迟迟找不到营地，就适当调大一点。没有唯一正确答案——这正是本关鼓励你"调数值、看结果"的实验精神。

关卡 · 狩猎派对

🏹 狩猎派对 —— 搜山推进，猎杀营地

图2：狩猎派对——率队缓慢向右推进搜索，沿途遇敌即战，直到发现并端掉兽人营地

策略：慢速推进 + 各自迎敌

本关任务是搜遍山峰、找出兽人营地。核心策略是把"行军"和"战斗"揉进同一个 for 循环：让整支队伍以极小步长缓慢向右推进搜索，谁的身边冒出敌人，谁就地开打，打完继续跟上。慢速推进保证阵型不散、火力能集中，这是能否啃下营地守军的关键。

英雄别亲自冲：关卡明确警告"如果你试着亲自和兽人作战，你可能会吸引兽人刺客的注意"。所以英雄应退到后方，专注做"指挥官"——只发号施令，让士兵去执行，切勿自己冲进敌群。

思路拆解

算法结构是"while True 外层 + for 内层"。每一轮：先 friends = hero.findFriends() 刷新部队；再 for friend in friends 遍历每个士兵；对每个士兵先 enemy = friend.findNearestEnemy() 从它自己的视角找最近的敌人；然后 if enemy: 就 command(friend, "attack", enemy)，else: 就用相对坐标 {"x": friend.pos.x + 0.35, "y": friend.pos.y} 命令它向右挪一小步。整支队伍就在"走一点、遇敌就打、打完再走"的节奏里逼近营地。

# 关键片段：遍历部队，遇敌就打，无敌向右一小步
for friend in friends:
    enemy = friend.findNearestEnemy()       # 各找各的最近敌人
    if enemy:
        hero.command(friend, "attack", enemy)
    else:
        moveTo = {"x": friend.pos.x + 0.35, "y": friend.pos.y}
        hero.command(friend, "move", moveTo)

算法要点回顾

这段代码把本单元三样组合拳全用上了：for 遍历让每个士兵都收到指令；friend.findNearestEnemy() 让每个士兵独立感知威胁；相对坐标 + 小步长让队伍慢速齐进、阵型不散。三者缺一，狩猎行动就会失败——不遍历则只有一人行动，用英雄视角找敌则队伍乱作一团，步长过大则快兵脱队被围歼。

为什么用 move 而不是 moveXY？命令士兵移动应使用 command(friend, "move", ...)，它是"下令后立即返回"的非阻塞方式，英雄能在同一轮里继续给其他士兵下令。若换成会卡住的阻塞式移动，就没法在一个循环里指挥全军了。这延续了前几单元关于 move 非阻塞特性的经验。

13.5 常见错误

Common Mistakes

13.5.1 新手最容易踩的坑（Pitfalls for Beginners）

13.5.1.1 for 练习中的典型问题 Typical issues while practicing for loops

图3：用错找敌视角、步长过大、写成绝对坐标，是本单元最常见的失误
易错点清单：
  • 用 hero 找敌人——写成 hero.findNearestEnemy()，全队都追同一个目标，应改用 friend.findNearestEnemy() 让各自应敌。
  • 写成绝对坐标——把 friend.pos.x + 0.35 误写成固定值如 {"x": 60, "y": 40}，所有士兵会挤向同一点。
  • 步长太大——增量写成 5、10，快兵脱队冲进敌群被各个击破；应保持较小值以控速保阵型。
  • 忘了改 y——只加 x、y 却写错或也加了值，士兵会斜着走偏离阵线；本关 y 应保持 friend.pos.y 不变。
  • findFriends 放在循环外——部队名单不刷新，阵亡单位残留、新单位漏掉，应放进 while True 每轮更新。
  • pos 属性链写错——写成 friend.x 或 friend.pos["x"] 而非 friend.pos.x，取不到坐标。
  • 攻击传错目标——"attack" 第三参数要传敌人对象 enemy，"move" 才传坐标字典，别弄反。
  • 英雄亲自上阵——招来兽人刺客；英雄应退后只做指挥。

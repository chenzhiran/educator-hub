10.1 字典基础

The Basics of Dictionaries

寒风凛冽的安息云峰到了！雪山之巅，路径崎岖，稍有不慎就会踩进陷阱。要在这里灵活穿行、精准移动，你需要掌握一种全新的数据结构——字典（dictionary）。它在 扣哒世界 里也被称作对象字面量（object literal），是用"名字"来存取数据的强大工具。本单元你会发现：原来你早就在用它了，只是从未认真端详过它的模样。

本单元主线：之前你用数组（array）按位置编号存取数据（coins[0]）；而字典换了个思路——用有意义的名字存取数据（pos["x"]）。当你写 hero.move(coin.pos) 时，那个 pos 其实就是一个装着 x 和 y 的小字典。看懂这一点，移动、寻路、构造坐标都会豁然开朗。

10.1.1 什么是字典（What Is a Dictionary）

10.1.1.1 用"名字"而不是"编号"存取数据 Look up by name, not by number

数组像一排储物柜，靠"第几号"取东西；字典则像一本通讯录，靠"名字"查电话。字典把数据组织成一组 键值对（key-value pair）：每个键（key）是一个名字，对应一个值（value）。关卡里的说法是："对象字面量是由与之相关联的键组成的。"比如坐标字典 {"x": 20, "y": 35}，键 "x" 对应值 20，键 "y" 对应值 35。

10.1.2 键值对结构（Key-Value Pairs）

10.1.2.1 花括号、冒号、逗号的分工 Braces, colons, and commas

写一个字典有固定的格式：用花括号 { } 把整个字典包起来，每一对里用冒号 : 把键和值连起来，多对之间用逗号 , 隔开。键通常是加引号的字符串，值可以是数字、字符串等。

# 一个表示位置的字典
pos = {"x": 20, "y": 35}
# 键 "x" 对应值 20，键 "y" 对应值 35

10.1.3 两种取值方式（Two Ways to Read）

10.1.3.1 方括号取键 与 点号取属性 Bracket access and dot access

从字典里取出某个值，有两种写法。关卡里两种都出现过：一种是方括号加键名 pos["x"]——正如关卡所说"pos.x 将返回 20，pos.y 将返回 35"；另一种是点号加属性名 pos.x。在 扣哒世界 里这两种写法效果相同，都能取到键 "x" 对应的值。

写法示例含义
方括号 + 键名pos["x"]取键 "x" 对应的值
点号 + 属性名pos.x取属性 x 的值（同上）
数组 vs 字典：数组用数字下标取值（gems[0]，第 0 个宝石），字典用键名取值（pos["x"]，x 坐标）。一个靠"排第几"，一个靠"叫什么"。理解这个区别，你就能根据场景选对工具：有序的一串用数组，带名字的属性用字典。

10.2 位置就是字典

A Position Is a Dictionary

10.2.1 pos 的真面目（What pos Really Is）

10.2.1.1 你早就在用字典了 You've been using dictionaries all along

这是本单元最重要的"顿悟时刻"：你之前写的每一个 coin.pos、enemy.pos、hero.pos，那个 pos 本身就是一个字典！关卡说得很清楚："'位置'是一种拥有一个 x 属性和一个 y 属性的对象。"所以 coin.pos.x 的完整含义是：先取硬币的 pos 字典，再从这个字典里取出 x 键的值。

coin = hero.findNearest(hero.findItems())
# coin.pos 是一个字典，形如 {"x": 34, "y": 20}
x = coin.pos.x     # 从 pos 字典里取 x 键 → 34
y = coin.pos.y     # 从 pos 字典里取 y 键 → 20

10.2.2 手写坐标字典（Building a pos by Hand）

10.2.2.1 自己造一个位置去指挥英雄 Construct your own position

既然 pos 是字典，那我们完全可以自己手写一个坐标字典，让英雄移动到任意指定的地方——哪怕那里没有任何物体。这正是"激流回旋"和"兽人山谷挖宝"两关的核心技巧：想去 (20, 35)，就直接传 {"x": 20, "y": 35}。

# 手写一个坐标字典，移动到 (20, 35)
hero.move({"x": 20, "y": 35})

# 移动到围栏后面的安全点 (15, 38)
hero.move({"x": 15, "y": 38})
两种参数来源：给 move 传位置时，可以用现成的字典（如 coin.pos，某个物体的位置），也可以临时手写一个字典（如 {"x": 20, "y": 35}，一个具体坐标）。前者用来追物体，后者用来去固定地点。

10.3 move 与 moveXY 的区别

move versus moveXY

10.3.1 参数的区别（Different Arguments）

10.3.1.1 一个参数 vs 两个参数 One argument versus two

本单元登场的新动作 move 和你熟悉的 moveXY 长得像，用法却不同。最直观的差别在参数：关卡说"move(pos) 有一个参数，而不是 moveXY(x, y) 的两个参数"。moveXY 要你拆开写 x 和 y 两个数字，move 只要一个装着坐标的字典。

moveXY —— 两个数字
hero.moveXY(coin.pos.x, coin.pos.y)
# 拆成 x、y 两个参数
move —— 一个位置
hero.move(coin.pos)
# 直接传整个 pos 字典

10.3.2 阻塞 vs 继续（Blocking versus Continuing）

10.3.2.1 这是二者最本质的差别 The deepest difference

比参数更关键的，是它们的运行行为。关卡把这点讲得很透彻：使用 moveXY，程序会停下来等待，直到英雄走到指定坐标才继续；而使用 move，英雄只朝目标迈出一小步，程序立刻继续往下运行。

10.3.3 一小步的追踪（Tracking Step by Step）

10.3.3.1 为什么"一小步"反而更强大 Why small steps win

"只走一小步"听起来像缺点，其实是 move 最大的优势。因为程序不会被冻住，你可以把 move 放进循环里，每一轮都重新计算目标、再迈一步。这样英雄就能实时追踪一个移动中的目标——目标跑到哪，下一步就朝哪。这正是"峭壁追逐"能追上会逃跑的 Pender 的秘诀。

一句话记牢：moveXY 适合去固定不动的地方（走到为止）；move 适合追移动中的目标或需要随时中断调整的场合（走一步、看一步）。选错了，追人会追丢、走路会撞墙。

关卡 · 峭壁追逐

🏃 峭壁追逐 —— 用 move 追上逃跑的目标

图2：峭壁追逐——用 move 一步步紧追不断逃跑的 Pender Spellbane

策略：把 move 放进循环持续追踪

Pender Spellbane 会不停地逃跑。如果用 moveXY 冲向她当前的位置，等你千辛万苦跑到，她早就走开了——你永远追的是"她刚才在的地方"。策略是改用 move：因为它只迈一小步就返回，把它放进 while True 循环，每一轮都重新找到 Pender、朝她的最新位置迈一步，就能像猎豹咬住猎物一样死死跟住。

思路拆解

算法思路是：开启 while True 永久循环；每轮用 hero.findNearest(hero.findFriends()) 找到 Pender（她是唯一的朋友，所以总是最近的那个）；确认找到后（if pender:），用 hero.move(pender.pos) 朝她当前位置迈一步。因为循环飞快地反复执行，无数个"一小步"连起来就成了紧咬不放的追逐。

# 关键片段：循环内用 move 追踪
pender = hero.findNearest(hero.findFriends())
if pender:
    hero.move(pender.pos)   # 只迈一步，下轮再更新
别用 moveXY 追人：这一关如果用 moveXY(pender.pos.x, pender.pos.y)，程序会卡在那里等你跑到旧坐标，等你到了 Pender 早跑远了。追移动目标，必须用会"走一步看一步"的 move。

⛷️ 激流回旋 —— 手写坐标字典走安全路

图3：激流回旋——在陷阱之间以坐标字典与宝石位置交替前进，蜿蜒收集宝石

策略：用 while 条件分段推进

这一关像滑雪的回旋赛道：陷阱密布，必须沿着"之"字形安全路径走，途中还要捡起宝石。核心技巧是用 hero.pos.x 作为循环条件分段前进。因为 move 只迈一小步，就用 while hero.pos.x < 20: 这样的循环"反复迈步，直到走过某个 x 坐标"，把整条路切成一段段来走。

思路拆解

算法思路是"安全点与宝石交替"：先用 while hero.pos.x < 20: 反复 move({"x": 20, "y": 35}) 走到第一个安全点；再用 while hero.pos.x < 25: 反复 move(gems[0].pos) 拐去捡第一颗宝石；如此这般，安全坐标（手写字典）和宝石坐标（现成 pos）交替出现，一段一段地把英雄安全送到终点。

# 关键片段：用 x 坐标分段，交替走安全点和宝石
while hero.pos.x < 20:
    hero.move({"x": 20, "y": 35})   # 手写字典：去安全点
while hero.pos.x < 25:
    hero.move(gems[0].pos)          # 现成 pos：去捡宝石
为什么用 while 而不是一句 move？因为 move 只走一小步。想真正"走到"某个 x 坐标，就得用 while hero.pos.x < 目标: 反复迈步，直到条件不再成立。这也是本关把 move 的"非阻塞"特性用足的地方——每迈一步循环都重新检查位置，走到了就自动进入下一段。
本关禁用 moveXY：关卡特意规定不能用 moveXY()，逼你熟练掌握 move + 坐标字典的组合。这是刻意的训练——先在受限环境里练熟新工具，才能在实战中信手拈来。

⛏️ 兽人山谷挖宝 —— 限时收集与撤退建墙

图4：兽人山谷挖宝——20 秒内狂捡金币，随后撤到围栏后并筑墙挡住兽人

策略：三阶段——抢收、撤退、封锁

兽人来袭前只有 20 秒！策略是清晰的三阶段：第一阶段限时抢金币，用 while hero.time < 20: 在时间窗口内不停捡最近的硬币；第二阶段撤退，用 while hero.pos.x > 16: 一路 move 到围栏后的安全坐标；第三阶段封锁，用 buildXY 造一道围栏挡住兽人。

思路拆解

算法思路是：抢收阶段每轮 coin = hero.findNearest(hero.findItems()) 找最近硬币、hero.move(coin.pos) 走过去，靠 hero.time 这个时间条件自动收尾；撤退阶段用手写字典 move({"x": 15, "y": 38}) 反复迈步退到围栏后；最后 hero.buildXY("fence", 20, 37) 在关键位置建墙。三段用不同的循环条件（时间、x 坐标）无缝衔接。

# 关键片段：限时抢金币 → 撤退 → 建墙
while hero.time < 20:
    coin = hero.findNearest(hero.findItems())
    hero.move(coin.pos)
# ... 撤退到围栏后 ...
hero.buildXY("fence", 20, 37)
用时间做循环条件：这一关的巧思是用 hero.time（游戏内已过去的秒数）当循环条件。while hero.time < 20 意味着"只在前 20 秒抢金币"，时间一到自动停止——不用自己数数，环境属性帮你计时。这和第七、八单元"用属性做条件"是同一思路。
优化路径才能达标：关卡挑战是"兽人出现前收集超过 60 枚硬币"。因为 move 一步步走较慢，要动脑优化路线——优先捡成堆、顺路的硬币，别为一枚远处的硬币折返，才能在 20 秒内攒够。

10.5 常见错误

Common Mistakes

10.5.1 新手最容易踩的坑（Pitfalls for Beginners）

10.5.1.1 字典与 move 的典型问题 Typical issues with dictionaries and move

图5：参数用错、忘记花括号、move 不放循环里，是本单元最常见的失误
易错点清单：
  • 给 move 传两个数字——写成 move(20, 35)。move 只收一个位置参数，要写成 move({"x": 20, "y": 35}) 或 move(coin.pos)。
  • 字典忘了花括号——写成 move("x": 20, "y": 35)，缺了 { } 就不是字典，会报错。
  • 键没加引号或用错符号——键值之间要用冒号 :，多对之间用逗号 ,，别写成分号或等号。
  • 用 move 追人却不放循环里——只写一句 move 只会迈一步就停。追踪必须放进循环反复执行。
  • 用 moveXY 追移动目标——会一直追"旧位置"，永远追不上。追人用 move。
  • while 条件方向写反——想向右走却写 while hero.pos.x > 20，一开始就不进循环。
  • 忘了本关禁用 moveXY——"激流回旋"里用了 moveXY 会不通过，必须用 move。

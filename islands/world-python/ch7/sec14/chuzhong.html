14.2 新技能：找最值

New Skill: Finding the Maximum

14.2.1 打擂台算法（The King-of-the-Hill Pattern）

14.2.1.1 遍历中"擂主"不断被挑战 A champion that keeps getting challenged

"从一堆东西里挑出最大的那个"是编程里最基础、最常用的算法之一，我们叫它打擂台（找最值）。做法是：先设一个"擂主"变量存"目前见过的最大值"，再逐个检查每个元素——如果某个比当前擂主还大，它就成为新擂主。全部检查完，擂主就是真正的最大值。本关要找的是 health（生命值）最高的敌人。

14.2.2 遍历找最大 health（Loop to Find Max Health）

14.2.2.1 两个变量：擂主与它的分数 Two variables: the champion and its score

把打擂台翻译成代码，需要两个变量：一个记"当前最强的敌人对象"（toughest），一个记"这个最强敌人的生命值"（mostHealth）。开局把 toughest 设为 None、mostHealth 设为 0；然后 for enemy in enemies: 逐个比较，遇到 enemy.health > mostHealth 就同时更新这两个变量。

# 打擂台：找出生命值最高的敌人
toughest = None          # 擂主（对象），一开始还没有
mostHealth = 0            # 擂主的生命值，从 0 起
enemies = hero.findEnemies()
for enemy in enemies:
    if enemy.health > mostHealth:   # 比擂主还强？
        toughest = enemy               # 换擂主
        mostHealth = enemy.health      # 更新最高分
两个变量必须"同步更新"：一旦发现更强的敌人，toughest（是谁）和 mostHealth（多强）要在同一个 if 里一起改。如果只更新其中一个，"擂主"和"擂主的分数"就对不上了，后续比较全乱套。这是打擂台算法最容易出错的地方。
为什么 mostHealth 从 0 开始？因为任何活着的敌人生命值都大于 0，所以第一个敌人一定能顺利"登上擂台"成为初始擂主。把初始最大值设成 0（或一个足够小的数），能保证擂台不会空着。

14.2.3 每帧重算的意义（Recompute Every Tick）

14.2.3.1 目标会变，所以要不停重找 The target changes, so keep re-finding it

本关最妙的一点在关卡提示里说得很清楚："不要持续攻击最难对付的敌人直到击败它！你要让你的弓箭手不断地将目标换为任何此刻生命值最高的敌人！"因为随着战斗进行，各单位的生命值时刻在变——现在最强的，被打几下后可能就不再是最强的了。所以整段"找最值 + 下令"必须放进 while True，每一帧都重新算一次擂主，让弓箭手的火力永远压在当下最硬的那个目标上。

🔄 每帧重算的三步节拍
①感知：findEnemies() 拿到当前所有敌人
②决策：打擂台算出此刻 health 最高的 toughest
③行动：命令所有弓箭手集火 toughest
下一帧，重复①②③——目标随战况实时切换，绝不"死磕"一个。

14.3 战术思维复习

Reviewing Tactical Thinking

14.3.1 集中火力（Focus Fire）

14.3.1.1 全军打同一个目标 The whole army hits one target

找到擂主之后，怎么下令？答案是集中火力——遍历所有弓箭手，让他们统统攻击同一个 toughest。这与上一单元"各打各的最近敌人"正好相反：那里是分散应敌保阵型，这里是攥成拳头快速打死一个高威胁目标。用哪种，取决于战场目标。

# 集中火力：所有弓箭手打同一个目标
if toughest:
    friends = hero.findFriends()
    for friend in friends:
        hero.command(friend, "attack", toughest)
别忘了先 if toughest：如果场上暂时没有敌人，打擂台结束后 toughest 仍是 None。此时若直接下令攻击 None 会出错。用 if toughest: 守卫一下——有目标才下令，没目标就跳过。这是"用前先判断存在"的好习惯。

14.3.2 借刀杀人（Let Enemies Fight）

14.3.2.1 让两拨敌人先自相残杀 Let the two enemy sides wear each other down

"借刀"这个关卡名点出了最高明的战术思想。场上食人魔正和雪人打架，关卡分析指出：如果你什么都不做、或只瞄最近的敌人，一方会赢、且残兵足以反过来击败你的弓箭手。聪明的做法是始终攻击当下最强的一方——相当于总去帮"弱势方"补刀，让两拨敌人尽可能互相消耗（借他们的刀互砍），等他们两败俱伤，你的弓箭手再收拾残局。

算法与战术的合一："总打最强的一方"在代码里恰好就是"每帧找 health 最高的敌人来打"。打擂台算法在这里不只是一段技巧，它本身就是这条战术的化身——谁暂时占上风就削谁，动态维持天平平衡，直到双方一起被拖垮。算法即策略，这正是本关想让你体会的编程之美。

14.4 实战关卡精讲

Level Strategy & Analysis

这一节聚焦关卡的策略、思路与算法设计，只展示用于说明的关键片段，完整通关程序请你自己动手完成。

关卡 · 借刀

🗡️ 借刀 —— 集火最强，坐收渔利

图2：借刀——食人魔与雪人混战，弓箭手每帧改瞄当下生命值最高者，坐收两败俱伤之利

策略：英雄不出手，只当"军师"

本关最反直觉的一点是——英雄自己不参与战斗。关卡明确说"你的英雄不需要参与战斗"。你的角色是"军师"：站在后方，用一段每帧刷新的程序，指挥弓箭手把火力始终压在场上最强的敌人身上。真正的杀伤既来自弓箭手，也来自被你操控着"互相消耗"的两拨敌人。

思路拆解

算法结构是"while True + 两个 for"。每一帧分三步走。第一步找最值：把 toughest = None、mostHealth = 0 归零后，用 for enemy in hero.findEnemies(): 打擂台，遇到 enemy.health > mostHealth 就更新 toughest 和 mostHealth。第二步判断存在：if toughest: 确认确实找到了目标。第三步集中火力：for friend in hero.findFriends(): 让每个弓箭手都 command(friend, "attack", toughest)。下一帧重复，目标随战况实时切换。

# 关键片段：找最值 → 判断存在 → 集中火力
toughest = None
mostHealth = 0
for enemy in hero.findEnemies():
    if enemy.health > mostHealth:
        toughest = enemy
        mostHealth = enemy.health

if toughest:
    for friend in hero.findFriends():
        hero.command(friend, "attack", toughest)

算法要点回顾

这段代码把本阶段的工具几乎全用上了：两次 for 遍历（一次找目标、一次下令）、command 三参数（攻击传敌人对象）、打擂台找最值（新算法）、以及 if toughest 的存在性判断。缺了打擂台就无法锁定最强目标；缺了每帧重算就会"死磕一个"而错失动态平衡；缺了 if toughest 则可能对 None 下令而报错。

变量归零要在循环内：toughest = None 和 mostHealth = 0 必须写在 while True 的每一轮开头。若写在循环外只归零一次，擂主就会一直沿用上一帧的旧值，无法随战况刷新，弓箭手会盯着一个可能已经变弱甚至消失的目标。
为什么不用 findNearest？如果只用 findNearestEnemy() 打最近的，你可能帮某一方太快清场，让胜方带着大量残兵反扑。而"打最强的"能持续压制暂时的优势方，把两拨敌人的战力都耗在互殴上——这就是本关必须自己写打擂台、而不能偷懒用现成"找最近"的原因。

14.5 常见错误

Common Mistakes

14.5.1 新手最容易踩的坑（Pitfalls for Beginners）

14.5.1.1 找最值与集火的典型问题 Typical issues with max-finding and focus fire

图3：变量没在循环内归零、只更新一个变量、忘记 if toughest，是本单元最常见的失误
易错点清单：
  • 归零写在循环外——toughest、mostHealth 应在 while True 每轮开头重置，否则擂主永远刷新不了。
  • 只更新一个变量——发现更强敌人时，toughest 和 mostHealth 要在同一个 if 里一起改，漏一个就对不上。
  • 比较写反——想找最大却写成 enemy.health < mostHealth，结果找出的是最弱的敌人。
  • 忘记 if toughest——场上没敌人时 toughest 为 None，直接攻击 None 会报错。
  • 死磕一个目标——把找最值放在 while True 外只算一次，弓箭手会盯着旧目标，违背"不断改瞄"的战术。
  • 英雄亲自上阵——本关英雄应只做指挥，冲进混战反而可能被残兵击败。
  • 攻击传错目标——"attack" 第三参数是敌人对象 toughest，不是坐标字典。
  • mostHealth 初值设太大——若设成一个比所有敌人都大的数，就没有敌人能登上擂台，toughest 一直是 None。

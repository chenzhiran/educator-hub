2.1 多个 while 循环

Multiple while Loops

2.1.1 一关多循环（Many Loops, One Level）

2.1.1.1 把大任务拆成几段循环 Split a big task into several loops

上一单元你认识了 while 循环，这一单元是动手练习——尤其要练"在一段程序里用好几个循环"。"海市蜃楼"关卡开门见山："使用多个 while 循环执行各种任务。" 现实中的任务往往由几个阶段组成，每个阶段有自己的目标和终止条件，于是一个阶段配一个循环是最自然的做法。

"海市蜃楼"就把一整关拆成四步：先攒够金币、再建诱饵、然后挑衅兽人、最后撤退。其中"攒金币"和"挑衅"各是一个 while 循环，"建诱饵""撤退"则是循环之间的单次动作。理解"哪些该循环、哪些只做一次"，是本单元的第一项功课。

2.1.2 循环的先后顺序（The Order of Loops）

2.1.2.1 上一个循环停了，下一个才开始 A loop must finish before the next begins

多个循环按顺序排列、依次执行：只有当第一个循环的条件变假、它彻底停下后，程序才会往下走到第二个循环。这一点非常重要——它意味着每个循环都必须能自己停下来，否则程序会永远卡在前一个循环里，后面的循环和动作根本轮不到。

2.1.3 不同类型的条件（Mixing Condition Types）

2.1.3.1 同一关里混用多种条件 Different conditions in one level

"海市蜃楼"精彩之处在于——它在同一关里用了两种截然不同的循环条件。第一个循环用数值比较 hero.gold < 25（攒够就停），第二个循环用相等判断 hero.health == hero.maxHealth（一旦掉血就停）。这提醒我们：条件要为每个阶段"量身定制"，选对条件，循环才能在恰当的时机停下。

while hero.gold < 25:              # 条件A：数值比较
    # ... 收集金币 ...

hero.buildXY("decoy", 71, 68)  # 循环之间的单次动作

while hero.health == hero.maxHealth: # 条件B：相等判断
    hero.say("Ogres stink!")

2.2 精确控制次数

Controlling the Exact Count

2.2.1 收集"正好 N 个"（Collect Exactly N）

2.2.1.1 多一个也不行，少一个也不行 Not one more, not one fewer

"菠菜力量"提出了一个更苛刻的要求：收集正好 7 瓶药水——喝少了打不过食人魔，喝多了会生病。这类"精确 N 次"的任务，考验的是计数循环的精确性。思路仍是计数器三部曲：potionCount = 0 初始化，while potionCount < 7 判断，捡到药水后 potionCount += 1。

potionCount = 0
while potionCount < 7:
    item = hero.findNearestItem()
    if item:
        hero.moveXY(item.pos.x, item.pos.y)
        potionCount += 1   # 只在真的捡到时才计数

2.2.2 < 与 <= 之差（< versus <=）

2.2.2.1 一个符号，差一整轮 One symbol, one whole iteration

"菠菜力量"点出了本单元最核心的一个陷阱："一个常见的错误是在 potionCount 小于或等于 7 时执行循环，结果收集了 8 瓶药水。" 也就是说，< 和 <= 只差一个等号，循环次数却会差整整一轮。

为什么？关键在于循环在计数达到几时还会再进去一次。用 potionCount < 7：当计数为 6 时条件成立、进去捡第 7 瓶、计数变 7；下一轮 7 < 7 为假，停止——正好 7 瓶。但若用 potionCount <= 7：当计数为 7 时 7 <= 7 仍成立，会再进去捡第 8 瓶——多了一瓶！

条件写法计数为 7 时最终收集结果
potionCount < 77 < 7 为假，停止正好 7 瓶✅ 正确
potionCount <= 77 <= 7 为真，再捡一瓶8 瓶❌ 多一瓶

2.2.3 差一错误（Off-by-One Errors）

2.2.3.1 编程界最出名的小 bug The famous off-by-one bug

刚才那个"多一瓶/少一瓶"的问题，在编程里有个专门的名字，叫做差一错误（Off-by-One Error）。它是初学者乃至资深程序员都会犯的经典 bug——循环多跑一次或少跑一次，往往就是因为条件里的 < 和 <=（或计数器起点是 0 还是 1）没选对。

验证小技巧：写完计数循环后，别急着运行——先心算"临界那一刻"：计数正好等于目标值时，条件到底是真还是假？想清楚这一步会不会"多进去一轮"，差一错误就无所遁形。对于"从 0 开始、要 N 次"的循环，用 < N 几乎总是对的。

2.3 相等条件循环

Loops with Equality Conditions

2.3.1 用 == 做条件（Using ==）

2.3.1.1 "只要还……就一直……" Keep going while two values match

"海市蜃楼"的挑衅循环用了 while hero.health == hero.maxHealth——只要生命值等于满血，就一直挑衅兽人。这类相等条件的含义是"只要状态还没被打破，就继续做某事"。这里的言外之意是：兽人被激怒后迟早会打你一下，你的血一旦掉哪怕一点点，health == maxHealth 就变假，挑衅停止，你便可以安全撤退了。

== 不是 =：条件里判断"相等"必须用双等号 ==，单等号 = 是赋值。写成 while hero.health = hero.maxHealth 会直接报错。这是初学者极易混淆的一点——"比较用双等，赋值用单等"务必牢记。

2.3.2 何时自动停下（When It Stops by Itself）

2.3.2.1 靠外部事件打破条件 An outside event breaks the condition

值得注意的是：挑衅循环体里只有一句 hero.say(...)，并没有任何代码去主动改变 health。那它靠什么停下来？靠外部事件——被兽人攻击。这和上一单元"峡谷风暴"里牦牛撤离、"先有付出才有回报"里烈日掉血是同一类：循环的终止不一定由你的代码直接造成，也可以由游戏世界的变化触发，只要那个变化最终会让条件变假即可。

🔄 两种"让条件变假"的方式
内部驱动：循环体自己改变条件相关的值——如 potionCount += 1、循环末尾重新找 yak。
外部驱动：由游戏世界的事件改变属性——如被兽人打掉血、金币被系统结算。
无论哪种，只要条件迟早会变假，循环就能安全退出；两种都不会发生，就是死循环。

Level Strategy & Analysis

这一节聚焦每一关的策略、思路与算法设计，看懂"每个循环该配什么条件、按什么顺序排"，你就能自己写出完整解法。

2.4.1 海市蜃楼（Mirage）

2.4.1.1 策略：四阶段任务，循环与单次动作交替 Strategy: four phases of loops and one-shot actions

图2：海市蜃楼——攒金币→建诱饵→挑衅→撤退，循环与单次动作交替推进

这一关是"多循环编排"的典范。算法思路是把任务拆成四个前后相接的阶段：① 用 while hero.gold < 25 的循环攒够金币；② 循环结束后用一次 buildXY("decoy", ...) 在指定标记建诱饵；③ 用 while hero.health == hero.maxHealth 的循环持续挑衅，把兽人斗士引向诱饵，直到自己挨打掉血才停；④ 最后一次 moveXY 撤退到红 X。

思路要点：成败的关键是分清"循环动作"与"单次动作"——攒钱、挑衅需要重复所以用循环；建诱饵、撤退只做一次所以放在循环外。此外两个循环的条件类型不同（数值 vs 相等），要根据"这个阶段靠什么信号结束"来选择合适的条件。

2.4.2 菠菜力量（Salted Earth / Spinach Power）

2.4.2.1 策略：精确计数，警惕差一错误 Strategy: count precisely, beware off-by-one

图3：菠菜力量——精确收集 7 瓶药水（不多不少），再进入战斗循环

这一关的核心是精确控制收集数量。算法思路是标准计数循环：potionCount = 0 起步，while potionCount < 7 判断，找到药水后移动过去并 potionCount += 1。收满 7 瓶、条件变假后，再用一个 while True 战斗循环去打食人魔。

关键抉择：这一关最考验人的是那个不等号——必须用 < 7 而非 <= 7。前者精确收 7 瓶，后者会收 8 瓶导致英雄"喝药过量生病"而失败。同时注意 potionCount += 1 要放在 if item 内部——只有真正捡到药水才计数，否则空转几轮却虚增计数，同样会数错。"计数放对位置 + 不等号选对方向"，是精确计数循环的两大命门。

2.5 常见错误

Common Mistakes

2.5.1 新手最容易踩的坑（Pitfalls for Beginners）

2.5.1.1 练习 while 循环时的典型问题 Typical issues when practicing loops

图4：差一错误、计数位置错、混淆 = 与 ==，是本单元最常见的失误
易错点清单：
  • 差一错误——把 < 7 写成 <= 7，导致多收一个；这是本单元头号陷阱。
  • 计数器位置错——把 potionCount += 1 放到了 if item 外面，没捡到也计数，数量对不上。
  • 混淆 = 与 ==——相等条件里误用赋值号 =，程序报错。
  • 前一个循环停不下来——多循环程序里，若第一个循环是死循环，后面的循环和动作永远执行不到。
  • 把单次动作写进了循环——建诱饵、撤退这类只需做一次的动作误放进循环体，被反复触发。
  • 条件类型选错——该用数值比较的地方用了相等判断（或反之），循环无法在正确时机停止。
  • 忘记初始化计数器——没写 potionCount = 0 就直接在循环里用它，导致报错。

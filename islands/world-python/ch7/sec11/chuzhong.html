11.1 字典温故知新

Revisiting Dictionaries

在安息云峰的上一站，你第一次认识了字典（dictionary）——用键值对存取数据、手写坐标字典 {"x": 20, "y": 35} 指挥英雄移动。本单元你将拿到一件威力大增的新装备——首领之星，学会召唤和指挥一支属于自己的军队。而指挥军队的每一道命令，背后都离不开字典。这一单元的主题就是：在真实的战场上把字典用熟、用活。

本单元主线：当你命令一名士兵移动到某处时，要传给它一个坐标字典（{"x": 50, "y": 40}）；当你把士兵编成队伍逐个下令时，要用数组遍历；当你决定召唤还是攻击时，要用条件判断。字典、数组、循环、条件——之前学的所有工具，都会在指挥军队时同时上阵。这正是"练习"二字的分量。

11.1.1 字典的复习（A Quick Recap）

11.1.1.1 键值对、花括号、取值 Key-value pairs at a glance

先花一分钟温习字典的样子：用花括号 { } 包裹，键值之间用冒号 :，多对之间用逗号 ,。一个位置字典就是 {"x": 50, "y": 40}，键 "x" 存横坐标，键 "y" 存纵坐标。

# 一个坐标字典，本单元处处要用它
target = {"x": 50, "y": 40}
hero.move(target)   # 把整个字典作为一个参数传进去

11.1.2 字典无处不在（Dictionaries Everywhere）

11.1.2.1 命令的"目的地"就是字典 The destination is a dictionary

本单元你会看到，字典不只是给英雄自己用的 move——当你指挥士兵时，告诉他"去哪里"用的也是坐标字典，例如 command(soldier, "move", {"x": 50, "y": 40})。可以说，凡是涉及"某个位置"的地方，字典都在幕后默默工作。把字典练熟，指挥军队才能得心应手。

11.2 召唤军队

Summoning an Army

11.2.1 costOf 与 summon（Cost and Summon）

11.2.1.1 先问价，再购买 Check the price, then buy

有了首领之星，你可以召唤（summon）盟友。首领之星 I 能召唤"soldier"（士兵）。但召唤要花钱，所以召唤前要先用 hero.costOf("soldier") 查一个士兵值多少金币，再和自己现有的 hero.gold 比较，钱够了才召唤。

11.2.2 用金钱做循环条件（Gold as a Condition）

11.2.2.1 有钱就一直招，招到没钱为止 Summon while you can afford it

"安息之云指挥官"里用了一个巧妙的写法：把"钱是否够"直接当作 while 循环的条件。while hero.gold > hero.costOf("soldier"): 意思是"只要金币还够买一个士兵，就继续召唤"，每召唤一个金币就减少，直到不够为止自动停下——一次性把手头的钱换成尽可能多的士兵。

# 只要钱够买一个士兵，就一直召唤
while hero.gold > hero.costOf("soldier"):
    hero.summon("soldier")   # 每召唤一个，gold 就减少
为什么条件会自动变假？因为每次 summon 都会扣掉召唤费用，hero.gold 越来越少。当剩下的钱不够再买一个时，gold > costOf(...) 变假，循环自然结束。这和第一单元"确保条件迟早变假、避免死循环"是同一个道理——只不过这次让条件变假的不是计数器，而是花掉的金币。

11.3 指挥军队

Commanding Your Troops

11.3.1 command 的三参数（Three Arguments）

11.3.1.1 命令谁、做什么、对谁/去哪 Who, what, and where/whom

指挥盟友用 command 方法，它是本单元的绝对主角。command 通常接收三个参数：第一个是被命令的盟友（哪名士兵），第二个是命令的动作（字符串，如 "move" 或 "attack"），第三个是动作的目标（去哪个坐标，或攻击哪个敌人）。

🎖️ command 参数速记
①谁：一个盟友对象，如 soldier
②什么动作：字符串命令，如 "move"、"attack"
③目标：移动时传坐标字典，攻击时传敌人对象
三者顺序不能乱——先说命令谁，再说做什么，最后说目标。

11.3.2 遍历盟友数组下令（Command Every Soldier）

11.3.2.1 用循环给"每一个"士兵下令 One command reaches only one soldier

一句 command 只能指挥一名士兵。要指挥整支军队，就得把 command 放进 while 循环，配合数组遍历——先用 hero.findFriends() 拿到所有盟友组成的数组，再用索引逐个取出、逐个下令。关卡特别提醒："你还需要把 command 代码放进一个 while 循环内，这样你就可以命令所有的士兵，而不仅限一个。"

soldiers = hero.findFriends()   # 拿到盟友数组
soldierIndex = 0
while soldierIndex < len(soldiers):
    soldier = soldiers[soldierIndex]   # 取出这一名士兵
    hero.command(soldier, "move", {"x": 50, "y": 40})
    soldierIndex += 1                # 索引前进，指向下一名
这就是数组遍历的实战：这段代码正是第七、八单元"遍历数组三件套"的翻版——索引从 0 开始、while soldierIndex < len(soldiers) 判断、soldierIndex += 1 前进。只不过这次循环体内做的不是求和或比较，而是给取出的每名士兵下达命令。同一套骨架，换了新用途。

11.3.3 move 与 attack 命令（Move and Attack）

11.3.3.1 目标的类型随命令而变 The target type depends on the order

要留意第三个参数的类型会随命令变化：命令 "move" 时，第三个参数是坐标字典（{"x": 50, "y": 40}，去哪里）；命令 "attack" 时，第三个参数是敌人对象（enemy，打谁）。搞清"移动给地点、攻击给对象"这条规则，就不会把参数传错。

命令移动 —— 传坐标字典
hero.command(soldier,
    "move", {"x": 50, "y": 40})
# 第三参数：去哪（字典）
命令攻击 —— 传敌人对象
hero.command(soldier,
    "attack", enemy)
# 第三参数：打谁（对象）

11.4 指挥官的完整节拍

The Commander's Rhythm

11.4.1 召唤-指挥-行动（Summon, Command, Act）

11.4.1.1 一名合格指挥官的循环 The loop a commander repeats

把召唤和指挥合起来，就是一名指挥官在战场上不断重复的节拍：攒钱 → 召唤 → 集结/攻击。"佣兵山"就把这套节拍装进一个 while True 大循环——每一轮都去捡硬币攒钱、有钱就召唤新兵、发现敌人就命令全军攻击。这与前面单元讲的 AI"感知→决策→行动"循环一脉相承。

关卡 · 安息之云指挥官

🎖️ 安息之云指挥官 —— 召唤并集结部队

图2：安息之云指挥官——先把金币换成一队士兵，命令他们集结，英雄再前去会合

策略：召唤 → 遍历下令 → 英雄会合

这是首领之星的入门关，任务很清晰：把手头的钱变成一支队伍，把队伍带到基地。策略分三步——先用"有钱就召唤"的循环把金币全换成士兵；再遍历士兵数组，逐个命令他们 "move" 到集结坐标；最后让英雄自己也移动过去与大家会合。

思路拆解

算法思路是：第一步 while hero.gold > hero.costOf("soldier"): 反复 summon("soldier")，把钱花光换成兵；第二步用 findFriends() 取得士兵数组，配合索引遍历，对每个士兵 command(soldier, "move", {"x": 50, "y": 40})；第三步用 while hero.distanceTo(target): 让英雄一路 move 到自己的目标点。关键在于——命令必须放进遍历循环，才能让每名士兵都收到指令。

# 关键片段：遍历士兵数组，逐个命令移动
while soldierIndex < len(soldiers):
    soldier = soldiers[soldierIndex]
    hero.command(soldier, "move", {"x": 50, "y": 40})
    soldierIndex += 1
先召唤再 findFriends：顺序很重要——要先把士兵全召唤出来，findFriends() 才能把他们都收进数组。如果先 findFriends 再召唤，后召唤的士兵就没被数进去，命令时会漏掉他们。
别忘索引自增：遍历士兵时若漏了 soldierIndex += 1，会卡在第一名士兵上死循环，其余士兵永远收不到命令，英雄也走不到会合点。
关卡 · 佣兵山

⚔️ 佣兵山 —— 边攒钱扩军边指挥作战

图3：佣兵山——在 while True 循环里循环往复：捡币、扩军、命令士兵迎击兽人

策略：一个大循环同时兼顾三件事

佣兵山是召唤指挥的综合练习：一边要捡硬币攒钱、一边要不断扩军、一边还要指挥士兵抵挡兽人的猛攻。策略是把这三件事全塞进一个 while True 永久循环，每一轮都依次处理——移动捡币、钱够就召唤、发现敌人就命令全军攻击。

思路拆解

算法思路是每轮做三个"如果"：其一，coin = findNearest(findItems())，若有硬币就 move(coin.pos) 走过去（用 move 而非 moveXY，好让后续命令不被阻塞）；其二，if hero.gold > hero.costOf("soldier"): 就 summon("soldier") 扩军；其三，enemy = findNearest(findEnemies())，若有敌人就遍历 findFriends() 得到的士兵数组，逐个 command(soldier, "attack", enemy)。三件事在同一轮循环里协同推进。

# 关键片段：发现敌人就命令全军攻击
enemy = hero.findNearest(hero.findEnemies())
if enemy:
    soldiers = hero.findFriends()
    soldierIndex = 0
    while soldierIndex < len(soldiers):
        soldier = soldiers[soldierIndex]
        soldierIndex += 1
        hero.command(soldier, "attack", enemy)   # 攻击目标是敌人对象
为什么用 move 而不是 moveXY？关卡注释明确提示"使用 move 而不是 moveXY，以便于不断发出命令"。因为 moveXY 会阻塞程序、卡在走路上，士兵就得不到及时指挥；move 走一步就返回，让英雄能在移动的同时持续召唤和下令。这正是上一单元 move 非阻塞特性的延续应用。
每轮重新 findFriends：因为军队在不断扩大，士兵数组要在循环内每轮重新 findFriends() 获取，才能把新召唤的士兵也纳入指挥。若在循环外只取一次，新兵就会变成"没人指挥"的散兵。

11.6 常见错误

Common Mistakes

11.6.1 新手最容易踩的坑（Pitfalls for Beginners）

11.6.1.1 召唤与指挥的典型问题 Typical issues with summon and command

图4：命令没进循环、参数传错、忘记重新 findFriends，是本单元最常见的失误
易错点清单：
  • command 只写一句——没放进循环，结果只有第一名士兵收到命令，其余全站着不动。
  • 攻击时传错目标——"attack" 的第三参数要传敌人对象，不是坐标字典；移动才传坐标字典。
  • 坐标字典写错——把 {"x": 50, "y": 40} 写成 (50, 40) 或漏了花括号、引号。
  • 先 findFriends 再召唤——顺序反了，后召唤的士兵没进数组，命令时被漏掉。
  • 循环外只 findFriends 一次——军队扩大后新兵得不到指挥，要在循环内每轮重新获取。
  • 忘记索引自增——漏掉 soldierIndex += 1，在第一名士兵处死循环。
  • 召唤条件写反——想"有钱就招"却写成 while hero.gold < hero.costOf(...)，钱够时反而不招。

12.1 从 while 到 for

From While to For

在上一单元，你学会了用 while 循环配合索引三件套来遍历盟友数组、逐个下令。那套写法很好用，但每次都要手写"设索引、判条件、自增索引"三行仪式，稍不留神漏了 soldierIndex += 1 就会死循环。本单元你将认识一位更简洁的老朋友——for 循环（for loop）。关卡"木材守卫"的提示说得很直白："一个 for 循环类似于一个 while 循环。有更多的准备工作，但它可以用来完成同样的事情。"学会 for 循环，你指挥千军万马时的代码会变得又短又稳。

本单元主线：for 循环专门用来"把一件事对一批对象各做一遍"。指挥每一名士兵、召唤固定数量的部队、让士兵和守卫点一一配对——这些"重复固定次数"或"逐个处理数组"的场景，正是 for 循环大显身手的地方。这一单元你要把 for 循环练成指挥军队的默认武器。

12.1.1 for 循环的由来（Why For Loops Exist）

12.1.1.1 while 遍历的"三件套"回顾 Recalling the while-loop ritual

回忆一下上一单元用 while 遍历盟友数组的写法：先设一个索引 soldierIndex = 0，再用 while soldierIndex < len(soldiers) 判断，循环体里取出 soldiers[soldierIndex]，最后别忘 soldierIndex += 1。四个步骤缺一不可，尤其是最后那句自增，一旦漏掉就会卡在第一名士兵上死循环。

# while 遍历：四步都要自己写
soldiers = hero.findFriends()
soldierIndex = 0                       # ① 设索引
while soldierIndex < len(soldiers):       # ② 判条件
    soldier = soldiers[soldierIndex]     # ③ 取元素
    hero.command(soldier, "move", pos)
    soldierIndex += 1                    # ④ 自增（最易漏）

12.1.2 for 与 while 对比（For vs. While）

12.1.2.1 同样的事，for 更省心 Same job, less bookkeeping

for 循环把"设索引、判条件、自增"这些琐事全部自动化了。你只需说清"对这个数组里的每个元素"，它就会自动从头到尾走一遍，每轮把当前元素交到你手里。下面把同一件事——遍历盟友数组——用两种循环写出来，一眼就能看出 for 的简洁。

while 写法（要管索引）
friends = hero.findFriends()
i = 0
while i < len(friends):
    friend = friends[i]
    # ...处理 friend...
    i += 1
for 写法（不用管索引）
for friend in hero.findFriends():
    # ...处理 friend...

    # 索引、自增全部省掉
什么时候用 for，什么时候用 while？一条经验法则：当你事先知道"要重复几次"或"要逐个处理一个数组/序列"时，用 for 最合适；当你不知道要循环多少次、只知道"满足某条件就一直做"（如"有钱就一直召唤"、游戏主循环 while True）时，用 while 更自然。本单元里，逐个指挥士兵用 for，而外层"永远运转"的游戏节拍仍然用 while True。

12.2 for 循环解剖

Anatomy of a For Loop

12.2.1 for X in Y 结构（The for X in Y Form）

12.2.1.1 两个部分：变量与序列 Two parts: the variable and the sequence

关卡注释精确地概括了 for 循环的骨架："for 循环有两个部分：for X in Y。Y 是需要遍历的数组，循环对 Y 中的每个元素都会执行一次，而 X 会被设置成当前循环的元素。"换句话说，Y 是被处理的"一批东西"，X 是每一轮从这批东西里取出来的"当前这一个"。

🔁 for 循环执行节奏
第 1 轮：X = 数组第 0 个元素 → 执行循环体
第 2 轮：X = 数组第 1 个元素 → 执行循环体
…… 一直到最后一个元素
结束：数组走完，循环自动停止——不用你操心索引，也不会死循环。

12.2.2 遍历数组（Iterating an Array）

12.2.2.1 直接把数组交给 for Feed the array straight to for

for 循环最常见的用法，就是直接遍历一个数组。比如遍历所有盟友、遍历所有敌人、遍历所有物品。你不需要先取长度、也不需要索引，直接写 for 元素 in 数组: 即可。下面这段来自"木材守卫"的片段，就用 for 遍历了 findFriends() 返回的盟友数组。

# 遍历每一个盟友，只让士兵行动
for friend in hero.findFriends():
    if friend.type == "soldier":
        enemy = friend.findNearestEnemy()
        if enemy:
            hero.command(friend, "attack", enemy)
for 里的 X 就是元素本身：注意这里 friend 每一轮直接就是一个盟友对象，可以立刻用 friend.type、friend.findNearestEnemy()。这和 while 写法里要先 friend = friends[i] 手动取出相比，省了一步。for 已经替你"取好"了。

12.2.3 range() 计数（Counting with range）

12.2.3.1 想重复固定次数就用 range Repeat a fixed number of times

如果你不是要遍历现成的数组，而是想"把一件事做 N 次"，就把 for 和 range() 搭配起来。range(4) 会生成 0, 1, 2, 3 这样一串数字（从 0 开始、不含 4，共 4 个），for 循环就会执行 4 次。"动物园管理员"里用 for i in range(4): hero.summon("soldier") 恰好召唤了 4 个士兵。

# 召唤正好 4 个士兵
for i in range(4):
    hero.summon("soldier")   # 循环体执行 4 次
range(4) 不含 4：初学者最容易搞混的一点——range(4) 得到的是 0、1、2、3，共 4 个数，但最大只到 3，不包含 4。这和数组索引从 0 开始、最大到"长度减一"是完全一致的规则。所以 range(len(friends)) 正好能覆盖一个数组的所有合法索引。

12.2.3.2 用 range(len(数组)) 拿到"下标" range(len(...)) gives you the indexes

有时你不只想遍历数组，还想知道"当前是第几个"——因为你要用这个序号去另一个数组里取对应的东西。这时可以写 for j in range(len(friends)):，此时 j 依次是 0、1、2……正好是每个元素的下标。"动物园管理员"和"壮烈牺牲"两关都用了这招，让士兵和守卫点一一配对，我们在 12.3.2 详细讲。

12.3 for 指挥军队

Commanding Troops with For

12.3.1 遍历盟友下令（Command Every Friend）

12.3.1.1 for + command 的黄金组合 The for + command combo

上一单元的核心是 command(谁, 动作, 目标) 三参数。本单元把它和 for 循环合起来，就得到指挥全军的最简写法：for friend in hero.findFriends(): 里对每个 friend 调用一次 command。移动时第三参数传坐标字典，攻击时第三参数传敌人对象——这条规则和上一单元完全一致。

for friend in hero.findFriends():
    if friend.type == "soldier":
        enemy = friend.findNearestEnemy()
        if enemy:
            hero.command(friend, "attack", enemy)   # 有敌人：攻击
        else:
            rightPos = {"x": 83, "y": 45}
            hero.command(friend, "move", rightPos)   # 没敌人：撤向右边
让每名士兵"自己找最近的敌人"：注意这里用的是 friend.findNearestEnemy()，也就是让每个士兵各自寻找离"它自己"最近的敌人，而不是离英雄最近的。这样分散在各处的士兵能各自迎击身边的威胁，比全军扑向同一个目标更聪明。

12.3.2 索引配对两数组（Pairing Two Arrays by Index）

12.3.2.1 用同一个下标同时取两边 One index, two arrays

这是本单元最精彩的技巧：当你有两个平行数组——一个装士兵、一个装守卫点——想让"第 j 名士兵去第 j 个点"时，就用 for j in range(len(friends)): 拿到共用的下标 j，再用它同时索引两个数组：friend = friends[j] 和 point = points[j]。这样士兵和位置就一一配对上了。

# 让第 j 名士兵去第 j 个守卫点
friends = hero.findFriends()
for j in range(len(friends)):
    friend = friends[j]       # 用 j 取士兵
    point = points[j]        # 用同一个 j 取位置
    hero.command(friend, "move", point)
为什么这里必须用 range，而不是 for friend in friends？因为你需要那个序号 j 去 points 里取对应的点。如果直接写 for friend in friends，你只拿到了士兵，却没有序号，就无法知道该配 points 里的哪一个。凡是"要同时按位置访问两个数组"的场景，就用 for j in range(len(...))。

关卡 · 木材守卫

🪵 木材守卫 —— 用 for 指挥每个士兵

图2：木材守卫——英雄退后捡币攒钱，用 for 循环指挥每名士兵各自迎敌

策略：英雄躲后方，士兵冲前线

这是 for 循环的入门关。核心策略是分工：英雄自己不去和兽人硬拼（关卡明确警告"如果你试着亲自和兽人作战，你可能会吸引兽人刺客的注意"），而是退到后方专心捡硬币攒钱、召唤士兵；真正的战斗交给召唤出来的士兵。所有指挥动作都放在一个 while True 大循环里持续进行。

思路拆解

算法思路是每轮循环做三件事：其一，coin = findNearest(findItems())，有硬币就 move(coin.pos) 过去捡（英雄借此后撤）；其二，if hero.gold >= hero.costOf("soldier"): 就 summon("soldier") 扩军；其三，也是本关重点——用 for friend in hero.findFriends() 遍历所有盟友，只对 friend.type == "soldier" 的下令，让每名士兵用 findNearestEnemy() 找到身边的敌人，有敌人就 command(friend, "attack", enemy)，没敌人就 command(friend, "move", rightPos) 推进到地图右侧。

# 关键片段：for 遍历盟友，各自迎敌或推进
for friend in hero.findFriends():
    if friend.type == "soldier":
        enemy = friend.findNearestEnemy()
        if enemy:
            hero.command(friend, "attack", enemy)
        else:
            hero.command(friend, "move", {"x": 83, "y": 45})
先判断类型再下令：findFriends() 返回的可能不只有士兵。先用 if friend.type == "soldier" 筛一遍，避免对不能作战的盟友发出攻击命令而报错或浪费。
for 让"死循环隐患"消失：用 for 遍历盟友，就不必再写 index += 1，自然不会因为漏掉自增而卡死。这正是本关想让你体会的 for 相对 while 的最大好处。

🦁 动物园管理员 —— 士兵与守卫点配对

图3：动物园管理员——把 4 名士兵分别派到 4 个笼子旁，各自就地防守

策略：定点防守，四点四兵

本关要保护 4 个关着雪人的笼子。策略是先把 4 个笼子的坐标存进一个数组 points，再召唤 4 名士兵，让第 j 名士兵驻守第 j 个笼子。关卡贴心提示："收集硬币时，可以在收集 80 金钱后停下，因为每个士兵的费用为 20"——80 ÷ 20 正好 4 个兵，与 4 个点对应。

思路拆解

算法分三段。第一段攒钱：while hero.gold < 80: 反复捡币，够 80 就停。第二段建军：for i in range(4): hero.summon("soldier") 精确召唤 4 个。第三段是本关灵魂——在 while True 里，用 for j in range(len(friends)): 拿到共用下标 j，同时取出 friend = friends[j] 和 point = points[j]，实现士兵与守卫点一一配对；再判断"附近是否真有兽人靠近"，是就 attack，否则 move 回自己的守卫点。

# 关键片段：同下标配对士兵与守卫点，就地防守
for j in range(len(friends)):
    point = points[j]
    friend = friends[j]
    enemy = friend.findNearestEnemy()
    if enemy and enemy.team == "ogres" and friend.distanceTo(enemy) < 5:
        hero.command(friend, "attack", enemy)
    else:
        hero.command(friend, "move", point)   # 回到自己的守卫点
"距离小于 5 才出击"的意义：条件 friend.distanceTo(enemy) < 5 让士兵只在敌人逼近时才离开岗位迎击，敌人一走远（或没敌人）就 move 回守卫点。这样每个笼子始终有兵把守，不会被士兵盲目追击而露出空档。这正是"定点防守"策略的关键。
数组下标不能越界：本关 points 有 4 个元素，士兵也召唤 4 个，两者数量一致，points[j] 才不会越界。如果士兵数量超过守卫点数量，points[j] 就会因为下标超出范围而报错——这也是为什么要精确召唤 4 个，不多不少。
关卡 · 壮烈牺牲

🎯 壮烈牺牲 —— 士兵沿路布点当诱饵

图4：壮烈牺牲——4 名士兵作诱饵，沿预设路径逐点移动，为英雄开路

策略：士兵当诱饵，逐点吸引火力

本关的士兵是"消耗品诱饵"——他们沿一条通往兽人营地的路径，被分别派往 4 个关键点，用来吸引和牵制敌人。策略与"动物园管理员"一脉相承，都是士兵与坐标点按下标配对，只不过这次不再是原地防守，而是一次性把每名士兵派往路径上的不同位置。

思路拆解

算法思路是：先 while hero.gold < 80: 攒够 80 金；再 for i in range(4): hero.summon("soldier") 召唤 4 名诱饵；接着定义含 4 个坐标的 points 数组和 friends = hero.findFriends()；最后用 for j in range(len(friends)): 遍历下标，把 friends[j] 和 points[j] 配对，逐个 command(friend, "move", point)，让每名士兵各奔其位。关卡注释点明了这一手法："使用 range 来得到可供遍历的数组。让各盟友士兵和各地点位置配对，然后命令他们移动。"

# 关键片段：range 遍历下标，士兵与路径点配对移动
friends = hero.findFriends()
for j in range(len(friends)):
    point = points[j]
    friend = friends[j]
    hero.command(friend, "move", point)
与动物园管理员的异同：两关都用 for j in range(len(friends)) 做"下标配对"，这是本单元最该练熟的模式。区别在于：动物园管理员放在 while True 里反复判断攻击/回防，是"持续防守"；壮烈牺牲只需把士兵一次性派到位，是"一次布点"。同一套配对骨架，服务于不同战术。
诱饵战术的算法之美：把士兵和一串预设坐标配对，本质上是用一个 for 循环完成了"批量分配任务"。当你以后遇到"N 个执行者对应 N 个任务/位置"的问题时，都可以套用这个"range 下标 + 双数组配对"的思路。

12.5 常见错误

Common Mistakes

12.5.1 新手最容易踩的坑（Pitfalls for Beginners）

12.5.1.1 for 循环的典型问题 Typical issues with for loops

图5：range 边界搞错、下标越界、该用 range 却用了 for-in，是本单元最常见的失误
易错点清单：
  • 误以为 range(4) 含 4——它其实是 0、1、2、3，共 4 个数，最大只到 3，别当成 1 到 4。
  • 该用下标却用了 for-in——需要同时索引两个数组时，必须写 for j in range(len(...)) 拿到 j，而不是 for friend in friends。
  • 两个数组数量不一致——士兵数比 points 多，points[j] 会下标越界报错；要让数量对齐（如恰好召唤 4 个）。
  • 忘了冒号或缩进——for ... : 行末要有冒号，循环体要缩进，否则语法错误。
  • 还在 for 里手写 index += 1——for 已自动前进，再自增反而打乱下标。
  • 攻击传错目标——"attack" 第三参数是敌人对象，"move" 第三参数才是坐标字典，别混。
  • 没先判断类型——对 findFriends() 里的非士兵盟友直接下攻击令，可能报错，应先 if friend.type == "soldier"。
  • 英雄亲自上阵——木材守卫里让英雄硬拼会招来刺客，应退后捡币、把战斗交给士兵。

8.1 数组迭代复习

Reviewing Array Iteration

沙漠深处的战斗越来越讲究策略：有时要先揪出最强的首领，有时要优先清掉最危险的弱兵。上一单元你学会了用"打擂台"算法在数组里找出最大或最小的元素。本单元在此基础上更进一步——学会把搜索极值的逻辑封装成一个函数，让代码更清晰、更可复用。这是从"写得出来"迈向"写得漂亮"的关键一步。

本单元两条主线：一是函数封装——把一段有明确输入输出的逻辑打包、起名、随时调用；二是搜索时机——同样的搜索，是"只做一次"还是"反复做"，取决于环境是否会变化。理解这两点，你的代码就会既优雅又健壮。AI 每一帧都在"感知环境→评估候选→选出最优→执行"，本单元的持续搜索正是这个循环的雏形。

8.1.1 遍历数组的地基（The Foundation）

8.1.1.1 标准的三部件结构 Index, condition, increment

在深入本单元之前，先快速回顾遍历数组的标准结构——它是后面一切的地基。三个不可或缺的部件是：索引变量记录进度、循环条件判断是否走完、索引自增让指针前进。

enemies = hero.findEnemies()   # 拿到敌人数组
enemyIndex = 0                   # 索引从 0 开始
while enemyIndex < len(enemies):   # 没走完就继续
    enemy = enemies[enemyIndex]     # 取出当前敌人
    # ... 处理这个 enemy ...
    enemyIndex += 1               # 索引前进（别忘）
三件套缺一不可：索引变量（记录进度）、循环条件（enemyIndex < len(enemies)，用 < 不是 <=）、索引自增（enemyIndex += 1）。漏掉自增就会在第一个敌人处死循环。

8.2 用函数封装搜索逻辑

Wrapping Search in a Function

8.2.1 函数的三要素（The Three Parts）

8.2.1.1 函数是一台"输入→加工→输出"的机器 A function is a machine

当一段逻辑有明确的"输入"和"输出"时，把它写成函数（function）是最好的选择。"从一群敌人里找出最强的那个"——输入是敌人数组，输出是一个敌人，正好适合封装成函数。一个函数由三部分构成：def 关键字加函数名和参数（定义入口）、函数体（具体做什么）、return 语句（把结果交出去）。

def findStrongestEnemy(enemies):   # 定义：名字 + 参数
    # ... 函数体：在这里做搜索 ...
    return strongest                # 把结果返回给调用者

8.2.2 定义之后要调用（Define then Call）

8.2.2.1 光定义不会运行，必须调用并接住返回值 A definition does nothing until called

光定义函数，它不会自己运行；必须在主程序里调用它，并接住返回值。调用时把实际的敌人数组传进去，函数就会把找到的首领交回来。

enemies = hero.findEnemies()
leader = findStrongestEnemy(enemies)   # 调用函数，接住返回的敌人
if leader:                          # 确认真的找到了才行动
    hero.attack(leader)

8.2.3 封装的三大好处（Why Wrap It）

8.2.3.1 可复用、易读、易改 Reusable, readable, maintainable

封装成函数的三大好处：可复用（哪里要找最强敌人都能调用这一个函数）、易读（主程序一句 findStrongestEnemy(enemies) 就一目了然，不必展开细节）、易改（想改搜索规则只需改函数内部，所有调用处不用动一个字）。

8.3 打擂台算法深化

The Champion Pattern, Deepened

8.3.1 最强与最弱（Strongest vs Weakest）

8.3.1.1 骨架相同，只差初始值与比较符号 Same skeleton, two swaps

本单元两个关卡分别要找血量最高（最强首领）和血量最低（最危险弱兵）的敌人。它们用的都是打擂台，唯一的差别在初始值和比较符号。

找最强（脆弱的士气：最大 health）
strongest = None
strongestHealth = 0
# ... 遍历中 ...
if enemy.health > strongestHealth:
    strongest = enemy
    strongestHealth = enemy.health
找最弱（Maxer 反击：最小 health）
weakest = None
leastHealth = 99999
# ... 遍历中 ...
if enemy.health < leastHealth:
    weakest = enemy
    leastHealth = enemy.health

擂主初始值0（比任何血量都小）99999（比任何血量都大）
比较符号enemy.health > ...enemy.health < ...
比较依据enemy.healthenemy.health
目标血最多的兽人首领血最少的危险弱兵

8.3.2 初始值不能填反（Don't Flip the Seed）

8.3.2.1 找最大填极小值，找最小填极大值 The seed must lose to any real value

初始值绝不能填反：找最大若填 99999，会让任何敌人都打不过初始擂主，结果永远是 None；找最小若填 0，同样会让擂主永不更新。找最大填极小值，找最小填极大值——这样第一个真实元素就一定能成为首任擂主。

8.3.3 擂主为何初始设 None（Why None）

8.3.3.1 为了给"空数组"留一个信号 None signals "nothing found"

把 strongest/weakest 初始设为 None，是为了应对空数组的情况。如果附近一个敌人都没有，循环一次都不执行，返回的 None 就是"没找到"的信号。主程序用 if leader: 或 if weakest: 一判断，就能安全地跳过行动，不会因为 None 没有属性而报错。

8.4 一次搜索 vs 持续搜索

Search Once or Search Repeatedly

8.4.1 搜索时机的选择（When to Search）

8.4.1.1 环境是否变化，决定搜索做几次 A changing world needs repeated search

两个关卡还展示了一个更深的区别：搜索应该做几次？答案取决于环境是否变化。

脆弱的士气：搜索一次就够

首领在开场就确定了，我们只需找出他、锁定他。搜索逻辑封装在函数里，主程序调用一次拿到首领即可。

Maxer 反击：需要反复搜索

敌人会不断被击败、血量不断变化，"最弱的那个"随时在变。所以要把搜索放进一个永久大循环，每一轮都重新 findEnemies() 再重新打擂台。

while True:                        # 外层：永不停止的战斗循环
    weakest = None
    leastHealth = 99999
    enemies = hero.findEnemies()     # 每轮重新感知（关键！）
    enemyIndex = 0
    while enemyIndex < len(enemies):  # 内层：本轮的打擂台搜索
        # ... 比较并更新 weakest ...
        enemyIndex += 1
    if weakest:
        hero.attack(weakest)         # 打击本轮选出的目标
为什么每轮都要重新 findEnemies()？如果只在循环外获取一次敌人数组，数组里的敌人被打死后仍留在列表中，程序会对着"幽灵"发呆。把感知放进循环内，才能始终基于最新战况做决策——这正是 AI"实时感知"的核心。

8.4.2 感知-决策-行动循环（Sense-Decide-Act）

8.4.2.1 一种典型的嵌套循环 A classic nested loop

Maxer 反击的骨架是一个 while True 永真循环，每一轮里都完成"重新感知→重新搜索→执行攻击"的完整流程。这是一种典型的嵌套循环（nested loop），也是几乎所有 AI 行为逻辑的基本节拍。

关卡 · 脆弱的士气

🏹 脆弱的士气 —— 函数找最强首领

图2：脆弱的士气——找出血量最高的兽人首领，一击瓦解敌军士气

策略：把"找最强"写成函数

你只有一名弓箭手，火力有限。但敌军有一个规律——当指挥官倒下时，敌人就会撤退。所以不必硬拼全部，只要先干掉兽人首领就能瓦解敌军士气。首领的特征是：血量最高的那个敌人。策略是写一个函数 findStrongestEnemy(enemies)，用打擂台法在敌人数组里找出 health 最大的敌人并返回，主程序调用它拿到首领后集中火力。

思路拆解

算法思路是：定义函数、参数是敌人数组；函数内初始化擂主 strongest = None、strongestHealth = 0；用 while enemyIndex < len(enemies) 遍历，比较 enemy.health 与 strongestHealth，更大就更新擂主；循环结束后 return strongest 把首领交给主程序；主程序调用函数、用 if leader: 确认后再攻击。

# 关键片段：函数内打擂台找最大血量
if enemy.health > strongestHealth:
    strongest = enemy
    strongestHealth = enemy.health
# ... 遍历结束后 ...
return strongest
教学重点：这一关的重点不是"怎么找最大"，而是怎么把找最大写成一个函数。注意 return 必须放在 while 循环外面——要等全部比完才有资格宣布冠军；若写进循环内会导致才比一个就提前返回。
初始值别设错：strongestHealth 初始值要设 0。如果设成 99999，没有任何敌人的血量能超过它，函数会一直返回 None，首领永远找不到。

💪 疯狂 Maxer 反击 —— 循环找最弱目标

图3：疯狂 Maxer 反击——持续锁定血量最低的兽人，先除掉伤害最高的威胁

策略：在永真循环里持续找最弱

这里的兽人有个反常规律——越小的兽人越危险，伤害越高，而"小"体现在血量最低上。所以策略要反过来：优先集火消灭血量最少的敌人，先解除最大威胁。用一个 while True 永真循环持续作战，每一轮都重新 findEnemies()，再用打擂台法找出 health 最小的敌人并攻击它；敌人死了、血量变了，下一轮会自动重新选出新的"最弱者"。

思路拆解

算法思路是：外层 while True 开启永久战斗循环；每轮开头重置擂主 weakest = None、leastHealth = 99999；循环内重新 findEnemies() 保证基于最新战况；内层 while 遍历敌人，enemy.health < leastHealth 就更新擂主；内层结束后若 weakest 存在就 attack(weakest)；回到外层顶部进入下一轮感知与搜索。

# 关键片段：循环内打擂台找最小血量
if enemy.health < leastHealth:   # 注意是 <（找最小）
    weakest = enemy
    leastHealth = enemy.health
# ... 内层结束后 ...
if weakest:
    hero.attack(weakest)
对比脆弱的士气：脆弱的士气搜索只做一次（首领固定），Maxer 反击搜索每轮都做（最弱者随战局变化）。这正是"环境是否变化决定搜索时机"的活教材。
两个易错点：一是 leastHealth 找最小要设 99999（不是 0）；二是 findEnemies() 必须写在外层循环内部，否则数组不随战况更新，英雄会攻击已经不存在的敌人。

8.6 常见错误

Common Mistakes

8.6.1 新手最容易踩的坑（Pitfalls for Beginners）

8.6.1.1 函数化搜索的典型问题 Typical issues with functional search

图4：初始值填反、return 位置错误、感知没进循环，是本单元最常见的失误
易错点清单：
  • 函数总是返回 None——找最大却把初始值设成了 99999。找最大设 0，找最小设 99999。
  • 只比了一个就返回——return 误写在 while 循环内部。要把 return 移到循环外，等全部比完。
  • 找最弱却选到血最多的——比较符号用反了。找最小用 <，找最大用 >。
  • 英雄攻击"空气"/不存在的敌人——findEnemies() 写在外层循环外，数组不更新。要放进循环内每轮刷新。
  • 英雄卡住不动——忘记 enemyIndex += 1，内层死循环。确保每轮遍历索引都前进。
  • 报错找不到 health / pos 属性——数组为空、擂主仍是 None 却直接使用。用前先 if weakest: / if leader: 判断。
  • 调用函数没反应——只定义了函数，忘了在主程序调用。定义后必须调用并接住返回值。

4.2 while 循环回顾

Review: while Loops

4.2.1 条件式循环（Conditional Loops）

4.2.1.1 "条件为假时，循环结束" The loop ends when the condition is false

快速回忆核心要义：while 循环在每一圈开头检查条件，条件为真就再跑一圈，为假就退出。条件不必永远是 True——用一个迟早会变假的条件，就能精确控制循环次数。

while hero.gold < 30:   # 条件为真就继续，够 30 金就停
    item = hero.findNearestItem()
    if item:
        hero.moveXY(item.pos.x, item.pos.y)

4.2.2 计数器三部曲（The Counter Pattern）

4.2.2.1 初始化 → 判断 → 递增 Initialize, test, increment

"重复固定次数"的万能模板，你在"尘埃"关卡里就掌握了它。这个模式在本单元的遍历里将再次登场——只不过计数器换成了"索引"。

🔢 计数器三部曲
①初始化：循环前设起点，如 attacks = 0
②判断：用计数器作条件，如 while attacks < 10
③递增：循环体内 attacks += 1，逼近终止
三者缺一不可——少了③就是死循环。

4.2.3 死循环防范（Avoiding Infinite Loops）

4.2.3.1 让条件迟早变假 Make sure the condition eventually turns false

黄金法则再强调：循环体内必须有代码能让条件逐渐趋向"变假"——计数器要递增、变量要更新、金币要增加。银行突袭关卡也明确警告："别忘了每次循环里增加索引的值，不然会出现无限循环（infinite loop）的错误。"

4.3 数组回顾

Review: Arrays

4.3.1 索引与长度（Index and Length）

4.3.1.1 从 0 开始，len() 量长度 Zero-based indexing and len()

数组是有序的数据列表。用 array[n] 取索引为 n 的元素，索引从 0 开始；用 len(array) 得到元素个数。合法索引范围永远是 0 到 len-1，越界就会报错。

4.3.2 遍历三部曲（The Iteration Recipe）

4.3.2.1 索引=0 → 条件 <len() → 每轮 +1 Index 0, test with len(), increment

这是本单元的重头戏，也是"银行突袭"的基石。银行突袭关卡把遍历方法讲得非常标准："创建一个用作数组索引的变量，初始值应该为 0……然后把索引变量加上 1，读取下一个元素。while 的条件部分则是检查索引变量是否仍小于数组长度。"

enemyIndex = 0                       # ① 索引从 0 开始
while enemyIndex < len(enemies):   # ② 条件：索引 < 长度
    enemy = enemies[enemyIndex]     # 用索引取当前元素
    hero.attack(enemy)
    enemyIndex += 1                  # ③ 每轮 +1，游标前进
遍历本质就是计数器：对比一下就会发现——遍历三部曲和 while 计数器三部曲结构完全一样，只是把普通计数器换成了"索引变量"，并用 len() 当作终点。理解这一点，你就打通了循环与数组的任督二脉。

4.3.3 数组要刷新（Refresh Stale Arrays）

4.3.3.1 战况在变，数据也要更新 Re-fetch the array each round

物品会被收集、敌人会死亡或新增，因此 find 方法返回的数组可能过时。在反复执行的外层循环里，每轮都要重新调用 findEnemies()、findItems() 拿到最新数据。"银行突袭"里的 enemies = hero.findEnemies() 就写在外层 while True 的开头，正是为了每波兽人来袭时刷新名单。

4.4 核心技能：循环嵌套

Key Skill: Nested Loops

4.4.1 什么是嵌套循环（What Is a Nested Loop）

4.4.1.1 循环里面还有循环 A loop inside another loop

本单元真正的"新意"在于把循环套起来。银行突袭关卡点明："如果你需要对几组事物（敌人、朋友等等）重复那些动作，那你可以将代码放进另一个 while 循环里……之后你的英雄会一次次收集完所有的物品。" 这就是嵌套循环（nested loop）——一个循环放在另一个循环体内。

在"银行突袭"里，外层是一个 while True（永远守卫银行），内层则是两个遍历循环（一个打完所有敌人、一个捡完所有金币）。外层每转一圈，内层就会完整地跑完一整轮。

4.4.2 内外层的分工（Inner vs. Outer）

4.4.2.1 外层管"重复几轮"，内层管"一轮里逐个处理" Outer repeats rounds, inner processes each element

理解嵌套循环的钥匙是分清两层各自的职责。一个生动的比喻：外层循环像"一天又一天"，内层循环像"这一天里挨家挨户送信"。每过一天（外层一圈），邮差都要把当天所有的信件（内层遍历）送完。

执行次数永远（关卡不结束就一直转）= 当前数组的长度

4.4.3 索引必须各自独立（Each Loop Needs Its Own Index）

4.4.3.1 不同数组用不同的索引变量 Use a separate index for each array

这是嵌套遍历里最关键、也最容易出错的一点。银行突袭要先遍历 enemies、再遍历 coins，它们各自需要一个独立的索引变量——enemyIndex 和 coinIndex，绝不能共用一个。而且每次进入内层循环前，都要把对应的索引重新归零。

while True:
    enemies = hero.findEnemies()
    enemyIndex = 0                    # 敌人索引，进循环前归零
    while enemyIndex < len(enemies):
        hero.attack(enemies[enemyIndex])
        enemyIndex += 1

    coins = hero.findItems()
    coinIndex = 0                     # 金币索引，另起一个、也要归零
    while coinIndex < len(coins):
        coin = coins[coinIndex]
        hero.moveXY(coin.pos.x, coin.pos.y)
        coinIndex += 1
忘记归零的后果：如果外层循环转第二圈时，索引还停留在上一圈结束时的值（比如仍等于长度），内层循环的条件一开始就为假，会直接跳过、一个元素都不处理。所以每次进入内层遍历前，务必把索引重新设回 0。

4.5 实战关卡精讲

Level Strategy & Analysis

4.5.1 银行突袭（Bank Raid）

4.5.1.1 策略：外层守卫，内层双遍历 Strategy: guard outside, double-iterate inside

图1：银行突袭——一波波兽人来抢金，先遍历敌人全歼，再遍历金币全收

这是本单元的综合大关，把 while 循环、数组、遍历、嵌套四样本领熔于一炉。兽人会一波又一波地来抢黄金，你要守住银行、击退每一波并把散落的金币全部收回。

算法思路分三层：最外层用 while True 无限守卫；每一圈开头先 findEnemies() 刷新敌人数组，用一个 enemyIndex 遍历循环把这一波敌人逐个攻击直至清空；打完后再 findItems() 拿到金币数组，用另一个 coinIndex 遍历循环逐个移动收集。外层转一圈就完整处理一波"来袭 + 清扫"，然后循环回去等待下一波。

🏦 银行突袭 · 算法骨架
外层：while True —— 永远守卫
  ├ 刷新 enemies，enemyIndex = 0
  ├ 内层①：遍历 enemies，逐个 attack，enemyIndex += 1
  ├ 刷新 coins，coinIndex = 0
  └ 内层②：遍历 coins，逐个 moveXY，coinIndex += 1

三个关键领悟：其一，为什么要嵌套——单靠一层遍历只能处理"一波"，套上 while True 才能应对"一波又一波"；其二，两个索引各司其职，enemyIndex 和 coinIndex 独立计数、进内层前各自归零；其三，数组每轮刷新，敌人和金币的数组都在外层循环内重新获取，保证数据永远是最新的。掌握了这一关，你就真正学会了"用程序处理任意数量、不断变化的目标"。

先打后收的顺序也是策略：关卡把"攻击敌人"放在"收集金币"之前，是有讲究的——先清除威胁，再安心捡钱，避免收金币途中被兽人偷袭。顺序安排本身就是算法设计的一部分。

4.6 综合易错点

Common Mistakes (Combined)

4.6.1 循环 + 数组 + 嵌套的坑（Pitfalls）

4.6.1.1 综合运用时最容易翻车的地方 Where things go wrong when combined

图2：忘记递增索引、索引不归零、内外层索引混用，是综合关卡最常见的失误
综合易错点清单：
  • 忘记递增索引——写了 while enemyIndex < len(enemies) 却漏掉 enemyIndex += 1，索引卡在 0，直接死循环。
  • 进内层前索引不归零——外层第二圈时索引还是上一轮的旧值，导致内层被整个跳过，一个都不处理。
  • 内外层共用一个索引变量——两个遍历都用 i，彼此干扰，计数彻底混乱。
  • 忘记在外层刷新数组——只在循环外取一次 find，第二波敌人来了却看不见，操作过时数据。
  • 索引越界——条件写成 <= 而非 <，多走一格访问 array[len] 报错。
  • 读取前不检查空数组——某一波没有金币时，若逻辑不当直接访问 coins[0] 会崩溃（遍历本身用 len() 天然安全，但单独取首元素时要当心）。
  • 缩进错乱——把内层循环或善后代码放错层级，导致"打一个敌人就去捡一次金币"这类逻辑错乱。

3.1 数组（列表）基础

The Basics of Arrays (Lists)

3.1.1 什么是数组（What Is an Array）

3.1.1.1 "数组是一个事物的列表" An array is a list of things

欢迎来到流金沙漠的新篇章！之前你面对的往往是单独一个敌人、一件物品。但真实的战场上，往往同时出现一群宝石、一队兽人、一批农民。这时候我们需要一种能把"很多个东西装在一起"的工具——这就是数组（array），在 Python 里它有一个更亲切的名字叫列表（list）。

"Sarven 救世主"关卡一语点破本质："数组是一个事物的列表，是有序的数据列表。" 关键词是"有序"——数组里的每个东西都有自己固定的排队位置，第一个永远是第一个，第二个永远是第二个，绝不会乱。你可以把它想象成沙漠里的一支驼队：驼队里的每头骆驼都有确定的先后次序。

# 一个装着四个朋友名字的数组（列表）
friendNames = ['Joan', 'Ronan', 'Nikita', 'Augustus']

用方括号 [ ] 把若干元素括起来、用逗号隔开，就创建了一个数组。数组里可以装字符串（名字）、数字，也可以装游戏里的物品对象、敌人对象。

图1：数组就像一支有序的驼队——每个元素都有固定的排队位置

3.1.2 索引与方括号（Index and Square Brackets）

3.1.2.1 从 0 开始数，用 array[n] 取元素 Count from zero, access with array[n]

数组里每个元素都有一个编号，叫做索引（index）。这里有一条几乎所有初学者都会踩坑的黄金规则：索引从 0 开始数，而不是从 1！ 所以第一个元素的索引是 0，第二个是 1，第三个是 2，以此类推。

要取出数组里某个位置的元素，使用 array[n] 这样的写法，其中 n 就是你想要的元素的索引。这正是"团队合作"和"第二宝石"两关的核心操作。

items = hero.findItems()   # 得到一个物品数组
gem0 = items[0]            # 第一颗宝石（索引 0）
hero.say("Bruno " + gem0)   # 用变量引用它

hero.say("Matilda " + items[1])  # 也可以不用变量，直接用 items[1]
两种用法都对：你既可以把元素先存进变量再用（gem0 = items[0]），也可以不用额外变量、直接使用数组元素（items[1]）。存进变量的写法更清晰、便于反复引用；直接使用则更简洁。两种方式在"团队合作"关卡里都出现了。

3.1.3 越界的危险（Index Out of Range）

3.1.3.1 索引不能大于等于数组长度 Index must be smaller than the length

关卡特别提醒："如果你用大于或等于数组长度的索引读取元素，你会得到一个错误或 undefined（未定义的）值。" 换句话说，一个长度为 3 的数组，合法索引只有 0、1、2；如果你写 items[3]，就"越界"了——沙漠里根本没有那第四个位置。

越界即出错：数组长度为 N 时，合法索引范围是 0 到 N-1。访问 array[N] 或更大的索引，Python 会抛出 IndexError（列表索引越界）错误，程序当场崩溃。这也是为什么在读取元素之前，我们常常需要先检查数组长度——这正是下一节的主题。

3.2 返回数组的方法

Methods That Return Arrays

3.2.1 findItems / findEnemies / findFriends（The find-Methods）

3.2.1.1 一次找回"一群"目标 Find all visible targets at once

之前你熟悉的 findNearestItem()、findNearestEnemy() 每次只返回"最近的那一个"。本单元登场的一批新方法则更强大——它们一次返回所有能看见的目标，打包成一个数组：

方法返回内容典型用途
hero.findItems()所有可见物品组成的数组收集宝石、金币
hero.findEnemies()所有可见敌人组成的数组攻击敌军、点名中立单位
hero.findFriends()所有可见友军组成的数组指挥、增益队友

关卡概览指出："像 findItems、findEnemies 以及 findFriends 这些方法返回含有物品、敌人或者朋友的数组。" 拿到数组后，你就能用索引挑出其中任意一个，或者遍历它们全部。

中立单位的小陷阱："招募队伍"关卡里有个有趣的细节——想招募的中立农民会被 findEnemies() 检测到，而不是 findFriends()。因为在他们参军之前，系统并不把他们算作你的友军。这提醒我们：要根据关卡实际情况判断该用哪个 find 方法。

3.2.2 用变量接住数组（Storing an Array in a Variable）

3.2.2.1 让数组有个名字 Give the array a name

find 方法返回的数组，通常我们会立刻用一个变量接住它，给它起个有意义的名字，之后就能反复引用、用索引取元素、用 len() 量长度。

items = hero.findItems()      # 物品数组叫 items
enemies = hero.findEnemies()  # 敌人数组叫 enemies

3.2.3 数组会过时（Arrays Can Go Stale）

3.2.3.1 战况在变，数组也要及时刷新 Refresh the array every loop

这是本单元最容易被忽略、也最关键的一点。"招募队伍"关卡明确警告："物品会出现或被收集。单位会死亡或被召唤。因此，来自 findItems()、findEnemies() 和 findFriends() 等方法的数组可能包含旧的数据。为了避免这个问题，您应该在每次循环中更新这些数组。"

想象你在沙漠里拍了一张"敌人分布快照"，把它存进 enemies。可是战斗瞬息万变——有的敌人倒下了，新的敌人又冒出来。如果你一直盯着那张旧快照打，就会攻击已经消失的目标、或漏掉新出现的威胁。解决办法：把 find 方法放进循环里，每一圈都重新调用一次，拿到最新的数组。

neutrals = hero.findEnemies()   # 循环外先取一次
while True:
    if len(neutrals):
        hero.say(neutrals[0])
    else:
        hero.say("没有人在这儿")
    neutrals = hero.findEnemies()  # 关键：每轮重新赋值，刷新数组
呼应第一单元：这和你在"峡谷风暴"里学到的"变量做条件必须在循环里更新"是同一个思想。数组也是一种变量，只要它会随时间变化，就必须在循环内定期刷新，否则你操作的永远是那张过时的旧快照。

3.3 数组的长度

The Length of an Array

3.3.1 len() 与空数组（len() and the Empty Array）

3.3.1.1 长度就是元素的个数 Length is the number of elements

关卡概览定义得很清楚："数组的长度是数组中包含元素的个数。一个空数组的长度为 0。" 在 Python 里，用内置函数 len() 来量一个数组有多长：

friendNames = ['Joan', 'Ronan', 'Nikita', 'Augustus']
len(friendNames)   # → 4，数组里有 4 个名字

empty = []
len(empty)         # → 0，空数组长度为 0
长度与最大索引的关系：如果 len(items) 是 4，那么合法索引是 0、1、2、3——最大合法索引永远比长度小 1。牢记这条，能帮你避开绝大多数越界错误。

3.3.2 读取前先检查（Check Before You Read）

3.3.2.1 根据要读第几个，选对检查方式 Match the check to the index you need

为什么要检查长度？因为 find 方法很可能返回一个空数组（视野里暂时没有敌人/物品）。如果不检查就直接 enemies[0]，程序会因越界而崩溃。关卡给出了两条实用规则：

📏 两种检查方式，看你要读第几个
① 只读第一个元素（索引 0）：只需确认数组非空即可——if len(enemies) > 0，或简写成 if len(enemies)（0 视为假、正数视为真）。
② 要读更靠后的元素（如第 3 个，索引 2）：就得检查得更精确——if len(items) >= 2 才能安全读取 items[1]（第二个）；要读 items[2] 则需 len(items) >= 3。 
enemies = hero.findEnemies()
if len(enemies) > 0:        # 只读第一个，检查非空就够
    hero.attack(enemies[0])

items = hero.findItems()
if len(items) >= 2:          # 要读第二个 items[1]，需长度≥2
    hero.moveXY(items[1].pos.x, items[1].pos.y)
图2：读取前先量长度——空数组直接读取会越界崩溃

3.4 遍历数组

Iterating Over an Array

3.4.1 索引变量遍历法（The Index Variable Pattern）

3.4.1.1 用一个变量当"游标"，逐个走过 Use an index variable as a cursor

只取一个元素还不够——很多时候我们要把数组里每个元素都处理一遍，这叫遍历（iterate）。"Sarven 救世主"关卡教给我们最经典的方法：用一个"索引变量"当游标，配合 while 循环，让它从 0 一路走到数组末尾。

这里巧妙地把第一单元的 while 循环和本单元的数组结合了起来。索引变量（如 friendIndex）扮演的正是"计数器"的角色，只不过这次它的意义是"当前走到了第几个元素"。

3.4.2 遍历三部曲（The Iteration Recipe）

3.4.2.1 起点 0 → 条件用 len() → 每轮 +1 Start at 0, test with len(), increment each pass

关卡指导说得很到位："你可以使用索引变量而不是数字来访问数组的元素。要遍历数组中的所有值，请使用 while 循环在每次循环中递增索引变量！在每次循环中，你要取出该数组索引处的朋友姓名，然后处理它。" 归纳成三步：

🔁 遍历三部曲
①初始化索引：循环前 friendIndex = 0，从第一个元素开始。
②以 len() 为条件：while friendIndex < len(friendNames)——只要索引还没到达长度，就说明还有元素没处理。
③循环体内递增：处理完当前元素后 friendIndex += 1，让游标前进一格。
漏掉③就是死循环；条件写成 <= 就会越界。 
friendNames = ['Joan', 'Ronan', 'Nikita', 'Augustus']
friendIndex = 0                          # ① 索引从 0 开始
while friendIndex < len(friendNames):    # ② 用 len() 作为终止条件
    friendName = friendNames[friendIndex]  # 用索引变量取当前元素
    hero.say(friendName + ', go home!')
    friendIndex += 1                     # ③ 每轮 +1，游标前进
为什么条件用 < 而不是 <=？因为长度为 4 的数组，合法索引是 0、1、2、3。当 friendIndex 递增到 4 时，4 < 4 为假，循环恰好停止——刚好处理完最后一个 [3]，不多不少。如果写成 friendIndex <= len(...)，就会尝试访问越界的 [4]，导致报错。

3.5.1 团队合作（Team Work）

3.5.1.1 策略：用索引精确分派每颗宝石 Strategy: assign each gem by index

图3：团队合作——三颗宝石限时消失，用索引把每颗分派给不同伙伴

这是数组的启蒙关：三颗宝石限时消失，你要指挥农民 Bruno、Matilda 和英雄自己分头去取。算法思路是先 findItems() 拿到宝石数组，再用不同索引取出各颗宝石——items[0] 交给 Bruno、items[1] 交给 Matilda、items[2] 由英雄亲自 moveXY 前往。

要点在于牢记索引从 0 开始：三颗宝石对应的索引是 0、1、2，而不是 1、2、3。这一关还示范了两种引用方式——既可以先 gem0 = items[0] 存进变量，也可以直接写 items[1]，两者可以混用。因为宝石固定是三颗、不会变动，这一关不需要循环，直接按索引点名即可。

3.5.2 协助防御（Backwoods Standoff）

3.5.2.1 策略：检查非空后攻击首个敌人 Strategy: attack the first enemy after a length check

图4：协助防御——每轮刷新敌人数组，非空时攻击索引 0，再返回原位

这一关保护农民免受兽人侵害。算法思路是一个 while True 循环，每轮先 enemies = hero.findEnemies() 拿到最新的敌人数组，然后用 if len(enemies) > 0 检查数组是否为空；只有非空时才 hero.attack(enemies[0]) 攻击第一个敌人，其余交给队友；攻击后再 moveXY 返回起始防守位置。

关键领悟有二：一是读取 enemies[0] 前必须先检查长度，否则视野无敌人时直接越界崩溃；二是敌人数组要在循环内每轮刷新，因为敌人会不断被消灭、又不断涌来。这一关只读第一个元素，所以检查"非空"就足够了。

3.5.3 招募队伍（Sarven Sentry / 点名招募）

3.5.3.1 策略：循环点名并持续刷新名单 Strategy: call names while refreshing the list

一群中立农民想参军，你要一个接一个喊出他们的名字招募入伍。算法思路是：先 neutrals = hero.findEnemies()（注意——中立单位被当作"敌人"检测），进入 while True 循环；每轮用 if len(neutrals) 判断名单是否还有人，有就 hero.say(neutrals[0]) 喊出队首那位的名字，没人就说"没有人在这儿"。

本关的灵魂在于最后那句 neutrals = hero.findEnemies()——因为每喊一个农民、他就参军离开了名单，名单在不断缩短、变化。必须在循环末尾重新调用 findEnemies() 刷新名单，否则你会一直对着旧快照喊同一个已经入伍的人。这一关把"数组会过时、必须每轮刷新"这个概念演绎得淋漓尽致。

len(neutrals) 的简写：本关条件写成了 if len(neutrals) 而非 if len(neutrals) > 0。在 Python 里，数字 0 会被当作"假"，任何正数会被当作"真"，所以两种写法效果相同。前者更简洁，是老手常用的技巧。

3.5.4 第二宝石（The Second Gem）

3.5.4.1 策略：永远只取索引 1 的物品 Strategy: always take index 1

图5：第二宝石——第一颗是炸弹，永远收集数组中的第二个（索引 1）

这一关设了个陷阱：每批物品里第一颗（最显眼的那颗）是炸弹，第二颗才安全。算法思路是 while True 循环，每轮 items = hero.findItems()，然后用 if len(items) >= 2 确认至少有两个物品后，前往 items[1]（第二颗，索引 1）；若不足两个，就先 moveXY 回中心标记等待新一批物品刷新。

关键领悟是长度检查的精确性：因为这次要读的是索引 1（第二个元素），只检查"非空"（长度≥1）不够——万一数组里只有 1 个物品，items[1] 照样越界。所以条件必须是 len(items) >= 2。这一关生动说明了 3.3.2 讲的"要读第几个，就检查到第几个"。

3.5.5 Sarven 救世主（Sarven Savior）

3.5.5.1 策略：用索引变量遍历整支名单 Strategy: iterate the whole roster with an index

图6：Sarven 救世主——遍历朋友名单逐个唤其回家，最后建栅栏封锁

这是本单元的综合关卡，第一次要求你把数组里的每个元素都处理一遍。算法思路是标准的遍历三部曲：给定朋友名单 friendNames，先 friendIndex = 0，用 while friendIndex < len(friendNames) 作条件，循环体内 friendName = friendNames[friendIndex] 取出当前朋友、hero.say(friendName + ', go home!') 唤其回家，然后 friendIndex += 1 前进到下一个。全部喊完后，循环外再 moveXY 回绿洲、buildXY("fence", ...) 建栅栏封锁。

三个关键领悟：其一，索引变量 friendIndex 就是驱动遍历的引擎，本质上是个计数器；其二，条件用 len() 而非写死的数字 4，这样名单增减时代码依然正确——这叫让代码适应数据；其三，friendIndex += 1 绝不能漏，漏了就是死循环。此外还复习了字符串用 + 拼接、以及善后代码（建栅栏）放在循环外的道理。

3.6 常见错误

Common Mistakes

3.6.1 新手最容易踩的坑（Pitfalls for Beginners）

3.6.1.1 数组操作的典型问题 Typical issues with arrays

图7：索引从 1 开始、忘记检查长度、忘记刷新数组，是本单元最常见的失误
易错点清单：
  • 索引从 1 开始数——把第一个元素当成 items[1]，其实应该是 items[0]。这是最普遍的错误。
  • 索引越界——数组长度为 3 却访问 items[3]，超出合法范围 0~2，抛出 IndexError。
  • 读取前忘记检查长度——视野里没有目标时 find 返回空数组，直接 enemies[0] 立刻崩溃。
  • 检查不够精确——要读 items[1] 却只检查了"非空"，数组恰好只有 1 个元素时依然越界，应检查 len >= 2。
  • 忘记刷新数组——只在循环外取一次 findEnemies()，操作的始终是过时的旧快照，应在循环内每轮重新调用。
  • 遍历时忘记递增索引——写了 while friendIndex < len(...) 却漏掉 friendIndex += 1，索引永远为 0，直接死循环。
  • 遍历条件用 <=——应为 friendIndex < len(...)，用 <= 会多走一格造成越界。
  • 把善后代码写进循环——如"救世主"的建栅栏应放在遍历循环外，放进去会反复触发。
